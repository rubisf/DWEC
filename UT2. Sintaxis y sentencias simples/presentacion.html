1. Metodologías Ágiles (Scrum) y Principios de Diseño (SOLID)

💡 Fundamentos Conceptuales

El desarrollo web profesional requiere combinar metodologías de trabajo ágiles con principios de diseño de software de alta calidad:

  • Metodología Ágil Scrum: Marco de trabajo iterativo enfocado en entregas continuas de valor mediante Sprints (ciclos de 1 a 4 semanas), refinamiento de historias de usuario en el Backlog y reuniones diarias de sincronización (Daily Standups).
  • Clean Code (Código Limpio): Principios de legibilidad que exigen nombres autoexplicativos para variables y funciones, funciones pequeñas orientadas a una sola responsabilidad y ausencia de efectos secundarios ocultos.
🔍 Ampliación y Estándares 2026

La arquitectura del código se rige por los 5 principios de diseño orientado a objetos SOLID adaptados a JavaScript:

  • S (Single Responsibility): Principio de Responsabilidad Única. Cada módulo o clase debe tener una sola razón para cambiar.
  • O (Open/Closed): Abierto para la extensión, cerrado para la modificación. Extender funcionalidad mediante herencia o composición sin alterar código testeado.
  • L (Liskov Substitution): Las clases derivadas deben poder sustituir a sus clases base sin alterar el comportamiento correcto del programa.
  • I (Interface Segregation): Los clientes no deben verse obligados a depender de interfaces o métodos que no utilizan.
  • D (Dependency Inversion): Inversión de Dependencias. Módulos de alto nivel no deben depender de detalles de bajo nivel, sino de abstracciones.

2. Tipos Primitivos, Objetos y Declaración de Variables (let / const)

💡 Fundamentos Conceptuales

JavaScript maneja una distinción clara entre tipos de datos primitivos por valor y objetos complejos por referencia:

  • Tipos Primitivos (Inmutables): number, string, boolean, undefined, null, symbol y bigint. Se comparan y copian directamente por su valor en memoria.
  • Tipos por Referencia (Mutables): Objetos, Arrays y Funciones. Se almacenan en la memoria Heap y las variables guardan una referencia (puntero) a la dirección de memoria.
  • Declaración con let y const: Reemplazan a var introduciendo ámbito de bloque (Block Scope) e impidiendo el Hoisting perjudicial (elevación implícita que dejaba variables con valor undefined). La TDZ (Temporal Dead Zone) prohíbe acceder a let/const antes de su línea de declaración.
🔍 Ampliación y Estándares 2026

Manejo de conversiones y coerciones de tipos según el estándar ECMAScript:

  • Coerción Implícita: Conversión automática de tipos realizada por el intérprete (ej. '5' - 2 = 3 pero '5' + 2 = '52').
  • Igualdad Estricta (===): Compara tanto el valor como el tipo de dato sin realizar coerción implícita, evitando fallos lógicos respecto a la igualdad débil (==).
  • Valores Falsy: Valores que se evalúan a false en contextos booleanos: false, 0, , null, undefined y NaN.

3. Estructuras de Control, Bucles Modernos y Operador Spread

💡 Fundamentos Conceptuales

El control de flujo en JavaScript se estructura mediante condicionales y estructuras repetitivas optimizadas:

  • Bucle for...of: Diseñado para iterar directamente sobre los valores de objetos iterables (Arrays, Cadenas, Sets, Maps).
  • Bucle for...in: Diseñado exclusivamente para recorrer las llaves o propiedades enumerables de un objeto.
  • Operador Spread (...): Desempaqueta y expande los elementos de un array u objeto iterable dentro de un nuevo contenedor (permite clonado superficial y concatenación).
  • Operador Rest (...): Agrupa múltiples argumentos sobrantes pasados a una función dentro de un array formal.
🔍 Ampliación y Estándares 2026

Operadores de cortocircuito y evaluación de valores nulos introducidos en las especificaciones modernas:

  • Operador de Fusión Nula (??): Devuelve el operando de la derecha solo si el de la izquierda es null o undefined (a diferencia de || que salta con cualquier valor falsy como 0 o ).
  • Encadenamiento Opcional (?.): Permite leer propiedades anidadas de un objeto sin lanzar un error TypeError si una referencia intermedia es nula.
  • Desestructuración (Destructuring): Sintaxis que permite extraer valores de arrays u objetos y asignarlos directamente a variables individuales.

4. Funciones Clásicas, Funciones Flecha y Contexto 'this'

💡 Fundamentos Conceptuales

Las funciones son bloques de construcción fundamentales y ciudadanos de primera clase (First-Class Citizens) en JavaScript:

  • Declaraciones y Expresiones de Función: Las declaraciones se elevan (Hoisting) al inicio del ámbito; las expresiones asociadas a variables se evalúan en tiempo de ejecución.
  • Funciones Flecha (Arrow Functions): Sintaxis compacta ((args) => expr) que carece de su propio objeto arguments y realiza un enlace léxico del contexto this.
  • Comportamiento del Contexto this: En funciones clásicas, this se determina dinámicamente según cómo se invoca la función (el objeto que la llama). En Arrow Functions, this se hereda del ámbito padre envolvente en el momento de su creación.
🔍 Ampliación y Estándares 2026

Métodos explícitos para la vinculación del contexto de ejecución (Explicit Binding):

  • Function.prototype.call(thisArg, arg1, arg2): Invoca la función inmediatamente fijando this y pasando argumentos individualmente.
  • Function.prototype.apply(thisArg, [argsArray]): Invoca la función fijando this y pasando los argumentos empaquetados en un array.
  • Function.prototype.bind(thisArg): Devuelve una nueva función con el contexto this permanentemente enlazado para ser ejecutada en el futuro.
💻 Demostración Práctica e Implementación de Código 🚀 Abrir Ejemplo Real en Vivo (ejemplo4_arrow_this.js) 🔗 
// UT2 - Ejemplo 4: Arrow Functions y Contexto this
const usuario = {
    nombre: "Rubén",
    lenguajes: ["JavaScript", "TypeScript"],
    mostrarLenguajes() {
        this.lenguajes.forEach(lang => console.log(`${this.nombre} programa en ${lang}`));
    }
};
usuario.mostrarLenguajes();
