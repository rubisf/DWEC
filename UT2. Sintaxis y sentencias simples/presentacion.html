1. Variables: Declaración, Tipos de Datos y Ámbito (Scope)

💡 Fundamentos Conceptuales

En JavaScript, la gestión de la memoria y el ciclo de vida de los identificadores dependen del mecanismo de declaración y el tipo de dato asignado:

  • Mecanismos de Declaración:
    • var (Heredado): Posee ámbito de función (Function Scope) y sufre elevación (Hoisting), permitiendo su uso antes de la declaración con valor undefined. Además, se añade al objeto global window si se declara fuera de funciones.
    • let (Estándar Moderno): Posee ámbito de bloque (Block Scope) delimitado por llaves {}. No sufre inicialización por hoisting y reside en la Temporal Dead Zone (TDZ) hasta su definición.
    • const: Ámbito de bloque. Exige inicialización inmediata y garantiza inmutabilidad de enlace de referencia (no se puede reasignar el identificador, aunque las propiedades internas de objetos y arrays sí son mutables).
  • Tipos de Datos Primitivos (Inmutables por valor): number (IEEE 754 de 64 bits), string, boolean, undefined (variable declarada sin valor), null (ausencia intencional de objeto), symbol (identificador único) y bigint (enteros de precisión arbitraria terminados en n).
  • Tipos de Datos Complejos (Referencia): object, arrays, funciones y colecciones (Map, Set). El operador typeof permite inspeccionar tipos (con la peculiaridad histórica de typeof null === "object").
🔍 Ampliación y Estándares 2026

Buenas Prácticas de Ámbito y Modo Estricto:

  • Regla de Oro de Declaración: Usar const por defecto para todo identificador. Usar let únicamente cuando sea estrictamente necesario reasignar el valor (como contadores de bucle). Evitar por completo var en código nuevo.
  • Directiva 'use strict': Activa el Modo Estricto de ECMAScript, prohibiendo variables globales accidentales sin declarar (ej. x = 10 lanzará ReferenceError), impidiendo duplicados en parámetros y optimizando la compilación JIT.
💻 Demostración Práctica e Implementación de Código 
// Comparativa de Ámbitos y Mutabilidad de Referencia
function demostrarAmbitos() {
    if (true) {
        var variableVar = "Accesible en toda la función";
        let variableLet = "Sólo dentro de este bloque if";
        const objetoConst = { propiedad: 100 };

        // Mutación interna permitida en const
        objetoConst.propiedad = 200; 
        console.log("const mutado:", objetoConst.propiedad);
    }

    console.log("var fuera del bloque:", variableVar); // Funciona
    // console.log(variableLet); // ReferenceError: variableLet is not defined
}

2. Conversiones de Tipos y Operaciones de Asignación

💡 Fundamentos Conceptuales

JavaScript es un lenguaje de tipado débil y dinámico donde las variables pueden sufrir conversiones implícitas (coerción) o requerir conversiones explícitas (casting) para garantizar la seguridad aritmética:

  • Conversión Implícita (Coerción Automática):
    • Operador +: Si uno de los operandos es una cadena de texto, actúa como concatenador, convirtiendo al otro operando a string (ej. "5" + 2 === "52").
    • Operadores aritméticos (-, *, /): Coaccionan los operandos a números (ej. "10" - 3 === 7).
    • Igualdad Débil (==) vs Igualdad Estricta (===): El operador == realiza coerción previa (ej. 0 == false es true), mientras que === compara tipo y valor sin conversión, siendo el único estándar admitido en desarrollo profesional.
    • Valores Truthy y Falsy: Se evalúan a falso en contextos booleanos únicamente: false, 0, -0, "", null, undefined y NaN. Cualquier otro valor (incluyendo [] y {}) es truthy.
  • Conversiones Explícitas:
    • A Número: Number(valor) (estricto), parseInt(cadena, 10) (extrae enteros con base explícita) y parseFloat(cadena).
    • A Cadena: String(valor) y método valor.toString().
    • A Booleano: Boolean(valor) o doble negación !!valor.
  • Operaciones de Asignación Modernas:
    • Asignación compuesta: +=, -=, *=, **= (exponenciación) y operadores lógicos de asignación: &&=, ||=, ??= (asigna sólo si es nulo o indefinido).
    • Asignación por Desestructuración: Extracción concisa de valores en variables independientes desde arrays y objetos (const [a, b] = array; const { nombre, rol } = usuario;).
🔍 Ampliación y Estándares 2026

Peligros de Coerción y Soluciones Modernas:

  • Validación con Number.isNaN(): Siempre debe preferirse el método estático Number.isNaN(v) frente a la función global isNaN(v), ya que esta última intenta coaccionar el argumento antes de evaluar, generando falsos positivos.
  • Desestructuración con Valores por Defecto y Renombrado: Permite asignar fallbacks inmediatos: const { tema = 'oscuro', usuario: alias } = opciones;.
💻 Demostración Práctica e Implementación de Código 
// Demostración de Coerción, Casting Seguro y Asignación por Desestructuración
console.log("=== Coerción vs Casting ===");
console.log("'20' + 5 =", "20" + 5);      // "205" (Concatenación)
console.log("Number('20') + 5 =", Number("20") + 5); // 25 (Aritmética)
console.log("'' == false:", "" == false); // true (Coerción peligrosa)
console.log("'' === false:", "" === false); // false (Comparación estricta)

// Asignación por desestructuración de datos de usuario
const respuestaAPI = { id: 104, nombre: "Elena", rol: "admin", configuracion: { activa: true } };
const { nombre, rol, configuracion: { activa }, nivel = "junior" } = respuestaAPI;

console.log(`Usuario extraído: ${nombre} (${rol}), Nivel: ${nivel}, Activa: ${activa}`);

// Asignación lógica nula (??=)
let temaSeleccionado = null;
temaSeleccionado ??= "dark-theme"; // Asigna porque es null
console.log("Tema configurado:", temaSeleccionado);

🎯 Reto 2: Normalizador de Entradas de Usuario con Coerción Segura y Desestructuración

📝 Enunciado y Especificación del Reto
Escribe una función llamada `normalizarUsuario(entrada)` que reciba un objeto con datos en formatos desordenados (ej: edad como string `"28"`, activo como número `1`, salario con coma `"1450.50"`). Aplica casting seguro, extrae los valores con desestructuración y genera un objeto normalizado con tipos primitivos estrictos (`number`, `boolean`, `string`). Si la edad no es un número válido, asigna un valor por defecto mediante el operador `??=`.
💡 Pistas Clave y Procedimiento Guiado
Usa parseFloat con replace(",", ".") para decimales con coma. Comprueba Number.isNaN para la edad y aplica el operador ??= para asignar un valor por defecto.
🔍 Desplegar Solución Embebida y Explicación Técnica Clic para Ver/Ocultar
Explicación Técnica: El saneamiento de entradas en frontend evita errores aritméticos derivados de coerción imprevista y homogeniza los datos recibidos de formularios o APIs externas.
💻 Código de la Solución Comentada:
function normalizarUsuario(entrada) {
    // Desestructuración con valores por defecto
    let { id, nombre, edad, activo, salario } = entrada;

    // Normalización de tipos
    id = Number(id);
    nombre = String(nombre).trim();
    
    // Casting de edad y control de NaN
    let edadNumerica = Number.parseInt(edad, 10);
    if (Number.isNaN(edadNumerica)) {
        edadNumerica = null;
    }
    edadNumerica ??= 18; // Operador nullish: si es null/undefined toma 18

    // Coerción a booleano estricto
    activo = Boolean(Number(activo));

    // Conversión de formato numérico decimal con coma a punto
    salario = Number.parseFloat(String(salario).replace(',', '.'));

    return {
        id,
        nombre,
        edad: edadNumerica,
        activo,
        salario: Number.isNaN(salario) ? 0 : salario
    };
}

// Prueba con datos sucios de formulario
const usuarioBruto = { id: "402", nombre: "  Carlos Santana  ", edad: "invalida", activo: 1, salario: "2450,75" };
console.table(normalizarUsuario(usuarioBruto));

3. Operadores Básicos, Expresiones y Sentencias Simples

💡 Fundamentos Conceptuales

Las expresiones combinan operandos y operadores para producir un valor. JavaScript cuenta con una jerarquía formal de precedencia y operadores de última generación:

  • Operadores Aritméticos y de Comparación: Adición (+), sustracción (-), multiplicación (*), división (/), módulo (%) y exponenciación (**). Operadores de incremento y decremento prefijo (++x) y postfijo (x++). Relacionales: >, <, >=, <=.
  • Operadores Lógicos y Cortocircuito (Short-Circuit Evaluation):
    • && (AND lógico): Evalúa el primer operando; si es falsy lo devuelve inmediatamente; si es truthy evalúa y devuelve el segundo.
    • || (OR lógico): Si el primer operando es truthy lo devuelve inmediatamente; si no, devuelve el segundo operando.
    • ! (NOT lógico): Invierte el valor booleano.
  • Operadores Modernos de Acceso y Fallback:
    • Operador Ternario (cond ? expr1 : expr2): Estructura condicional compacta en una sola expresión.
    • Nullish Coalescing (??): Devuelve el operando de la derecha únicamente si el de la izquierda es null o undefined. A diferencia de ||, respeta el 0, el false y el "" como valores válidos.
    • Optional Chaining (?.): Permite leer propiedades profundamente anidadas sin provocar una excepción si una referencia intermedia es null o undefined (ej. usuario?.direccion?.calle).
  • Sentencias Simples y Estructura: Una sentencia simple expresa una acción (declaración, asignación, llamada a función). Finaliza formalmente con punto y coma (;) regulado por la inserción automática (ASI - Automatic Semicolon Insertion). Los bloques {} agrupan cero o más sentencias simples.
🔍 Ampliación y Estándares 2026

Precedencia de Operadores y Reglas de Estilo:

  • Peligros de ASI (Inserción Automática de Punto y Coma): Un retorno de función con la expresión en la línea siguiente (ej: return \n { id: 1 }) devolverá undefined porque el motor inserta un punto y coma tras return. Por convención profesional, se deben usar siempre puntos y comas explícitos.
  • Combinación Segura ?. y ??: La sintaxis const cp = cliente?.direccion?.cp ?? 'S/N'; previene excepciones y asigna un valor seguro en una sola línea elegante y declarativa.
💻 Demostración Práctica e Implementación de Código 
// Demostración de Optional Chaining, Nullish Coalescing y Cortocircuito
const perfil = {
    nombre: "Marina",
    config: {
        intentosMaximos: 0, // 0 es falsy, ¡pero es un valor válido de intentos!
        notificaciones: false
    }
};

// Problema con operador OR || tradicional
const intentosIncorrecto = perfil.config.intentosMaximos || 5; // Asigna 5 por error (0 es falsy)
// Solución con Nullish Coalescing ??
const intentosCorrecto = perfil.config.intentosMaximos ?? 5;   // Conserva 0 (no es null ni undefined)

console.log("Con || (incorrecto):", intentosIncorrecto); // 5
console.log("Con ?? (correcto):", intentosCorrecto);     // 0

// Acceso seguro con encadenamiento opcional
const codigoPostal = perfil?.datosBancarios?.direccion?.cp ?? "Sin Código Postal";
console.log("Código Postal:", codigoPostal);

🔍 Desplegar Solución Embebida y Explicación Técnica Clic para Ver/Ocultar

function procesarPedidosExpress(pedidos) {
    return pedidos.map(pedido => {
        // Fallback seguro de envío respetando el 0€
        const costeEnvio = pedido.envio ?? 4.99;
        const total = Number((pedido.base + costeEnvio).toFixed(2));
        
        // Extracción segura de dirección profunda
        const direccionEntrega = pedido.cliente?.direccion?.calle 
            ? \`\${pedido.cliente.direccion.calle}, \${pedido.cliente.direccion.ciudad ?? 'S/C'}\` 
            : "Recogida en Tienda Central";

        return {
            id: pedido.id,
            total,
            envio: costeEnvio === 0 ? "Gratis" : \`\${costeEnvio}€\`,
            direccion: direccionEntrega
        };
    });
}

    { id: 3, base: 100, envio: 12.5, cliente: { direccion: null } } // Cliente sin dirección

4. Estructuras de Control: Decisiones y Bucles

💡 Fundamentos Conceptuales

El control del flujo de ejecución en JavaScript se organiza en estructuras condicionales y estructuras repetitivas optimizadas:

  • Estructuras de Decisión:
    • if / else if / else: Ramificaciones binarias o múltiples basadas en la evaluación booleana de expresiones.
    • switch (expresion): Comparación de coincidencia estricta (===) con múltiples cláusulas case. Requiere la sentencia break para evitar la ejecución accidental en cascada (fallthrough). Admite cláusula default para casos no coincidentes y agrupamiento de casos para compartir lógica.
  • Estructuras de Repetición Tradicionales:
    • for (init; cond; step): Bucle clásico gobernado por un índice numérico. Óptimo cuando se conoce previamente el número de iteraciones.
    • while (condicion): Bucle con comprobación previa. La condición se valida antes de cada ciclo; si es falsa inicialmente, nunca se ejecuta.
    • do ... while (condicion): Bucle con comprobación posterior. Garantiza al menos una ejecución del bloque de código.
  • Bucles Iteradores Modernos (ES6+):
    • for ... of: Itera sobre los valores de cualquier objeto iterable (Arrays, Strings, Sets, Maps, NodeLists). Sintaxis limpia y preferida para colecciones.
    • for ... in: Itera sobre las claves/propiedades enumerables de un objeto. No debe emplearse para recorrer arrays debido a que incluye propiedades del prototipo y no garantiza el orden numérico de índices.
  • Control de Interrupción: Sentencias break (finaliza el bucle de inmediato) y continue (salta a la siguiente iteración). Admite etiquetas de bucle (etiqueta: for ...) para saltos en bucles anidados.
🔍 Ampliación y Estándares 2026

Optimización de Bucles y Prevención de Bloqueos:

  • Caché de Longitud en Bucles For Clásicos: Al recorrer colecciones vivas del DOM (como HTMLCollection), es crucial cachear la longitud: for (let i = 0, len = coleccion.length; i < len; i++), previniendo que el navegador recalcule el tamaño del DOM en cada vuelta.
  • Elección del Bucle Adecuado: Utilizar for...of para arrays e iterables; reservar for...in exclusivamente para depuración u objetos planos no ordenados.
💻 Demostración Práctica e Implementación de Código 
// Demostración de estructuras de decisión y bucles iteradores modernos
const transacciones = [
    { id: 1, tipo: "ingreso", cantidad: 500 },
    { id: 2, tipo: "gasto", cantidad: 120 },
    { id: 3, tipo: "comision", cantidad: 15 },
    { id: 4, tipo: "ingreso", cantidad: 300 }
];

let balanceTotal = 0;

// Bucle for...of para recorrer valores de objetos
for (const transaccion of transacciones) {
    switch (transaccion.tipo) {
        case "ingreso":
            balanceTotal += transaccion.cantidad;
            break;
        case "gasto":
        case "comision": // Casos agrupados
            balanceTotal -= transaccion.cantidad;
            break;
        default:
            console.warn("Tipo de transacción desconocido:", transaccion.tipo);
    }
}

console.log(`Balance financiero final calculado: ${balanceTotal}€`);

🎯 Reto 4: Motor de Reglas de Descuento y Filtrado de Stock con Bucles e Interrupciones

📝 Enunciado y Especificación del Reto
Escribe una función que procese un inventario de artículos aplicando descuentos según la categoría con una estructura `switch`. Recorre el inventario con `for...of`. Si un producto tiene stock 0, salta al siguiente con `continue`. Si se detecta un artículo con precio negativo (error de base de datos), interrumpe el procesamiento global con `break` y notifica la anomalía.
💡 Pistas Clave y Procedimiento Guiado
Declara un array de artículos. Usa switch(articulo.categoria) para fijar el porcentaje de descuento. Controla articulo.stock === 0 con continue y articulo.precio < 0 con break.
🔍 Desplegar Solución Embebida y Explicación Técnica Clic para Ver/Ocultar
Explicación Técnica: La combinación de switch con sentencias continue y break permite estructurar flujos de validación robustos y eficientes en colecciones de datos comerciales.
💻 Código de la Solución Comentada:
function procesarInventario(articulos) {
    const catalogoProcesado = [];
    let errorCritico = false;

    for (const prod of articulos) {
        // Control de anomalía crítica: interrupción con break
        if (prod.precio < 0) {
            console.error("ALERTA CRÍTICA: Precio negativo detectado en ID " + prod.id + ". Proceso detenido.");
            errorCritico = true;
            break;
        }

        // Producto sin existencias: salto con continue
        if (prod.stock === 0) {
            console.warn("Stock agotado para " + prod.nombre + ". Omitiendo de catálogo activo.");
            continue;
        }

        let descuento = 0;
        switch (prod.categoria) {
            case "informatica":
                descuento = 0.10; // 10%
                break;
            case "telefonia":
                descuento = 0.15; // 15%
                break;
            case "accesorios":
                descuento = 0.20; // 20%
                break;
            default:
                descuento = 0.05; // 5% base
        }

        const precioFinal = Number((prod.precio * (1 - descuento)).toFixed(2));
        catalogoProcesado.push({
            id: prod.id,
            nombre: prod.nombre,
            precioOriginal: prod.precio,
            precioFinal,
            ahorro: Number((prod.precio - precioFinal).toFixed(2))
        });
    }

    return { catalogoProcesado, estado: errorCritico ? "Interrumpido con Errores" : "Procesado con Éxito" };
}

5. Comentarios, Documentación con JSDoc y Pruebas en el Navegador

💡 Fundamentos Conceptuales

El código profesional en JavaScript exige estándares formales de documentación técnica y procedimientos estructurados de depuración y prueba dentro del navegador:

  • Tipos de Comentarios:
    • Comentarios de una línea (//): Aclaraciones puntuales sobre el porqué de una decisión de diseño, no sobre lo evidente.
    • Comentarios multilínea (/* ... */): Bloques de explicación arquitectónica o desactivación temporal de fragmentos de código.
  • Estándar JSDoc: Formato universal de documentación mediante comentarios especiales (/** ... */) que habilita autocompletado inteligente y comprobación estática de tipos en editores como VS Code:
    • @param {tipo} nombre - Descripción: Define tipo y función de un parámetro.
    • @returns {tipo} Descripción: Declara el tipo de dato devuelto.
    • @type {tipo}: Tipifica variables complejas o constantes.
    • @throws {Error}: Especifica las excepciones que la función puede propagar.
    • @example: Muestra ejemplos interactivos de llamada y salida.
  • Técnicas de Prueba y Depuración en el Navegador:
    • console.table(datos): Renderiza matrices de objetos en formato de tabla interactiva con ordenación de columnas.
    • console.time('etiqueta') / console.timeEnd('etiqueta'): Cronometra el tiempo exacto de ejecución con precisión de microsegundos.
    • console.assert(afirmacion, mensaje): Comprobación condicional que sólo emite un error si la condición es falsa.
    • debugger;: Instrucción que fuerza la apertura de las herramientas de desarrollador y pausa el hilo principal para inspección paso a paso.
🔍 Ampliación y Estándares 2026

De JSDoc a TypeScript y Pruebas Unitarias:

  • Chequeo Estático con // @ts-check: Añadiendo esta directiva en la primera línea de cualquier fichero .js, el compilador de TypeScript integrado en el IDE analiza las anotaciones JSDoc y detecta errores de tipos en tiempo real sin requerir compilar a TypeScript.
  • Trazas de Pila con console.trace(): Permite imprimir la cadena jerárquica exacta de llamadas a funciones que condujeron a un punto determinado del programa.

/**
 * Calcula el Impuesto sobre el Valor Añadido (IVA) de una factura comercial.
 * @param {number} baseImponible - Importe monetario bruto en euros.
 * @param {number} [tipoIva=0.21] - Tipo impositivo aplicable (0.04, 0.10, 0.21).
 * @returns {number} Importe total de la factura con IVA incluido.
 * @throws {TypeError} Si la base imponible no es un número finito positivo.
 * @example
 * const total = calcularFacturaConIva(100, 0.21); // Devuelve 121
 */
function calcularFacturaConIva(baseImponible, tipoIva = 0.21) {
    if (typeof baseImponible !== "number" || baseImponible <= 0 || !Number.isFinite(baseImponible)) {
        throw new TypeError("La base imponible debe ser un número finito positivo.");
    }
    return Number((baseImponible * (1 + tipoIva)).toFixed(2));
}

// Comprobación y prueba unitaria en consola
console.assert(calcularFacturaConIva(100, 0.21) === 121, "Error en cálculo de IVA del 21%");
console.log("Prueba unitaria superada con éxito.");

/**
 * @typedef {Object} Estadisticas
 * @property {number} media - Media aritmética de los valores.
 * @property {number} maximo - Valor más alto de la serie.
 * @property {number} minimo - Valor más bajo de la serie.
 */

/**
 * Calcula métricas estadísticas descriptivas sobre una colección numérica.
 * @param {number[]} numeros - Array con valores numéricos.
 * @returns {Estadisticas} Objeto con las métricas calculadas.
 * @throws {Error} Si el array está vacío o contiene elementos no numéricos.
 * @example
 * const stats = calcularEstadisticas([10, 20, 30]); // { media: 20, maximo: 30, minimo: 10 }
 */
function calcularEstadisticas(numeros) {
    if (!Array.isArray(numeros) || numeros.length === 0) {
        throw new Error("El argumento debe ser un array con al menos un elemento numérico.");
    }

    console.time("Cálculo Estadístico");

    let suma = 0;
    for (const num of numeros) {
        if (typeof num !== "number" || Number.isNaN(num)) {
            throw new TypeError("Todos los elementos del array deben ser números válidos.");
        }
        suma += num;
    }

    const media = Number((suma / numeros.length).toFixed(2));
    const maximo = Math.max(...numeros);
    const minimo = Math.min(...numeros);

    // Punto de interrupción para inspección en navegador
    debugger;

    console.timeEnd("Cálculo Estadístico");

    return { media, maximo, minimo };
}

// Pruebas y Aserciones
const muestra = [15, 22, 8, 45, 31, 19];
const resultado = calcularEstadisticas(muestra);

console.assert(resultado.maximo === 45, "Error en cálculo de máximo");
console.assert(resultado.minimo === 8, "Error en cálculo de mínimo");
console.table(resultado);
