1. Funciones de Orden Superior, Closures y Callbacks

💡 Fundamentos Conceptuales

Las Funciones de Orden Superior (Higher-Order Functions) son funciones que reciben otras funciones como argumentos o devuelven funciones como resultado:

  • Callbacks: Funciones pasadas como parámetros a otras funciones para ser ejecutadas en un momento posterior o tras completar una tarea.
  • Closures (Clausuras): Capacidad de una función interna de 'recordar' y mantener acceso al ámbito léxico (variables locales) de su función contenedora padre, incluso después de que la función padre haya finalizado su ejecución.
  • Encapsulación de Estado: Los closures permiten crear variables privadas y emular el patrón de módulo sin exponer datos al ámbito global.
🔍 Ampliación y Estándares 2026

Optimización y conceptos avanzados de evaluación funcional:

  • Currying (Curryficación): Técnica que transforma una función de múltiples argumentos en una secuencia de funciones uniparamétricas consecutivas (f(a,b,c) => f(a)(b)(c)).
  • Memoización (Memoization): Patrón de optimización que almacena en caché los resultados de funciones puras pesadas basados en sus argumentos para evitar cálculos repetidos.
  • Funciones Puras: Funciones que siempre devuelven el mismo resultado para los mismos argumentos y no producen efectos secundarios (no mutan variables externas).
💻 Demostración Práctica e Implementación de Código 🚀 Abrir Ejemplo Real en Vivo (ejemplo1_closures_currying.js) 🔗 
// UT4 - Ejemplo 1: Closures y Currying
function crearContador() {
    let contador = 0;
    return () => ++contador;
}
const incrementar = crearContador();
console.log("Contador:", incrementar(), incrementar());

2. Arrays y Métodos Funcionales Modernos

💡 Fundamentos Conceptuales

Los Arrays en JavaScript disponen de un catálogo de métodos funcionales declarativos que evitan la mutación directa:

  • Array.prototype.map(cb): Transforma cada elemento del array devolviendo un nuevo array de la misma longitud.
  • Array.prototype.filter(cb): Evalúa una condición booleana en cada elemento devolviendo un nuevo array con los elementos que la cumplen.
  • Array.prototype.reduce(cb, init): Acumula y reduce todos los elementos del array a un único valor final (objeto, número o array).
🔍 Ampliación y Estándares 2026

Nuevos métodos inmutables introducidos en las especificaciones recientes de ECMAScript (ES2023+):

  • toSorted(), toReversed(), toSpliced(): Versiones inmutables de sort(), reverse() y splice() que devuelven una copia modificada sin alterar el array original.
  • with(index, value): Devuelve una copia del array reemplazando el elemento de un índice específico de forma inmutable.
  • findLast() y findLastIndex(): Buscan elementos iterando desde el final del array hacia el principio.

3. Programación Orientada a Objetos: Clases ES6 y Herencia

💡 Fundamentos Conceptuales

La especificación ES6 introdujo la sintaxis de clases como una capa de azúcar sintáctico sobre la herencia prototípica nativa:

  • Constructor y Métodos: El método constructor() inicializa las propiedades de la instancia. Los métodos definidos dentro de la clase se asignan al prototipo de la clase (Class.prototype).
  • Herencia con extends y super: La palabra clave extends establece la cadena de prototipos y super() invoca el constructor de la clase padre.
  • Campos Privados (#propiedad): Sintaxis nativa que garantiza el encapsulamiento estricto a nivel de lenguaje, impidiendo el acceso a la propiedad desde fuera de la clase.
🔍 Ampliación y Estándares 2026

Mecanismos internos del sistema de herencia basado en prototipos (Prototypal Inheritance):

  • Prototype Chain (Cadena de Prototipos): Todos los objetos poseen una referencia interna ([[Prototype]]) a su prototipo. Si una propiedad no existe en el objeto, la búsqueda asciende por la cadena hasta llegar a Object.prototype o null.
  • Métodos Estáticos (static): Métodos asociados directamente a la clase contenedora y no a las instancias individuales.
  • Getters y Setters: Métodos de acceso (get / set) para controlar y validar la lectura y escritura de propiedades de forma encapsulada.
💻 Demostración Práctica e Implementación de Código 🚀 Abrir Ejemplo Real en Vivo (ejemplo3_poo_clases.js) 🔗 
// UT4 - Ejemplo 3: POO y Clases
class Persona {
    #id;
    constructor(id, nombre) { this.#id = id; this.nombre = nombre; }
    getId() { return this.#id; }
}
const p = new Persona(101, "Carlos");
console.log(`Persona: ${p.nombre} (ID: ${p.getId()})`);

4. Catálogo de Patrones de Diseño en JavaScript

💡 Fundamentos Conceptuales

Los Patrones de Diseño son soluciones reutilizables a problemas comunes en la arquitectura de software:

  • Patrón Singleton (Creacional): Garantiza que una clase tenga una única instancia global en toda la aplicación y proporciona un punto de acceso único a ella.
  • Patrón Factory (Creacional): Proporciona una interfaz para crear objetos delegando en subclases o funciones la decisión de qué clase concreta instanciar.
  • Patrón Observer / PubSub (Comportamiento): Define una relación uno-a-muchos entre objetos para que cuando un sujeto cambie de estado, todos sus observadores sean notificados automáticamente.
🔍 Ampliación y Estándares 2026

Patrones estructurales y de diseño moderno orientados a JavaScript web:

  • Patrón Module (Estructural): Encapsula código privado expuesto a través de un objeto público mediante closures o ES Modules.
  • Patrón Decorator (Estructural): Añade responsabilidades adicionales a un objeto dinámicamente sin modificar la clase original.
  • Principios de Refactorización: Aplicación del patrón desacoplado para mantener una arquitectura mantenible y testeable mediante inyección de dependencias.
💻 Demostración Práctica e Implementación de Código 🚀 Abrir Ejemplo Real en Vivo (ejemplo4_patrones_diseno.js) 🔗 
// UT4 - Ejemplo 4: Patrón Singleton
class SingletonBD {
    static #instancia;
    constructor() {
        if (SingletonBD.#instancia) return SingletonBD.#instancia;
        SingletonBD.#instancia = this;
    }
}
const bd1 = new SingletonBD();
const bd2 = new SingletonBD();
console.log("¿Misma instancia Singleton?:", bd1 === bd2);
