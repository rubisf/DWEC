1. Funciones Predefinidas del Lenguaje y Funciones Personalizadas

💡 Fundamentos Conceptuales

En JavaScript, las funciones son ciudadanos de primera clase (First-Class Citizens): pueden asignarse a variables, pasarse como argumentos y devolverse desde otras funciones:

  • Funciones Predefinidas Globales:
    • Conversión y comprobación numérica: parseInt(cadena, base), parseFloat(cadena), isNaN(), isFinite().
    • Codificación de URLs: encodeURI() (codifica URLs completas conservando delimitadores de protocolo/path) y encodeURIComponent() (codifica todos los caracteres especiales para parámetros de consulta ?query=...). Funciones inversas: decodeURI() y decodeURIComponent().
    • Evaluación dinámica: eval(). ⚠️ Desaconsejada y prohibida en Modo Estricto por representar un grave vector de inyección de código y degradar la optimización del compilador JIT.
  • Definición de Funciones Personalizadas:
    • Declaración de Función (Function Declaration): function calcular() {}. Posee elevación completa (hoisting), pudiendo invocarse antes de su línea de definición.
    • Expresión de Función (Function Expression): const sumar = function(a, b) { return a + b; };. No sufre hoisting de inicialización.
    • Funciones Flecha (Arrow Functions): Sintaxis concisa ((a, b) => a + b). Tienen retorno implícito para expresiones directas y enlace léxico de this (no poseen su propio this, sino que heredan el contexto envolvente donde fueron creadas). No pueden utilizarse como constructoras con new.
  • Parámetros Avanzados: Parámetros por defecto ((x = 10)), parámetros Rest para aridad indefinida ((...valores)) y desestructuración directa de argumentos.
🔍 Ampliación y Estándares 2026

El Contexto de Ejecución y Enlace de this:

  • Diferencia Crítica de this: En funciones clásicas, this se determina dinámicamente en el momento de la llamada (el objeto que invoca la función). En funciones flecha, this queda fijado estáticamente en tiempo de compilación según el ámbito léxico donde se escribió la función.
  • Métodos de Enlace Explícito: fn.call(contexto, arg1, arg2), fn.apply(contexto, [args]) y fn.bind(contexto) (devuelve una nueva función permanentemente vinculada).
💻 Demostración Práctica e Implementación de Código

const gestorEventos = {
    nombre: "Taller DWEC",
    participantes: ["Carlos", "Marta", "David"],
    
    // Método clásico con función flecha interna que conserva léxicamente 'this'

        console.log(`Lista para el evento: ${this.nombre}`);

        todos.forEach(p => console.log(` - Asistente: ${p} registrado en ${this.nombre}`));
    }
};

2. Arrays: Creación, Manipulación y Métodos de Recorrido

💡 Fundamentos Conceptuales

Los arrays en JavaScript son objetos dinámicos de longitud variable indexados numéricamente con capacidad de almacenar tipos heterogéneos:

  • Creación de Arrays: Notación literal corchetes ([]), constructor new Array(longitud), método estático Array.of(elem1, elem2) y conversión de iterables con Array.from(iterable, mapFn) (ideal para convertir NodeLists del DOM a arrays reales).
  • Mutación de Estructura (Pila y Cola):
    • Operaciones al final: push(...elementos) (añade al final y devuelve nueva longitud) y pop() (extrae y devuelve el último elemento).
    • Operaciones al inicio: unshift(...elementos) (inserta al principio) y shift() (extrae el primer elemento).
  • Transformación y Extracción:
    • splice(inicio, borrarConteo, ...insertar): Método mutador versátil. Elimina elementos, inserta nuevos o sustituye en cualquier posición del array.
    • slice(inicio, fin): Método inmutable. Extrae una porción superficial (shallow copy) del array sin modificar el original.
    • concat(...arrays) y join(separador): Combinación de arrays y serialización a cadena de texto.
  • Métodos de Recorrido:
    • Bucle for tradicional con índice numérico.
    • Bucle for ... of para iteración secuencial directa sobre elementos.
    • Método funcional forEach((elemento, indice, array) => { ... }). Nota: forEach no admite break ni continue.
🔍 Ampliación y Estándares 2026

Copia Superficial vs Copia Profunda en Arrays:

  • El operador Spread ([...original]) y slice(): Realizan copias superficiales (Shallow Copy). Si el array contiene objetos internos, las referencias a dichos objetos se comparten entre ambas copias.
  • Copia Profunda Moderna con structuredClone(): API estándar nativa para clonar arrays u objetos anidados sin compartir referencias internas, superando las limitaciones de JSON.parse(JSON.stringify()).

class GestorTareas {
    constructor() {
        this.tareas = [];
    }

    agregarTareaRegular(tarea) {
        this.tareas.push({ id: Date.now() + Math.random(), titulo: tarea, prioridad: "Normal" });
    }

    agregarTareaUrgente(tarea) {
        this.tareas.unshift({ id: Date.now() + Math.random(), titulo: tarea, prioridad: "URGENTE" });
    }

    procesarSiguiente() {
        const atendida = this.tareas.shift();
        console.log("Procesando tarea:", atendida?.titulo ?? "Cola vacía");
        return atendida;
    }

    rotarCola() {
        if (this.tareas.length > 1) {
            const cabeza = this.tareas.shift();
            this.tareas.push(cabeza);
            console.log("Cola rotada: el primer elemento pasa al final.");
        }
    }

    eliminarPorIndice(indice) {
        if (indice >= 0 && indice < this.tareas.length) {
            const [eliminada] = this.tareas.splice(indice, 1);
            console.log("Tarea eliminada:", eliminada.titulo);
        }
    }

    mostrar() {
        console.table(this.tareas);
    }
}

gestor.agregarTareaRegular("Limpiar logs de acceso");

3. Operaciones Agregadas en Arrays: Mapeo, Filtrado, Reducción y Ordenación

💡 Fundamentos Conceptuales

La programación funcional en JavaScript se fundamenta en métodos iteradores inmutables que procesan colecciones de datos sin alterar el array de origen:

  • Transformación con map(callback): Aplica una función a cada elemento y genera un nuevo array de la misma longitud con los resultados transformados.
  • Filtrado con filter(callback): Evalúa un predicado booleano y devuelve un nuevo array conteniendo únicamente aquellos elementos que cumplan la condición.
  • Reducción Acumulativa con reduce(callback, valorInicial): Reduce todo el array a un único valor (un número, un objeto, un mapa o una estructura agrupada) mediante un acumulador.
  • Búsqueda y Verificación:
    • find(callback): Devuelve el primer elemento que cumple el predicado (o undefined).
    • findIndex(callback): Devuelve el índice del primer elemento coincidente (o -1).
    • some(callback): Booleano true si al menos un elemento cumple la condición.
    • every(callback): Booleano true si todos los elementos cumplen la condición.
    • includes(valor): Comprueba si un valor simple existe dentro del array.
  • Ordenación con sort() y Métodos Inmutables ES2023:
    • sort(funcionComparacion): ⚠️ Mutador. Por defecto ordena alfabéticamente convirtiendo a string (lo que provoca que [10, 2].sort() sea [10, 2]). Para números se exige la función de comparación (a, b) => a - b.
    • toSorted() y toReversed(): Estándar moderno inmutable. Devuelven un nuevo array ordenado o invertido sin mutar el original.
  • Encadenamiento Funcional (Method Chaining): Capacidad de concatenar múltiples operaciones (datos.filter(...).map(...).reduce(...)) en un pipeline de datos limpio y declarativo.
🔍 Ampliación y Estándares 2026

Aplanamiento y Reducciones Complejas:

  • Métodos flat() y flatMap(): array.flat(profundidad) aplana sub-arrays anidados. flatMap() combina un mapeo y un aplanamiento de un solo nivel de profundidad de manera óptima en una sola iteración.
  • Reducción a Objetos Agrupados (GroupBy): Usar reduce para agrupar colecciones por categoría: datos.reduce((acc, el) => { (acc[el.cat] ??= []).push(el); return acc; }, {}).

📝 Enunciado y Especificación del Reto

💡 Pistas Clave y Procedimiento Guiado
Usa filter(t => t.tipo === "gasto"), luego reduce para sumar por categorias: acc[t.categoria] = (acc[t.categoria] || 0) + t.cantidad.
🔍 Desplegar Solución Embebida y Explicación Técnica Clic para Ver/Ocultar
Explicación Técnica: El encadenamiento de métodos funcionales permite transformar colecciones complejas sin efectos secundarios (side-effects) ni mutación de los datos originales.
💻 Código de la Solución Comentada:
function analizarGastos(transacciones) {
    // 1. Filtrar gastos válidos
    const gastos = transacciones.filter(t => t.tipo === "gasto");

    // 2. Agrupar y sumar por categoría usando reduce
    const gastosPorCategoria = gastos.reduce((acc, t) => {
        acc[t.categoria] = Number(((acc[t.categoria] || 0) + t.cantidad).toFixed(2));
        return acc;
    }, {});

    // 3. Convertir a array de objetos y ordenar de forma inmutable con toSorted
    const rankingCategorias = Object.entries(gastosPorCategoria)
        .map(([categoria, total]) => ({ categoria, total }))
        .toSorted((a, b) => b.total - a.total);

    const gastoGlobal = gastos.reduce((total, t) => total + t.cantidad, 0);

    return {
        gastoGlobal: Number(gastoGlobal.toFixed(2)),
        rankingCategorias
    };
}

4. Introducción a la Orientación a Objetos: Literales, Constructores y Clases ES6

💡 Fundamentos Conceptuales

JavaScript implementa un modelo de Programación Orientada a Objetos basada en Prototipos que con la llegada de ES6 incorporó la sintaxis formal de clases:

  • 1. Objetos Literales: Notación { clave: valor }. Soporta propiedades abreviadas, propiedades computadas [expresion]: valor y métodos abreviados. Métodos estáticos de Object: Object.keys(), Object.values(), Object.entries() y Object.assign().
  • 2. Funciones Constructoras y Cadena Prototípica (Heredado):

    Funciones invocadas con el operador new (ej. function Usuario(n) { this.nombre = n; }). Los métodos se vinculan al prototipo: Usuario.prototype.saludar = function() { ... }; para que todas las instancias compartan la misma función en memoria a través de la propiedad oculta __proto__.

  • 3. Clases Modernas ES6+ (class): Azúcar sintáctico elegante sobre el modelo de prototipos:
    • Constructor con constructor(...args).
    • Métodos y propiedades de instancia tradicionales.
    • Getters y Setters: get propiedad() y set propiedad(valor) para encapsulación y validación de acceso.
    • Miembros Estáticos con static: Propiedades y métodos vinculados a la clase, no a las instancias (ej. métodos factoría).
    • Campos y Métodos Privados (#): Estándar nativo moderno. Los campos que inician con almohadilla (ej. #clavePrivada) son totalmente inaccesibles desde el exterior de la clase, garantizando encapsulamiento estricto.
    • Herencia y Polimorfismo: Palabra clave extends para heredar de una clase padre e invocación obligatoria a super(...args) en el constructor hijo.
🔍 Ampliación y Estándares 2026

Encapsulamiento Real frente a Convenciones Antiguas:

  • De _propiedad a #propiedad: Antiguamente, la privacidad se simulaba por convención anteponiendo un guion bajo (_saldo), pero la propiedad seguía siendo pública y modificable. Los campos privados #saldo ofrecen verdadero encapsulamiento a nivel de motor (Hard Private), arrojando SyntaxError si se intentan leer desde fuera.
  • Polimorfismo: Las subclases pueden sobreescribir métodos del padre adaptando el comportamiento a su especialización, conservando la llamada al método base mediante super.metodo().
💻 Demostración Práctica e Implementación de Código 
// POO Moderna en JavaScript: Clases, Campos Privados (#) y Herencia
class CuentaBancaria {
    #saldo; // Campo privado estricto

    constructor(titular, saldoInicial = 0) {
        this.titular = titular;
        this.#saldo = Math.max(0, saldoInicial);
    }

    // Getter para lectura controlada
    get saldo() {
        return this.#saldo;
    }

    ingresar(cantidad) {
        if (cantidad <= 0) throw new Error("La cantidad debe ser positiva.");
        this.#saldo += cantidad;
        console.log(`Ingreso de ${cantidad}€. Saldo actual: ${this.#saldo}€`);
    }

    retirar(cantidad) {
        if (cantidad > this.#saldo) throw new Error("Saldo insuficiente.");
        this.#saldo -= cantidad;
        return cantidad;
    }
}

function comparativaOrientacionObjetos() {
    console.group("🏷️ 1. Creación Mediante Objeto Literal");
    const productoLiteral = {
        id: 1,
        nombre: "Monitor Ultrawide",
        precio: 450,
        descuento: 10,
        calcularPrecioFinal() {
            return Number((this.precio * (1 - this.descuento / 100)).toFixed(2));
        }
    };
    console.log("Objeto Literal creado:", productoLiteral.nombre, "- Precio final:", productoLiteral.calcularPrecioFinal(), "€");
    console.groupEnd();

    console.group("⚙️ 2. Creación Mediante Función Constructora y Prototipo (ES5)");
    function ProductoConstructor(id, nombre, precio, descuento = 0) {
        this.id = id;
        this.nombre = nombre;
        this.precio = precio;
        this.descuento = descuento;
    }

    // Vinculación de métodos al Prototype para compartir una sola referencia en memoria
    ProductoConstructor.prototype.calcularPrecioFinal = function() {
        return Number((this.precio * (1 - this.descuento / 100)).toFixed(2));
    };

    const productoProto = new ProductoConstructor(2, "Teclado Mecánico", 120, 15);
    console.log("Instancia desde Constructor:", productoProto.nombre, "- Precio final:", productoProto.calcularPrecioFinal(), "€");
    console.log("¿productoProto instanceof ProductoConstructor?:", productoProto instanceof ProductoConstructor); // true
    console.log("Prototipo directo:", Object.getPrototypeOf(productoProto) === ProductoConstructor.prototype); // true
    console.groupEnd();

    console.group("🚀 3. Clases Modernas ES6+ con Encapsulamiento Privado (#) y Polimorfismo");
    class ProductoES6 {
        #precio;
        #descuento;

        constructor(id, nombre, precio, descuento = 0) {
            this.id = id;
            this.nombre = nombre;
            this.precio = precio;       // Setter con validación
            this.descuento = descuento; // Setter
        }

        get precio() {
            return this.#precio;
        }

        set precio(nuevoPrecio) {
            if (typeof nuevoPrecio !== "number" || nuevoPrecio < 0) {
                throw new TypeError("El precio debe ser un número positivo.");
            }
            this.#precio = nuevoPrecio;
        }

        get descuento() {
            return this.#descuento;
        }

        set descuento(nuevoDescuento) {
            if (nuevoDescuento < 0 || nuevoDescuento > 100) {
                throw new RangeError("El descuento debe estar entre 0% y 100%.");
            }
            this.#descuento = nuevoDescuento;
        }

        calcularPrecioFinal() {
            return Number((this.#precio * (1 - this.#descuento / 100)).toFixed(2));
        }
    }

    class ProductoDigital extends ProductoES6 {
        constructor(id, nombre, precio, descuento, enlaceDescarga, tamanioMB) {
            super(id, nombre, precio, descuento);
            this.enlaceDescarga = enlaceDescarga;
            this.tamanioMB = tamanioMB;
        }

        // Sobreescritura polimórfica: aplica canon digital del 2%
        calcularPrecioFinal() {
            const baseConDescuento = super.calcularPrecioFinal();
            const canonDigital = baseConDescuento * 0.02;
            return Number((baseConDescuento + canonDigital).toFixed(2));
        }
    }

    const ebook = new ProductoDigital(101, "Guía Avanzada DWEC 2024", 30, 20, "https://descargas.es/dwec.pdf", 25);
    console.log(`Producto Digital: ${ebook.nombre}`);
    console.log(`Precio Base: ${ebook.precio}€`);
    console.log(`Precio Final con Descuento y Canon: ${ebook.calcularPrecioFinal()}€`);
    console.log("¿ebook instanceof ProductoES6?:", ebook instanceof ProductoES6); // true
    console.groupEnd();
}

5. Uso de Objetos de Usuario en Aplicaciones y Patrones de Diseño Básicos

💡 Fundamentos Conceptuales

En el desarrollo de software frontend, los patrones de diseño proporcionan soluciones probadas y estandarizadas a problemas arquitectónicos comunes:

  • Modelado de Entidades del Dominio: Organización de los datos del negocio mediante colecciones de objetos interactivos que encapsulan estado y operaciones lógicas (ej. Clases Usuario, ItemCarrito, Catalogo).
  • Patrón Módulo (Module Pattern):

    Aísla la lógica privada exponiendo únicamente una API pública. Históricamente implementado mediante IIFEs (Immediately Invoked Function Expressions); hoy estandarizado de forma nativa con los ES Modules (ficheros .js con declaraciones export e import).

  • Patrón Factoría (Factory Pattern):

    Función o método que encapsula y abstrae la instanciación de objetos complejos. En lugar de invocar directamente new Clase() en múltiples sitios, la factoría decide qué subclase o estructura crear según los parámetros facilitados.

  • Patrón Singleton Simple (Instancia Única):

    Garantiza que una clase posea una única instancia compartida a lo largo de todo el ciclo de vida de la aplicación web, proporcionando un punto de acceso global unificado. Fundamental para gestores de estado, servicios de configuración o buses de eventos.

🔍 Ampliación y Estándares 2026

El Patrón Módulo Nativo y el Singleton en ES Modules:

  • Los Módulos ES son Singletons por Especificación: Cuando un fichero módulo exporta una instancia de objeto (ej. export const servicioAuth = new AuthService();), el motor del navegador evalúa y ejecuta el módulo una sola vez. Cualquier otro fichero que lo importe compartirá exactamente la misma instancia en memoria.
  • Desacoplamiento con Factorías: El patrón factoría facilita el testing unitario, permitiendo inyectar objetos falsos (mocks) o cambiar de implementación sin alterar el código cliente.
💻 Demostración Práctica e Implementación de Código 
// Patrón Singleton y Patrón Factoría en JavaScript

// 1. Patrón Singleton Simple: Gestor de Configuración Global
class ConfiguracionApp {
    static #instancia = null;

    constructor() {
        if (ConfiguracionApp.#instancia) {
            return ConfiguracionApp.#instancia; // Devuelve la instancia ya existente
        }
        this.idioma = "es";
        this.modoOscuro = true;
        this.apiEndpoint = "https://api.empresa.com/v1";
        ConfiguracionApp.#instancia = this;
    }

    static getInstancia() {
        if (!this.#instancia) {
            this.#instancia = new ConfiguracionApp();
        }
        return this.#instancia;
    }
}

            default:

class NotificacionFactory {
    static fabricar(tipo, texto) {
        const id = "NOTIF_" + Math.random().toString(36).substring(2, 7);
        const timestamp = new Date().toLocaleTimeString();

        switch (tipo.toLowerCase()) {
            case "urgente":
                return { id, tipo, texto, prioridad: 1, icono: "🚨", timestamp };
            case "alerta":
                return { id, tipo, texto, prioridad: 2, icono: "⚠️", timestamp };
            case "info":
            default:
                return { id, tipo: "info", texto, prioridad: 3, icono: "ℹ️", timestamp };
        }
    }
}

// Singleton: Gestor Central de Notificaciones
class GestorNotificaciones {
    static #instanciaUnica = null;
    #historial = [];

    constructor() {
        if (GestorNotificaciones.#instanciaUnica) {
            return GestorNotificaciones.#instanciaUnica;
        }
        GestorNotificaciones.#instanciaUnica = this;
    }

    publicar(tipo, mensaje) {
        const notificacion = NotificacionFactory.fabricar(tipo, mensaje);
        this.#historial.push(notificacion);
        console.log(\`[\${notificacion.icono} \${notificacion.tipo.toUpperCase()}] \${notificacion.texto}\`);
        return notificacion;
    }

    obtenerHistorial() {
        return [...this.#historial]; // Retorna copia inmutable
    }
}

6. Depuración de Funciones y Clases, y Documentación con JSDoc

💡 Fundamentos Conceptuales

La depuración estructurada en aplicaciones modulares basadas en POO requiere técnicas de trazabilidad y formalización del código mediante JSDoc:

  • Inspección del Call Stack (Pila de Llamadas) en DevTools:

    Cuando se alcanza un punto de interrupción (breakpoint o debugger;), el panel Sources de DevTools despliega la secuencia completa de llamadas activas. Permite retroceder en la pila de llamadas para examinar el valor de variables en funciones previas que continúan en espera de resolución.

  • Inspección de Ámbitos (Scopes):
    • Local: Variables declaradas dentro del cuerpo de la función actual.
    • Closure (Clausura): Variables del entorno léxico superior capturadas por la función interna.
    • Script / Module: Variables accesibles en el módulo activo.
    • Global: Propiedades del objeto window.
  • Documentación JSDoc para Arquitectura POO:
    • @class: Especifica que la función o constructo representa una clase.
    • @extends {ClasePadre}: Documenta la herencia.
    • @property {tipo} nombre: Documenta propiedades de objetos y clases.
    • @typedef {Object} NombreTipo: Crea tipos de datos personalizados para reutilizar en múltiples funciones.
🔍 Ampliación y Estándares 2026

Depuración de Pérdidas de Memoria por Closures Huérfanos:

  • El Peligro de Clausuras Accidentales: Si una función interna mantiene una referencia léxica a un objeto pesado (como un nodo DOM grande o un array de miles de elementos) y dicha función se almacena en un escuchador global o temporizador, el recolector de basura no podrá liberar la memoria, provocando una fuga de memoria (Memory Leak).
  • Trazas Limpias con console.trace(): Imprime la cadena de llamadas directamente en la consola sin necesidad de pausar la ejecución del navegador.

📝 Enunciado y Especificación del Reto

🔍 Desplegar Solución Embebida y Explicación Técnica Clic para Ver/Ocultar
Explicación Técnica: La combinación de validaciones estrictas de tipos con JSDoc y trazas de pila (console.trace) reduce drásticamente el tiempo necesario para diagnosticar errores en producción.
💻 Código de la Solución Comentada:
/**
 * @typedef {Object} ResumenEstadistico
 * @property {number} total - Suma acumulada de los valores.
 * @property {number} promedio - Media aritmética.
 * @property {number} desviacionMaxima - Diferencia entre el valor máximo y mínimo.
 */

/**
 * Motor de cálculos estadísticos avanzados con validación estricta de tipos.
 * @class
 */
class CalculadoraEstadistica {
    /**
     * Valida que un array contenga exclusivamente números finitos válidos.
     * @param {number[]} datos - Colección a validar.
     * @throws {TypeError} Si algún elemento no es un número finito.
     */
    #validarColeccion(datos) {
        if (!Array.isArray(datos) || datos.length === 0) {
            throw new TypeError("Se requiere un array no vacío de números.");
        }
        for (let i = 0; i < datos.length; i++) {
            if (typeof datos[i] !== "number" || !Number.isFinite(datos[i])) {
                console.trace("Origen del valor no numérico en posición " + i);
                throw new TypeError(\`El elemento en índice \${i} ('\${datos[i]}') no es un número válido.\`);
            }
        }
    }

    /**
     * Ejecuta el análisis estadístico sobre el conjunto de datos numéricos.
     * @param {number[]} serie - Array de valores numéricos.
     * @returns {ResumenEstadistico} Objeto estructurado con las métricas calculadas.
     */
    analizar(serie) {
        try {
            this.#validarColeccion(serie);
            const total = serie.reduce((acc, val) => acc + val, 0);
            const promedio = Number((total / serie.length).toFixed(2));
            const max = Math.max(...serie);
            const min = Math.min(...serie);

            return {
                total: Number(total.toFixed(2)),
                promedio,
                desviacionMaxima: Number((max - min).toFixed(2))
            };
        } catch (error) {
            console.error("❌ Error en análisis estadístico:", error.message);
            return null;
        }
    }
}

const calc = new CalculadoraEstadistica();
console.table(calc.analizar([10.5, 20.2, 35.8, 14.1]));
// Prueba de fallo controlado con traza
calc.analizar([10, "veinte", 30]);
