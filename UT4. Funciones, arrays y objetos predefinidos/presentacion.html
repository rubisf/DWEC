1. Funciones Predefinidas del Lenguaje y Funciones Personalizadas

💡 Fundamentos Conceptuales

En JavaScript, las funciones son ciudadanos de primera clase (First-Class Citizens): pueden asignarse a variables, pasarse como argumentos y devolverse desde otras funciones:

  • Funciones Predefinidas Globales:
    • Conversión y comprobación numérica: parseInt(cadena, base), parseFloat(cadena), isNaN(), isFinite().
    • Codificación de URLs: encodeURI() (codifica URLs completas conservando delimitadores de protocolo/path) y encodeURIComponent() (codifica todos los caracteres especiales para parámetros de consulta ?query=...). Funciones inversas: decodeURI() y decodeURIComponent(). ⚡ Probar encodeURI y encodeURIComponent en JSFiddle 🔗
    • Evaluación dinámica: eval(). ⚠️ Desaconsejada y prohibida en Modo Estricto por representar un grave vector de inyección de código y degradar la optimización del compilador JIT.
  • Definición de Funciones Personalizadas:
    • Declaración de Función (Function Declaration): function calcular() {}. Posee elevación completa (hoisting), pudiendo invocarse antes de su línea de definición.
    • Expresión de Función (Function Expression): const sumar = function(a, b) { return a + b; };. No sufre hoisting de inicialización.
    • Funciones Flecha (Arrow Functions): Sintaxis concisa ((a, b) => a + b). Tienen retorno implícito para expresiones directas y enlace léxico de this (no poseen su propio this, sino que heredan el contexto envolvente donde fueron creadas). No pueden utilizarse como constructoras con new. ⚡ Probar Uso de this en JSFiddle 🔗
  • Parámetros Avanzados: Parámetros por defecto ((x = 10)), parámetros Rest para aridad indefinida o infinitos ((...valores)) y desestructuración directa de argumentos. ⚡ Probar Parámetros Infinitos y por Defecto en JSFiddle 🔗

El Contexto de Ejecución y Enlace de this:

  • Diferencia Crítica de this: En funciones clásicas, this se determina dinámicamente en el momento de la llamada (el objeto que invoca la función). En funciones flecha, this queda fijado estáticamente en tiempo de compilación según el ámbito léxico donde se escribió la función. ⚡ Probar Uso de this en JSFiddle 🔗

2. Arrays: Creación, Manipulación y Métodos de Recorrido

💡 Fundamentos Conceptuales

Los arrays en JavaScript son objetos dinámicos de longitud variable indexados numéricamente con capacidad de almacenar tipos heterogéneos:

  • Creación de Arrays: Notación literal corchetes ([]), constructor new Array(longitud), método estático Array.of(elem1, elem2) y conversión de iterables con Array.from(iterable, mapFn) (ideal para convertir NodeLists del DOM a arrays reales).
  • Mutación de Estructura (Pila y Cola):
    • Operaciones al final: push(...elementos) (añade al final y devuelve nueva longitud) y pop() (extrae y devuelve el último elemento).
    • Operaciones al inicio: unshift(...elementos) (inserta al principio) y shift() (extrae el primer elemento).
  • Transformación y Extracción:
    • splice(inicio, borrarConteo, ...insertar): Método mutador versátil. Elimina elementos, inserta nuevos o sustituye en cualquier posición del array.
    • slice(inicio, fin): Método inmutable. Extrae una porción superficial (shallow copy) del array sin modificar el original. ⚡ Probar Spread y Slice en JSFiddle 🔗
    • concat(...arrays) y join(separador): Combinación de arrays y serialización a cadena de texto.
  • Métodos de Recorrido:
    • Bucle for tradicional con índice numérico.
    • Bucle for ... of para iteración secuencial directa sobre elementos.
    • Método funcional forEach((elemento, indice, array) => { ... }). Nota: forEach no admite break ni continue.
🔍 Ampliación y Estándares 2026

Copia Superficial vs Copia Profunda en Arrays:

  • El operador Spread ([...original]) y slice(): Realizan copias superficiales (Shallow Copy). Si el array contiene objetos internos, las referencias a dichos objetos se comparten entre ambas copias. ⚡ Probar Spread y Slice en JSFiddle 🔗
  • Copia Profunda Moderna con structuredClone(): API estándar nativa para clonar arrays u objetos anidados sin compartir referencias internas, superando las limitaciones de JSON.parse(JSON.stringify()).

    }

    }

        return atendida;

            console.log("Tarea eliminada:", eliminada.titulo);
        }
    }

    mostrar() {
        console.table(this.tareas);
    }

3. Operaciones Agregadas en Arrays: Mapeo, Filtrado, Reducción y Ordenación

💡 Fundamentos Conceptuales

La programación funcional en JavaScript se fundamenta en métodos iteradores inmutables que procesan colecciones de datos sin alterar el array de origen: ⚡ Probar map, filter, reduce, find, sort... en JSFiddle 🔗

  • Transformación con map(callback): Aplica una función a cada elemento y genera un nuevo array de la misma longitud con los resultados transformados.
  • Filtrado con filter(callback): Evalúa un predicado booleano y devuelve un nuevo array conteniendo únicamente aquellos elementos que cumplan la condición.
  • Reducción Acumulativa con reduce(callback, valorInicial): Reduce todo el array a un único valor (un número, un objeto, un mapa o una estructura agrupada) mediante un acumulador.
  • Búsqueda y Verificación:
    • find(callback): Devuelve el primer elemento que cumple el predicado (o undefined).
    • findIndex(callback): Devuelve el índice del primer elemento coincidente (o -1).
    • some(callback): Booleano true si al menos un elemento cumple la condición.
    • every(callback): Booleano true si todos los elementos cumplen la condición.
    • includes(valor): Comprueba si un valor simple existe dentro del array.
  • Ordenación con sort() y Métodos Inmutables ES2023:
    • sort(funcionComparacion): ⚠️ Mutador. Por defecto ordena alfabéticamente convirtiendo a string (lo que provoca que [10, 2].sort() sea [10, 2]). Para números se exige la función de comparación (a, b) => a - b.
    • toSorted() y toReversed(): Estándar moderno inmutable. Devuelven un nuevo array ordenado o invertido sin mutar el original.
  • Encadenamiento Funcional (Method Chaining): Capacidad de concatenar múltiples operaciones (datos.filter(...).map(...).reduce(...)) en un pipeline de datos limpio y declarativo.

Aplanamiento y Reducciones Complejas:

  • Métodos flat() y flatMap(): array.flat(profundidad) aplana sub-arrays anidados. flatMap() combina un mapeo y un aplanamiento de un solo nivel de profundidad de manera óptima en una sola iteración.

function analizarGastos(transacciones) {
    // 1. Filtrar gastos válidos
    const gastos = transacciones.filter(t => t.tipo === "gasto");

    // 2. Agrupar y sumar por categoría usando reduce
    const gastosPorCategoria = gastos.reduce((acc, t) => {
        acc[t.categoria] = Number(((acc[t.categoria] || 0) + t.cantidad).toFixed(2));
        return acc;

    // 3. Convertir a array de objetos y ordenar de forma inmutable con toSorted
    const rankingCategorias = Object.entries(gastosPorCategoria)
        .map(([categoria, total]) => ({ categoria, total }))
        .toSorted((a, b) => b.total - a.total);

    const gastoGlobal = gastos.reduce((total, t) => total + t.cantidad, 0);

    return {
        gastoGlobal: Number(gastoGlobal.toFixed(2)),
        rankingCategorias
    };
}

4. Introducción a la Orientación a Objetos: Literales, Constructores y Clases ES6

💡 Fundamentos Conceptuales

JavaScript implementa un modelo de Programación Orientada a Objetos basada en Prototipos que con la llegada de ES6 incorporó la sintaxis formal de clases: ⚡ Probar POO (Literales, Constructores y Clases) en JSFiddle 🔗

  • 1. Objetos Literales: Notación { clave: valor }. Soporta propiedades abreviadas, propiedades computadas [expresion]: valor y métodos abreviados. Métodos estáticos de Object: Object.keys(), Object.values(), Object.entries() y Object.assign().
  • 2. Funciones Constructoras y Cadena Prototípica (Heredado):

    Funciones invocadas con el operador new (ej. function Usuario(n) { this.nombre = n; }). Los métodos se vinculan al prototipo: Usuario.prototype.saludar = function() { ... }; para que todas las instancias compartan la misma función en memoria a través de la propiedad oculta __proto__.

  • 3. Clases Modernas ES6+ (class): Azúcar sintáctico elegante sobre el modelo de prototipos:
    • Constructor con constructor(...args).
    • Métodos y propiedades de instancia tradicionales.
    • Getters y Setters: get propiedad() y set propiedad(valor) para encapsulación y validación de acceso.
    • Miembros Estáticos con static: Propiedades y métodos vinculados a la clase, no a las instancias (ej. métodos factoría).
    • Campos y Métodos Privados (#): Estándar nativo moderno. Los campos que inician con almohadilla (ej. #clavePrivada) son totalmente inaccesibles desde el exterior de la clase, garantizando encapsulamiento estricto.
    • Herencia y Polimorfismo: Palabra clave extends para heredar de una clase padre e invocación obligatoria a super(...args) en el constructor hijo.

Encapsulamiento Real frente a Convenciones Antiguas:

🧩 1. Singleton

💡 Propósito y Cuándo Utilizarlo

El patrón Singleton garantiza que una clase posea una única instancia compartida a lo largo de todo el ciclo de vida de la aplicación web y proporciona un punto de acceso global y centralizado a ella:

  • ¿Qué problema resuelve? Evita múltiples estados dispersos o instancias duplicadas de recursos compartidos que deben ser únicos en la app.
  • Cuándo utilizarlo: Gestores de configuración global, clientes de conexión a APIs REST/WebSockets, servicios de autenticación y sesión, carritos de compra o telemetría.
  • Identidad en Memoria: Múltiples llamadas a new devuelven la misma referencia (configA === configB es true).
🔍 Características Clave y Estándares

Implementación Moderna con Clases ES6 y Campos Privados:

  • Campo Estático Privado: Se declara static #instancia = null; dentro de la clase para almacenar la referencia única.
  • Constructor Guard: Si #instancia ya existe en el momento de invocar new, se devuelve la instancia existente impidiendo recreaciones.
  • Método Factoría Estático: Se expone static getInstancia() para obtenerla de forma declarativa.
💻 Código de Ejemplo: Implementación de Singleton Creacionales → Creación de objetos 
// --- 1. Patrón Singleton (Creacional) con Campos Privados Estáticos en ES6+ ---

class ConfiguracionSistema {
    static #instancia = null; // Instancia única compartida a nivel de clase

    constructor() {
        if (ConfiguracionSistema.#instancia) {
            // Si ya existe la instancia, devolvemos la misma referencia en memoria
            return ConfiguracionSistema.#instancia;
        }
        this.entorno = "producción";
        this.apiURL = "https://api.empresa.es/v2";
        this.limitePeticiones = 100;
        this.sesionActiva = false;
        this.usuarioActual = null;
        
        ConfiguracionSistema.#instancia = this; // Almacenamos la primera y única instancia
    }

    static getInstancia() {
        if (!this.#instancia) {
            this.#instancia = new ConfiguracionSistema();
        }
        return this.#instancia;
    }

    iniciarSesion(usuario) {
        this.sesionActiva = true;
        this.usuarioActual = usuario;
        console.log(`Sesión iniciada correctamente para: ${usuario}`);
    }
}

🧩 2. Factory Method

💡 Propósito y Cuándo Utilizarlo

El patrón Factory Method define una interfaz o método para crear un objeto, pero delega en las subclases o funciones especializadas la decisión de qué clase concreta instanciar:

  • ¿Qué problema resuelve? Desacopla el código cliente de las clases concretas que deben instanciarse. El creador opera contra interfaces o clases base genéricas.
  • Cuándo utilizarlo: Creación dinámica de componentes de interfaz (botones, modales, tarjetas), procesadores de formato (JSON, XML, CSV) o exportadores de documentos.
  • Principio Abierto/Cerrado (OCP): Se pueden incorporar nuevos tipos creando nuevas subclases sin alterar el código existente del cliente.
🔍 Características Clave y Estándares

Diferencia entre Factory Method y Factoría Simple:

  • Factoría Simple: Un método con un switch/case que devuelve clases distintas según un parámetro de texto.
  • Factory Method (GoF Puro): Patrón polimórfico donde la clase base delega la instanciación mediante herencia sobreescribiendo el método crearBoton().
💻 Código de Ejemplo: Implementación de Factory Method Creacionales → Creación de objetos

class BotonHTML {

🧩 3. Builder

💡 Propósito y Cuándo Utilizarlo

El patrón Builder separa la construcción paso a paso de un objeto complejo de su representación final, permitiendo que el mismo proceso de construcción produzca diferentes configuraciones:

  • ¿Qué problema resuelve? Elimina el problema del "Telescoping Constructor" (constructores con 8 o 10 parámetros opcionales y valores null confusos).
  • Cuándo utilizarlo: Al construir constructores de consultas (Query Builders SQL/NoSQL), ensambladores de peticiones HTTP complejas o configuradores de UI personalizados.
  • Fluent API: Cada método del constructor retorna this, habilitando encadenamiento de métodos limpio (Method Chaining).
🔍 Características Clave y Estándares

Ventajas en Desarrollo Frontend:

  • Inmutabilidad y Validación: Permite validar la integridad de todos los campos juntos en el paso final .construir() o .build() antes de crear la instancia definitiva.
  • Legibilidad Declarativa: El código resulta auto-documentado y legible sin necesidad de memorizar el orden posicional de los argumentos.
💻 Código de Ejemplo: Implementación de Builder Creacionales → Creación de objetos 
// --- 3. Patrón Builder (Creacional): Constructor de Peticiones HTTP Fluent ---

class PeticionHTTPBuilder {
    #url = "";
    #metodo = "GET";
    #cabeceras = {};
    #cuerpo = null;
    #timeoutMs = 5000;

    paraUrl(url) {
        this.#url = url;
        return this; // Permite Method Chaining
    }

    conMetodo(metodo) {
        this.#metodo = metodo.toUpperCase();
        return this;
    }

    conCabecera(clave, valor) {
        this.#cabeceras[clave] = valor;
        return this;
    }

    conCuerpoJSON(datos) {
        this.#cabeceras["Content-Type"] = "application/json";
        this.#cuerpo = JSON.stringify(datos);
        return this;
    }

    conTimeout(ms) {
        this.#timeoutMs = ms;
        return this;
    }

    construir() {
        if (!this.#url) throw new Error("La URL de la petición es obligatoria.");
        return {
            url: this.#url,
            metodo: this.#metodo,
            cabeceras: { ...this.#cabeceras },
            cuerpo: this.#cuerpo,
            timeoutMs: this.#timeoutMs
        };
    }
}

// Uso del Builder con interfaz fluida

    .conCuerpoJSON({ usuario: "ruben", clave: "123456" })

🧩 4. Prototype

💡 Propósito y Cuándo Utilizarlo

El patrón Prototype especifica las clases de objetos a crear mediante una instancia prototípica, creando nuevos objetos copiando o clonando dicho prototipo existente:

  • ¿Qué problema resuelve? Ahorra el elevado coste computacional de instanciar e inicializar objetos complejos desde cero repetidamente.
  • Cuándo utilizarlo: En sistemas con generación masiva de objetos similares (partículas en Canvas, filas de hojas de cálculo, plantillas de documentos predefinidas).
  • Naturaleza Prototípica de JavaScript: Es el modelo fundacional nativo del lenguaje JavaScript mediante Object.create(prototipo) y la propiedad prototype.
🔍 Características Clave y Estándares

Delegación Prototípica vs Copia Superficial:

  • Delegación Prototípica (Object.create): Las propiedades y métodos del prototipo se comparten en memoria; los cambios en el prototipo se reflejan automáticamente en los clones.
  • Clonación de Estado: Permite personalizar propiedades individuales en cada clon sin alterar el prototipo base.
💻 Código de Ejemplo: Implementación de Prototype Creacionales → Creación de objetos 
// --- 4. Patrón Prototype (Creacional): Clonación Prototípica Nativa en JS ---

const prototipoEnemigo = {
    tipo: "Soldado Básico",
    puntosVida: 100,
    armadura: 15,
    habilidades: ["Ataque cuerpo a cuerpo"],

    atacar() {
        console.log(`⚔️ ${this.nombre ?? this.tipo} inflige 20 puntos de daño.`);

    clonar(nombrePersonalizado) {
        // Crea un nuevo objeto delegando en el prototipo actual
        const nuevoEnemigo = Object.create(this);
        nuevoEnemigo.nombre = nombrePersonalizado;
        return nuevoEnemigo;

};

🧩 5. Adapter

💡 Propósito y Cuándo Utilizarlo

El patrón Adapter (Adaptador) permite que clases con interfaces incompatibles puedan colaborar conjuntamente traduciendo la interfaz de una clase a otra que el cliente espera:

  • ¿Qué problema resuelve? Permite integrar librerías de terceros o sistemas legados sin necesidad de modificar el código fuente del cliente ni del proveedor.
  • Cuándo utilizarlo: Al migrar de una librería antigua (ej. jQuery AJAX) a una moderna (Fetch API), al integrar diferentes pasarelas de pago, o al normalizar formatos de datos de APIs dispares.
  • Principio de Responsabilidad Única: Separa la lógica de conversión de datos de la lógica de negocio principal.
🔍 Características Clave y Estándares

Patrón Adapter en Frontend Moderno:

  • Envoltorios de API (Wrappers): En aplicaciones SPA, se crea un adaptador para que los componentes consuman un servicio normalizado, aislando a la interfaz de cambios en los nombres de campos del backend (ej. first_name ➔ nombre).

🧩 6. Decorator

💡 Propósito y Cuándo Utilizarlo

El patrón Decorator (Decorador / Envoltorio) añade funcionalidades a un objeto existente sin modificar su clase original, envolviéndolo en capas como ponerle una funda al móvil o las capas de una cebolla:

  • ¿Por qué no usar Herencia? Si queremos combinar canales (WhatsApp, Email, SMS, Telegram), la herencia exigiría crear clases para cada combinación (NotificadorWhatsAppEmail, NotificadorWhatsAppSMS, etc.). ¡Una explosión inmanejable de decenas de clases rígidas!
  • La Idea del Envoltorio (Wrapper): En lugar de modificar el objeto original, creamos un decorador que lo recibe en su constructor (constructor(notificador)) y lo guarda dentro.
  • Mecanismo de Ejecución: Al invocar enviar(), el decorador primero delega en el objeto original (this.notificador.enviar()) y a continuación añade su comportamiento adicional.
🔍 Características Clave y Estándares

Las 3 Claves del Patrón y Comparativa con Herencia:

  • 1. No modificamos la clase original: La clase base sigue intacta y funcionando exactamente igual.
  • 2. Mismo método / interfaz: El decorador expone el mismo método (enviar()), por lo que el cliente no nota si usa el objeto base o decorado.
  • 3. Encadenamiento libre por capas: Podemos apilar decoradores en cualquier orden:
    [ SMS ➔ [ Email ➔ [ WhatsApp ➔ [ NotificadorBase ] ] ] ]
  • Herencia vs Decorator: La herencia es estática en compilación; el decorator es dinámico en tiempo de ejecución (añades o quitas capas según lo necesite el usuario).
💻 Código de Ejemplo: Implementación de Decorator Estructurales → Composición de clases y objetos 
// --- 6. Patrón Decorator (Estructural): Envolver Objetos como Capas sin Modificar la Base ---

}

    }
    enviar(mensaje) {

    }
}

// 3. Decorador Email: Envuelve cualquier notificador y añade correo

    constructor(notificador) {
        this.notificador = notificador;
    }
    enviar(mensaje) {
        this.notificador.enviar(mensaje);

🧩 7. Proxy

💡 Propósito y Cuándo Utilizarlo

El patrón Proxy proporciona un intermediario que controla, audita y gestiona el acceso a un objeto real, interceptando sus operaciones tanto ANTES como DESPUÉS de ejecutarse:

  • Fase ANTES (Pre-procesamiento): Validación de tipos/parámetros, control de permisos/seguridad, comprobación previa de caché e inicio de cronómetros (telemetría).
  • Fase DESPUÉS (Post-procesamiento): Almacenamiento en caché del resultado, medición de tiempos de respuesta (auditoría/benchmarking), enriquecimiento/formateo de la respuesta devuelta y registro de logs de éxito/error.
  • API Nativa de JavaScript: ES6 proporciona new Proxy(target, handler) con trampas como get, set y apply para interceptar lectura, mutación o invocación.
🔍 Características Clave y Estándares

El Doble Momento de Interceptación (Antes y Después):

  • Antes: Si el proxy resuelve la petición (ej. con caché o rechazando por falta de permisos), ahorra por completo la llamada al objeto real.
  • Después: Si la llamada al objeto real se produce, el proxy tiene acceso al resultado devuelto para auditarlo, modificarlo o almacenar métricas antes de entregarlo al cliente.
💻 Código de Ejemplo: Implementación de Proxy Estructurales → Composición de clases y objetos 
// --- 7. Patrón Proxy (Estructural): Acciones ANTES y DESPUÉS con Proxy ES6 ---

// 1. Servicio Real (Operación costosa en cómputo o red)
const servicioAPI = {
    obtenerCotizacion(cripto) {
        console.log(`🌐 [Servicio Real] Solicitando cotización remota de: ${cripto}...`);
        return { cripto, precioUSD: 62450.50 };
    }
};

// 2. Proxy Intermediario: Control Total ANTES y DESPUÉS
const cacheMemoria = new Map();

const proxyServicio = new Proxy(servicioAPI, {
    get(target, propiedad) {
        if (propiedad === "obtenerCotizacion") {
            return function(cripto) {
                // ==========================================
                // 🔹 1. ACCIONES "ANTES" DE LLAMAR A LA FUNCIÓN
                // ==========================================
                console.log(`
➡️ [Proxy ANTES]: Validando entrada y comprobando caché para '${cripto}'...`);
                
                // Validación de entrada previa
                if (!cripto || typeof cripto !== "string") {
                    throw new Error("Parámetro de criptomoneda inválido.");
                }

                // Ahorro de llamada si ya está en memoria caché
                if (cacheMemoria.has(cripto)) {
                    console.log(`⚡ [Proxy HIT]: Servido desde memoria caché (ahorra llamada real).`);
                    return cacheMemoria.get(cripto);
                }

                // Inicio de cronómetro para auditoría de rendimiento
                const tInicio = performance.now();

                // ==========================================
                // ⚙️ LLAMADA AL MÉTODO DEL OBJETO REAL
                // ==========================================
                const resultadoReal = target[propiedad](cripto);

                // ==========================================
                // 🔹 2. ACCIONES "DESPUÉS" DE LLAMAR A LA FUNCIÓN
                // ==========================================
                const duracionMs = (performance.now() - tInicio).toFixed(2);

                // 1. Guardar en caché el resultado recién obtenido
                cacheMemoria.set(cripto, resultadoReal);

                // 2. Registro de auditoría y métricas de rendimiento
                console.log(`⬅️ [Proxy DESPUÉS]: Guardado en caché y auditado (${duracionMs} ms de cómputo).`);

                // 3. Post-procesamiento: enriquecer la respuesta antes de devolverla
                resultadoReal.auditadoPor = "ProxySeguridadV1";
                resultadoReal.recuperadoEn = new Date().toLocaleTimeString();

                return resultadoReal; // El cliente recibe el objeto final enriquecido
            };
        }
        return target[propiedad];
    }
});

// --- Demostración práctica ---

console.log("Resultado final recibido por el cliente:", res1);

console.log("
=== 2. Segunda llamada (con caché activa) ===");
const res2 = proxyServicio.obtenerCotizacion("BTC");

🧩 9. Composite

💡 Propósito y Cuándo Utilizarlo

El patrón Composite (Objeto Compuesto) permite componer objetos en estructuras jerárquicas en árbol (relación parte-todo) permitiendo a los clientes tratar objetos individuales y compuestos de manera uniforme:

  • ¿Qué problema resuelve? Evita que el cliente deba comprobar si un elemento es simple o una colección para invocar sus métodos.
  • Cuándo utilizarlo: Sistemas de archivos (Archivos y Carpetas), árboles del DOM de HTML, menús multinivel, o interfaces gráficas con contenedores y componentes hijos.
  • Recursión Elegante: Las operaciones se propagan automáticamente a través de todos los nodos descendientes del árbol.
🔍 Características Clave y Estándares

El Árbol DOM como Composite por Excelencia:

  • Estructura DOM: Un Node de HTML puede ser un texto individual (hoja) o un elemento como <div> que contiene otros nodos hijos. Los métodos como cloneNode() o textContent se aplican de forma homogénea en todo el árbol.

🧩 10. Observer

💡 Propósito y Cuándo Utilizarlo

El patrón Observer (Observador) define una relación de 1 a N entre objetos: cuando el emisor (**Subject**) cambia de estado o realiza una acción, **notifica automáticamente** a todos sus escuchadores (**Observers**):

  • ¿Qué problema resuelve? Permite la comunicación reactiva y desacoplada: el emisor no necesita saber quién lo escucha ni cuántos observadores hay.
  • Integración Nativa en JavaScript: En JavaScript no hace falta programar listas manuales de callbacks; el propio lenguaje implementa el patrón mediante la clase nativa EventTarget y el estándar de eventos.
  • Cuándo utilizarlo: Modelos de datos reactivos (carritos, almacenes de estado, autenticación), comunicación entre componentes y actualización de interfaces.
🔍 Características Clave y Estándares

La Tríada Nativa del Patrón Observer en JavaScript:

  • 1. Sujeto Observable (Subject): Cualquier clase que hereda de extends EventTarget.
  • 2. Suscripción (Subscribe): objeto.addEventListener("evento", callback).
  • 3. Notificación (Notify): this.dispatchEvent(new CustomEvent("evento", { detail: datos })).
💻 Código de Ejemplo: Implementación de Observer Comportamentales → Comunicación entre objetos 
// --- 10. Patrón Observer (Comportamental): Implementación Nativa con EventTarget ---

// 1. Sujeto Observable (Hereda de la clase nativa EventTarget)
class CarritoCompras extends EventTarget {
    #productos = [];

    agregarProducto(nombre, precio) {
        const item = { nombre, precio };
        this.#productos.push(item);

        // Notificación nativa (Notify) a todos los observadores suscritos:
        const evento = new CustomEvent("productoAgregado", {
            detail: {
                producto: item,
                totalArticulos: this.#productos.length
            }
        });
        this.dispatchEvent(evento); // Dispara el evento nativo
    }

    vaciar() {
        this.#productos = [];
        this.dispatchEvent(new CustomEvent("carritoVaciado"));
    }
}

// 2. Instancia del Sujeto
const miCarrito = new CarritoCompras();

// 3. Observadores (Suscripción mediante addEventListener)
// Observador A: Actualización de la Interfaz de Usuario
miCarrito.addEventListener("productoAgregado", (evento) => {
    const { producto, totalArticulos } = evento.detail;
    console.log(`🖥️ [UI]: Se añadió "${producto.nombre}". Total en cesta: ${totalArticulos} artículos.`);
});

// Observador B: Servicio de Analítica / Telemetría
miCarrito.addEventListener("productoAgregado", (evento) => {
    console.log(`📊 [Analítica]: Conversión registrada para producto de ${evento.detail.producto.precio}€.`);
});

// Observador C: Escucha un evento diferente del mismo sujeto
miCarrito.addEventListener("carritoVaciado", () => {
    console.log("🗑️ [Alerta]: El carrito ha sido vaciado por completo.");
});

// --- Demostración del flujo reactivo ---
miCarrito.agregarProducto("Portátil Gaming", 1250);
miCarrito.agregarProducto("Ratón Inalámbrico", 35);
miCarrito.vaciar();

🧩 11. Strategy

💡 Propósito y Cuándo Utilizarlo

El patrón Strategy (Estrategia) define una familia de algoritmos intercambiables, encapsulando cada uno de ellos en una clase u objeto independiente y haciéndolos intercambiables en tiempo de ejecución:

  • ¿Qué problema resuelve? Elimina estructuras complejas y difíciles de mantener basadas en múltiples condicionales if-else o switch.
  • Cuándo utilizarlo: Diferentes algoritmos de ordenación o compresión, cálculo dinámico de impuestos o descuentos comerciales, y estrategias de validación de formularios.
  • Principio de Responsabilidad Única: Cada algoritmo se prueba, aísla y evoluciona de manera independiente.
🔍 Características Clave y Estándares

Estrategias en JavaScript Funcional:

  • Objetos Literales y Funciones: En JavaScript, las estrategias no requieren necesariamente jerarquías complejas de clases; pueden implementarse elegantemente como funciones puras u objetos con métodos directos.

🧩 12. Command

💡 Propósito y Cuándo Utilizarlo

El patrón Command (Comando) consiste en convertir una acción o petición en un objeto independiente. En lugar de invocar directamente métodos sobre un receptor, encapsulamos la orden dentro de un objeto con su método ejecutar() y deshacer():

  • La Metáfora del Mando a Distancia: Un mando tiene botones que no saben de electrónica ni de cómo funciona un televisor o aire acondicionado; solo disparan el comando asignado.
  • Los 4 Protagonistas del Patrón:
    • Invocador (Mando / Botón de UI): Solicita la orden llamando a comando.ejecutar().
    • Comando: Encapsula la acción y delega en el receptor adecuado.
    • Receptor (Televisión / Base de datos): Quien realmente sabe realizar el trabajo.
    • Cliente: Crea y vincula los comandos específicos con el invocador.
  • Superpoderes: Permite implementar fácilmente Deshacer (Ctrl + Z), repetición de órdenes, colas de tareas asíncronas y macros (secuencias de comandos agrupadas).
🔍 Características Clave y Estándares

Diferencia clave entre Command y Strategy:

  • Strategy: Encapsula algoritmos alternativos (cambia cómo se calcula algo, ej. 3 formas de aplicar un descuento comercial).
  • Command: Encapsula una orden/acción concreta (permite guardarla, diferirla, encolarla o deshacerla en el tiempo).
💻 Código de Ejemplo: Implementación de Command Comportamentales → Comunicación entre objetos 
// --- 12. Patrón Command (Comportamental): Mando a Distancia con Deshacer (Undo) ---

// 1. RECEPTOR: El dispositivo que sabe cómo realizar el trabajo real
class Television {
    encender() { console.log("📺 Televisión encendida."); }
    apagar() { console.log("📺 Televisión apagada."); }
    subirVolumen() { console.log("🔊 Volumen subido (+1)."); }
    bajarVolumen() { console.log("🔉 Volumen bajado (-1)."); }
}

// 2. COMANDOS: Encapsulan cada orden y su acción inversa (deshacer)
class EncenderTVComando {
    constructor(television) { this.tv = television; }
    ejecutar() { this.tv.encender(); }
    deshacer() { this.tv.apagar(); }
}

class SubirVolumenComando {
    constructor(television) { this.tv = television; }
    ejecutar() { this.tv.subirVolumen(); }
    deshacer() { this.tv.bajarVolumen(); }
}

// 3. INVOCADOR: El Mando a Distancia (No conoce dispositivos, solo ejecuta comandos)
class MandoADistancia {
    #historial = [];

    pulsarBoton(comando) {
        comando.ejecutar();
        this.#historial.push(comando); // Guarda la orden para poder deshacerla
    }

    pulsarBotonDeshacer() {
        const ultimoComando = this.#historial.pop();
        if (ultimoComando) {
            console.log("⏪ [Ctrl+Z]: Deshaciendo última acción...");
            ultimoComando.deshacer();
        } else {
            console.log("⚠️ No hay más acciones en el historial.");
        }
    }
}

// 4. CLIENTE: Configura los dispositivos, comandos y mando
const miTV = new Television();
const mando = new MandoADistancia();

// Ejecutamos diferentes órdenes desde el mismo mando
mando.pulsarBoton(new EncenderTVComando(miTV));   // 📺 Televisión encendida.
mando.pulsarBoton(new SubirVolumenComando(miTV)); // 🔊 Volumen subido (+1).
mando.pulsarBoton(new SubirVolumenComando(miTV)); // 🔊 Volumen subido (+1).

// Deshacer operaciones en orden inverso (Ctrl + Z)
mando.pulsarBotonDeshacer(); // ⏪ Deshace: 🔉 Volumen bajado (-1).
mando.pulsarBotonDeshacer(); // ⏪ Deshace: 🔉 Volumen bajado (-1).
mando.pulsarBotonDeshacer(); // ⏪ Deshace: 📺 Televisión apagada.

🧩 13. Mediator

💡 Propósito y Cuándo Utilizarlo

El patrón Mediator (Mediador) reduce el acoplamiento caótico entre múltiples objetos impidiendo que se comuniquen directamente entre sí y obligándolos a colaborar únicamente a través de un objeto mediador central:

  • ¿Qué problema resuelve? Evita una red enredada de dependencias en "tela de araña" donde cada objeto necesita referencias directas a todos los demás.
  • Cuándo utilizarlo: Salas de chat multiusuario, formularios complejos donde un campo altera el estado de múltiples selectores y botones, o torres de control de tráfico.
  • Relación 1 a N Centralizada: Los componentes (colegas) solo conocen al mediador central.
🔍 Características Clave y Estándares

Mediator frente a Observer:

  • Observer: La comunicación fluye unidireccionalmente desde el emisor hacia los observadores suscritos.
  • Mediator: Coordina y arbitra bidireccionalmente la interacción cruzada entre múltiples componentes participantes.
💻 Código de Ejemplo: Implementación de Mediator Comportamentales → Comunicación entre objetos 
// --- 13. Patrón Mediator (Comportamental): Sala de Chat Centralizada ---

// Mediador Central
class SalaChatMediador {
    #participantes = new Map();

    registrar(usuario) {
        this.#participantes.set(usuario.nombre, usuario);
        usuario.sala = this;
        console.log(`[Sala] ${usuario.nombre} se ha unido.`);
    }

    enviar(mensaje, remitente, destinatario = null) {
        if (destinatario) {
            // Comunicación privada directa mediante el mediador
            const receptor = this.#participantes.get(destinatario);
            receptor?.recibir(`(Privado de ${remitente.nombre}): ${mensaje}`);
        } else {
            // Emisión broadcast a todos excepto el remitente
            this.#participantes.forEach(u => {
                if (u !== remitente) {
                    u.recibir(`(${remitente.nombre}): ${mensaje}`);
                }
            });
        }
    }
}

// Participante que solo conoce al mediador
class UsuarioChat {
    constructor(nombre) {
        this.nombre = nombre;
        this.sala = null;
    }
    enviar(mensaje, para = null) { this.sala.enviar(mensaje, this, para); }
    recibir(mensaje) { console.log(`[${this.nombre} recibe] ${mensaje}`); }
}

🧩 14. State

💡 Propósito y Cuándo Utilizarlo

El patrón State (Estado) permite a un objeto alterar su comportamiento cuando cambia su estado interno, aparentando que el objeto ha cambiado de clase:

  • ¿Qué problema resuelve? Sustituye enormes bloques de condicionales (if (estado === "reproduciendo") ... else if ...) por clases de estado polimórficas.
  • Cuándo utilizarlo: Máquinas de estados finitos (FSM), reproductores multimedia, flujos de pedidos (Pendiente ➔ Pagado ➔ Enviado ➔ Entregado), o personajes de videojuegos.
  • Transición Limpia: El propio estado activo o el contexto determinan cuándo y cómo transicionar al siguiente estado.
🔍 Características Clave y Estándares

Ventajas de Encapsular Estados:

  • Estados como Clases Independientes: Añadir un nuevo estado (ej. EstadoEnBucle) solo requiere crear una nueva clase implementando los métodos, sin tocar los estados existentes.

// Factoría de Objetos Notificación
class NotificacionFactory {
    static fabricar(tipo, texto) {
        const id = "NOTIF_" + Math.random().toString(36).substring(2, 7);
        const timestamp = new Date().toLocaleTimeString();

        switch (tipo.toLowerCase()) {
            case "urgente":
                return { id, tipo, texto, prioridad: 1, icono: "🚨", timestamp };
            case "alerta":
                return { id, tipo, texto, prioridad: 2, icono: "⚠️", timestamp };
            case "info":
            default:
                return { id, tipo: "info", texto, prioridad: 3, icono: "ℹ️", timestamp };
        }
    }
}

// Singleton: Gestor Central de Notificaciones
class GestorNotificaciones {
    static #instanciaUnica = null;
    #historial = [];

    constructor() {
        if (GestorNotificaciones.#instanciaUnica) {
            return GestorNotificaciones.#instanciaUnica;
        }
        GestorNotificaciones.#instanciaUnica = this;
    }

    publicar(tipo, mensaje) {
        const notificacion = NotificacionFactory.fabricar(tipo, mensaje);
        this.#historial.push(notificacion);
        console.log(`[${notificacion.icono} ${notificacion.tipo.toUpperCase()}] ${notificacion.texto}`);
        return notificacion;
    }

    obtenerHistorial() {
        return [...this.#historial]; // Retorna copia inmutable
    }
}

💡 Fundamentos Conceptuales

La depuración estructurada en aplicaciones modulares basadas en POO requiere técnicas de trazabilidad y formalización del código mediante JSDoc:

    • Closure (Clausura): Variables del entorno léxico superior capturadas por la función interna.

    • @extends {ClasePadre}: Documenta la herencia.
    • @property {tipo} nombre: Documenta propiedades de objetos y clases.
    • @typedef {Object} NombreTipo: Crea tipos de datos personalizados para reutilizar en múltiples funciones.

/**
 * @typedef {Object} ResumenEstadistico
 * @property {number} total - Suma acumulada de los valores.
 * @property {number} promedio - Media aritmética.
 * @property {number} desviacionMaxima - Diferencia entre el valor máximo y mínimo.
 */

/**
 * Motor de cálculos estadísticos avanzados con validación estricta de tipos.
 * @class
 */
class CalculadoraEstadistica {
    /**
     * Valida que un array contenga exclusivamente números finitos válidos.
     * @param {number[]} datos - Colección a validar.
     * @throws {TypeError} Si algún elemento no es un número finito.
     */
    #validarColeccion(datos) {
        if (!Array.isArray(datos) || datos.length === 0) {
            throw new TypeError("Se requiere un array no vacío de números.");
        }
        for (let i = 0; i < datos.length; i++) {
            if (typeof datos[i] !== "number" || !Number.isFinite(datos[i])) {
                console.trace("Origen del valor no numérico en posición " + i);
                throw new TypeError(`El elemento en índice ${i} ('${datos[i]}') no es un número válido.`);
            }
        }
    }

    /**
     * Ejecuta el análisis estadístico sobre el conjunto de datos numéricos.
     * @param {number[]} serie - Array de valores numéricos.
     * @returns {ResumenEstadistico} Objeto estructurado con las métricas calculadas.
     */
    analizar(serie) {
        try {
            this.#validarColeccion(serie);
            const total = serie.reduce((acc, val) => acc + val, 0);
            const promedio = Number((total / serie.length).toFixed(2));
            const max = Math.max(...serie);
            const min = Math.min(...serie);

            return {
                total: Number(total.toFixed(2)),
                promedio,
                desviacionMaxima: Number((max - min).toFixed(2))
            };
        } catch (error) {
            console.error("❌ Error en análisis estadístico:", error.message);
            return null;
        }
    }
}

console.table(calc.analizar([10.5, 20.2, 35.8, 14.1]));
