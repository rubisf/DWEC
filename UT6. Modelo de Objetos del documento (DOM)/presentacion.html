1. El Árbol DOM y Jerarquía de Nodos

💡 Fundamentos Conceptuales

El Document Object Model (DOM) representa cualquier documento HTML como un árbol jerárquico de nodos orientados a objetos:

  • Tipos Principales de Nodos: Document (raíz), Element (etiquetas HTML), Text (contenido textual dentro de etiquetas) y Comment (comentarios HTML).
  • Propiedades de Navegación de Nodos (Incluyen texto/espacios): parentNode, childNodes, firstChild, lastChild, nextSibling, previousSibling.
🔍 Ampliación y Estándares 2026

Propiedades de navegación orientadas exclusivamente a elementos HTML (Element Traversal):

  • Navegación Limpia entre Elementos: parentElement, children (HTMLCollection de nodos elemento), firstElementChild, lastElementChild, nextElementSibling, previousElementSibling. Ignoran saltos de línea y texto plano.
  • Diferencia NodeList vs HTMLCollection: HTMLCollection es una colección viva (live) de elementos; querySelectorAll() devuelve un NodeList estático que soporta forEach().

}

2. Selección y Recorrido del DOM (QuerySelector y Closest)

💡 Fundamentos Conceptuales

Selección y recorrido eficiente del árbol DOM mediante selectores CSS estandarizados:

  • document.querySelector(selectorCSS): Devuelve el primer elemento que coincide con el selector CSS especificado (o null si no existe).
  • document.querySelectorAll(selectorCSS): Devuelve una NodeList estática con todos los elementos coincidentes.
  • element.closest(selectorCSS): Asciende por la cadena de ancestros desde el elemento actual buscando el primer nodo padre que coincida con el selector.
🔍 Ampliación y Estándares 2026

Métodos de comprobación de coincidencia y rendimiento de búsqueda:

  • element.matches(selectorCSS): Evalúa si el elemento actual coincide con un selector CSS determinado devolviendo true o false.
  • Comparación de Rendimiento: document.getElementById() y getElementsByClassName() ofrecen un rendimiento ligeramente superior en bucles masivos respecto a querySelector por evitar el motor de evaluación CSS.
💻 Demostración Práctica e Implementación de Código 🚀 Abrir Ejemplo Real en Vivo (ejemplo2_selectores_dom.js) 🔗 
// UT6 - Ejemplo 2: QuerySelector
if (typeof document !== 'undefined') {
    const el = document.querySelector(".tarjeta");
    console.log("Elemento encontrado:", el ? el.tagName : "No presente");
}

3. Manipulación Dinámica Moderna: Clases, Atributos y Dataset

💡 Fundamentos Conceptuales

Manipulación dinámica de la estructura, atributos y clases visuales del DOM:

  • Gestión de Clases con classList: Proporciona métodos limpios como add(), remove(), toggle() y contains() sin necesidad de manipular la cadena className.
  • Manipulación de Atributos: getAttribute(), setAttribute(), removeAttribute() y hasAttribute() para interactuar con atributos HTML nativos.
  • Atributos Personalizados data-*: Permiten almacenar datos arbitrarios en elementos HTML. Se acceden programáticamente mediante la propiedad element.dataset.
🔍 Ampliación y Estándares 2026

Optimización de renderizado y prevención de problemas de reflow (reflujo de diseño):

  • DocumentFragment: Contenedor temporal ligero fuera del árbol DOM principal. Permite acumular decenas de nuevos nodos e insertarlos en el documento en una única operación DOM.
  • Evitar Reflow / Repaint: Leer propiedades geométricas como offsetHeight o getBoundingClientRect() fuerza al navegador a recalcular el diseño inmediatamente. Debe agruparse la lectura de propiedades geométricas separada de la escritura de clases o estilos.
💻 Demostración Práctica e Implementación de Código 🚀 Abrir Ejemplo Real en Vivo (ejemplo3_manipulacion_dataset.js) 🔗

    console.log("Dataset asignado:", div.dataset.usuarioId);

4. Fundamentos de APIs RESTful y Códigos de Respuesta

💡 Fundamentos Conceptuales

Una API RESTful (Representational State Transfer) es una arquitectura de comunicación HTTP para el intercambio de datos estructurados (generalmente JSON):

  • Verbos HTTP Principales: GET (recuperar recurso), POST (crear recurso), PUT (reemplazar recurso completo), PATCH (modificar recurso parcialmente), DELETE (eliminar recurso).
  • Códigos de Estado HTTP:
    • 200 OK / 201 Created: Éxito en la operación.
    • 400 Bad Request / 401 Unauthorized / 404 Not Found: Errores del cliente.
    • 500 Internal Server Error: Error interno del servidor.
🔍 Ampliación y Estándares 2026

Endpoints, payloads y buenas prácticas de diseño de arquitecturas REST:

  • Estructura de Recursos Nombres/URLs: Las URIs deben representar recursos en plural (ej. /api/v1/usuarios/42) y no acciones o verbos.
  • Cabeceras de Petición HTTP: Content-Type: application/json especifica el formato del cuerpo; Authorization: Bearer <token> transmite credenciales seguras.
