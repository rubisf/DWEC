1. Estructura del Árbol DOM y sus Niveles Jerárquicos

💡 Fundamentos Conceptuales

El Document Object Model (DOM) es una interfaz de programación estandarizada por el W3C y WHATWG que representa un documento HTML como un árbol jerárquico de nodos de objetos en memoria:

  • Tipos de Nodos Fundamentales (Jerarquía Node):
    • Node.DOCUMENT_NODE (Tipo 9): El nodo raíz supremo, representado por document.
    • Node.ELEMENT_NODE (Tipo 1): Representa cada una de las etiquetas HTML del documento (<div>, <p>, <button>).
    • Node.TEXT_NODE (Tipo 3): Contiene el texto textual dentro de una etiqueta o entre elementos (incluyendo saltos de línea y espacios en blanco del código HTML).
    • Node.COMMENT_NODE (Tipo 8): Comentarios HTML (<!-- ... -->).
  • Navegación Tradicional por Nodos (Incluye Nodos de Texto y Espacios):

    parentNode, childNodes (NodeList viva de todos los hijos), firstChild, lastChild, nextSibling, previousSibling. ⚠️ Peligro: Los saltos de línea en el HTML generan nodos de texto invisibles que pueden hacer que firstChild no sea el primer elemento esperado.

  • Navegación Moderna Exclusiva por Elementos (Recomendada):

    Ignora espacios y comentarios, navegando estrictamente entre etiquetas HTML:

    • parentElement: Elemento padre directo.
    • children: Colección HTMLCollection conteniendo únicamente los nodos de tipo elemento.
    • firstElementChild y lastElementChild: Primer y último hijo de tipo etiqueta.
    • nextElementSibling y previousElementSibling: Elementos hermanos contiguos.
🔍 Ampliación y Estándares 2026

El Coste de Acceso al DOM (Reflow y Repaint):

  • Reflow (Layout): Recálculo de la geometría y posición física de los elementos en el documento. Ocurre al añadir o eliminar nodos o cambiar dimensiones. Es la operación más costosa en rendimiento.
  • Repaint: Redibujado de píxeles en pantalla (colores, sombras) sin alterar la geometría.
  • Minimizar Lecturas y Escrituras Intercaladas: Leer una propiedad geométrica (como offsetHeight) tras modificar estilos en el DOM fuerza al navegador a ejecutar un Reflow síncrono involuntario (Layout Thrashing).
💻 Demostración Práctica e Implementación de Código 
// Navegación por la jerarquía DOM: Comparativa de propiedades de Elemento vs Nodo
const contenedor = document.getElementById("seccion-principal");

console.log("=== Navegación Jerárquica Segura por Elementos ===");
console.log("Padre del contenedor:", contenedor.parentElement.tagName);
console.log("Número de etiquetas hijas (children):", contenedor.children.length);
console.log("Primer hijo elemento (firstElementChild):", contenedor.firstElementChild.tagName);
console.log("Último hijo elemento (lastElementChild):", contenedor.lastElementChild.tagName);

// Iterar únicamente sobre elementos ignorando espacios en blanco
for (const hijo of contenedor.children) {
    console.log(` -> Elemento hijo: <${hijo.tagName.toLowerCase()}> con ID '${hijo.id}'`);
}

Para cada nodo debe mostrar su tipo (`ELEMENT_NODE`, `TEXT_NODE`), su nombre de etiqueta y, en caso de ser un elemento, cuántos hijos posee mediante `children.length`.

🔍 Desplegar Solución Embebida y Explicación Técnica Clic para Ver/Ocultar
Explicación Técnica: Comprender la anatomía del árbol de nodos y distinguir entre nodos de texto y nodos de elemento es indispensable para manipular el DOM sin errores derivados de saltos de línea.
💻 Código de la Solución Comentada:
function inspeccionarJerarquiaDOM(nodo, nivel = 0) {
    const indentacion = "  ".repeat(nivel);
    const tipoTexto = nodo.nodeType === Node.ELEMENT_NODE ? "Etiqueta" :
                      nodo.nodeType === Node.TEXT_NODE ? "Texto" :
                      nodo.nodeType === Node.COMMENT_NODE ? "Comentario" : "Otro";

    // Si es un nodo de texto con sólo espacios en blanco, omitir o resumir
    if (nodo.nodeType === Node.TEXT_NODE) {
        const textoLimpio = nodo.nodeValue.trim();
        if (textoLimpio) {
            console.log(\`\${indentacion}📄 [Texto]: "\${textoLimpio}"\`);
        }
        return;
    }

    if (nodo.nodeType === Node.ELEMENT_NODE) {
        console.log(\`\${indentacion}📁 <\${nodo.tagName.toLowerCase()}> [ID: \${nodo.id || "sin id"}, Hijos: \${nodo.children.length}]\`);
        
        // Recorrido recursivo de los hijos de elemento
        for (const hijo of nodo.childNodes) {
            inspeccionarJerarquiaDOM(hijo, nivel + 1);
        }
    }
}

2. Objetos del DOM: Acceso a Elementos y Selección Moderna

💡 Fundamentos Conceptuales

Para manipular el documento, JavaScript debe localizar los elementos en memoria. La especificación ha evolucionado desde métodos clásicos hacia selectores CSS universales:

  • Métodos Clásicos de Selección:
    • document.getElementById("id"): Extremadamente rápido. Devuelve una única referencia de elemento o null.
    • document.getElementsByClassName("clase"): Devuelve una colección HTMLCollection viva (Live Collection) con todos los elementos coincidentes.
    • document.getElementsByTagName("tag"): Devuelve una HTMLCollection viva con todas las etiquetas de ese tipo.
  • Colecciones Vivas (Live) vs Estáticas (Static):

    Una HTMLCollection es viva: si se añade o elimina un elemento en el DOM, la colección se actualiza automáticamente en memoria al instante. Por el contrario, una NodeList estática es una foto fija en el instante de la consulta.

  • Selectores W3C Modernos (Selectors API):
    • document.querySelector("selectorCSS"): Devuelve el primer elemento que coincida con cualquier selector CSS complejo (clases, IDs, atributos, pseudoclases) o null.
    • document.querySelectorAll("selectorCSS"): Devuelve una colección NodeList estática con todos los elementos coincidentes. Soporta directamente el método .forEach().
  • Métodos Contextuales de Elemento:
    • elemento.matches("selector"): Comprueba si el elemento actual satisface un selector CSS (devuelve booleano).
    • elemento.closest("selector"): Busca hacia arriba en el árbol DOM el ancestro más cercano (incluyendo al propio elemento) que coincida con el selector. Imprescindible para delegación de eventos.
🔍 Ampliación y Estándares 2026

Conversión de NodeList y HTMLCollection a Arrays:

  • Uso de Array.from() o Spread: Ni HTMLCollection ni NodeList poseen los métodos funcionales de array (como .map(), .filter() o .reduce()). Para utilizarlos, se debe convertir la colección: const elementos = Array.from(document.querySelectorAll('.card')); o [...document.querySelectorAll('.card')].
  • Búsquedas Ágiles Contextuales: Tanto querySelector como querySelectorAll pueden invocarse desde cualquier elemento del DOM, no sólo desde document, restringiendo la búsqueda exclusivamente al subárbol interno de ese contenedor.
💻 Demostración Práctica e Implementación de Código 
// Selección moderna de elementos y evaluación contextual con matches y closest
// 1. Selector CSS complejo con querySelectorAll
const botonesPeligrosos = document.querySelectorAll("article.noticia button.btn-eliminar[data-activo='true']");
console.log("Número de botones peligrosos encontrados:", botonesPeligrosos.length);

// 2. Uso del método closest para ascender al contenedor padre
botonesPeligrosos.forEach(boton => {
    boton.addEventListener("click", () => {
        // Encontrar el artículo padre más próximo
        const articulo = boton.closest("article.noticia");
        if (articulo) {
            console.log("Artículo localizado con closest():", articulo.dataset.id);
        }

        // Comprobación de selector con matches
        if (boton.matches(":disabled")) {
            console.log("El botón está deshabilitado.");
        }
    });
});

🎯 Reto 2: Selector Contextual Avanzado en Estructuras Anidadas con matches y closest

📝 Enunciado y Especificación del Reto
Diseña una función llamada `resaltarFilaContextual(elementoClicado)` que, al hacer clic en cualquier sub-elemento dentro de una tabla compleja (un icono, un enlace, un span o un botón), utilice `closest()` para localizar la fila `<tr>` contenedora, verifique con `matches(".fila-activa")` si la fila ya estaba seleccionada, y conmute su clase visual cambiando el fondo y emitiendo el identificador de la fila en consola.
💡 Pistas Clave y Procedimiento Guiado

🔍 Desplegar Solución Embebida y Explicación Técnica Clic para Ver/Ocultar
Explicación Técnica: El método closest() desacopla por completo la lógica JavaScript de la estructura interna del HTML, permitiendo modificar el marcado interno sin romper los controladores de eventos.
💻 Código de la Solución Comentada:
function resaltarFilaContextual(elementoClicado) {
    // 1. Localizar la fila <tr> ascendiendo en el árbol DOM
    const fila = elementoClicado.closest("tr");
    
    if (!fila) {
        console.warn("El clic no ocurrió dentro de ninguna fila de tabla.");
        return null;
    }

    // 2. Verificar el estado actual con matches()
    const yaSeleccionada = fila.matches(".fila-activa");

    if (yaSeleccionada) {
        fila.classList.remove("fila-activa");
        fila.style.backgroundColor = "";
        console.log(\`Fila deseleccionada: ID \${fila.dataset.id || 'S/N'}\`);
    } else {
        fila.classList.add("fila-activa");
        fila.style.backgroundColor = "#e0e7ff";
        console.log(\`Fila seleccionada: ID \${fila.dataset.id || 'S/N'}\`);
    }

    return fila;
}

3. Creación, Inserción, Modificación y Eliminación de Nodos en el Documento

💡 Fundamentos Conceptuales

La alteración de la estructura del documento en tiempo de ejecución debe conciliar seguridad contra inyecciones de código y optimización de rendimiento:

  • Creación de Nodos en Memoria:
    • document.createElement("tag"): Crea un nuevo nodo de tipo elemento HTML en memoria desconectado del árbol.
    • document.createTextNode("texto"): Crea un nodo de texto puro.
    • nodo.cloneNode(deep): Clona un nodo existente. Si deep es true, copia recursivamente todos sus descendientes e hijos.
  • Manipulación de Contenido Textual y HTML:
    • nodo.textContent: ✅ 100% Inmune a XSS. Asigna o lee texto plano escapando cualquier etiqueta HTML automáticamente.
    • nodo.innerHTML: Parsea una cadena como código HTML. ⚠️ Riesgo grave de XSS si la cadena proviene de datos no confiables de usuarios. Además, destruye y recrea todos los listeners previos de sus hijos.
  • Métodos de Inserción en el Árbol DOM:
    • Clásicos: padre.appendChild(nuevoHijo) (añade al final) y padre.insertBefore(nuevo, referencia).
    • Modernos (W3C DOM Living Standard): padre.append(...nodosOCadenas) (permite múltiples argumentos y texto directo), padre.prepend() (inserta al principio), elemento.before() (hermano anterior) y elemento.after() (hermano posterior).
    • elemento.insertAdjacentHTML(posicion, html): Inyecta plantillas HTML sin destruir los nodos existentes. Admite 4 posiciones exactas: 'beforebegin', 'afterbegin', 'beforeend', 'afterend'.
  • Eliminación de Nodos: Método moderno y conciso elemento.remove(), o método clásico padre.removeChild(hijo). Sustitución con padre.replaceChild(nuevo, viejo).
  • Optimización de Rendimiento con DocumentFragment: Contenedor ligero en memoria (document.createDocumentFragment()). Permite acumular cientos de nodos y anexarlos al DOM real en una única operación atómica, produciendo un único Reflow del navegador.
🔍 Ampliación y Estándares 2026

Rendimiento Crítico: innerHTML vs createElement vs DocumentFragment:

  • El Error de Acumular con innerHTML (innerHTML += ...): Cada vez que se ejecuta contenedor.innerHTML += html dentro de un bucle, el navegador serializa todo el contenido previo a cadena, destruye todos los elementos DOM hijos, invalida los listeners registrados y vuelve a parsear el HTML entero. Se debe construir la estructura completa con DocumentFragment antes de tocar el DOM.
  • Plantillas Nativas con <template>: Elemento HTML cuyo contenido no se renderiza al cargar. Mediante template.content.cloneNode(true) se generan clones instantáneos listos para rellenar con datos.
💻 Demostración Práctica e Implementación de Código 
// Inserción Atómica de Alto Rendimiento con DocumentFragment
function renderizarListadoProductos(productos, contenedorPadre) {
    // Crear fragmento en memoria para evitar múltiples reflows
    const fragmento = document.createDocumentFragment();

    productos.forEach(prod => {
        const tarjeta = document.createElement("article");
        tarjeta.className = "producto-card";
        tarjeta.dataset.id = prod.id;

        // Inyección segura de texto con textContent
        const titulo = document.createElement("h3");
        titulo.textContent = prod.nombre; // Seguro contra XSS

        const precio = document.createElement("p");
        precio.className = "precio-etiqueta";
        precio.textContent = `${prod.precio.toFixed(2)} €`;

        tarjeta.append(titulo, precio);
        fragmento.appendChild(tarjeta);
    });

    // Inserción única en el árbol visible: un solo Reflow
    contenedorPadre.appendChild(fragmento);
    console.log(`Renderizados ${productos.length} productos en una sola operación atómica.`);
}

Cada elemento de la lista debe incluir un botón de eliminación. 🔍 Desplegar Solución Embebida y Explicación Técnica Clic para Ver/Ocultar
Explicación Técnica: La combinación de DocumentFragment para inserción masiva y el evento transitionend para borrado coordinado proporciona una experiencia fluida y libre de saltos visuales.

function generarListaTareas(tareas, contenedor) {
    // Vaciar contenedor de forma eficiente
    contenedor.replaceChildren();

    const fragmento = document.createDocumentFragment();

    tareas.forEach((textoTarea, indice) => {
        const li = document.createElement("li");
        li.className = "item-tarea-dinamica";
        li.style.cssText = "display: flex; justify-content: space-between; padding: 8px; margin-bottom: 6px; background: #f8fafc; border-radius: 6px; transition: opacity 0.3s, transform 0.3s;";

        const spanTexto = document.createElement("span");
        spanTexto.textContent = \`\${indice + 1}. \${textoTarea}\`; // Seguro contra XSS

        const btnBorrar = document.createElement("button");
        btnBorrar.textContent = "🗑️ Borrar";
        btnBorrar.style.cssText = "background: #ef4444; color: white; border: none; padding: 4px 8px; border-radius: 4px; cursor: pointer;";

        // Borrado coordinado con animación
        btnBorrar.onclick = () => {
            li.style.opacity = "0";
            li.style.transform = "translateX(20px)";
            li.addEventListener("transitionend", () => {
                li.remove();
                console.log("Nodo eliminado del DOM tras finalizar transición CSS.");
            }, { once: true });
        };

        li.append(spanTexto, btnBorrar);
        fragmento.appendChild(li);
    });

    // Inserción única en el DOM
    contenedor.appendChild(fragmento);
}

4. Manipulación de Atributos, Propiedades y Atributos de Datos (dataset)

💡 Fundamentos Conceptuales

En el DOM existe una diferencia sustancial entre los atributos HTML del marcado inicial y las propiedades vivas del objeto JavaScript en memoria:

  • Atributos HTML vs Propiedades del Objeto DOM:
    • Atributo HTML: Lo que está escrito textualmente en la etiqueta del documento (ej. <input value="inicio">). Se manipula con getAttribute() y setAttribute().
    • Propiedad DOM: La propiedad viva en memoria dentro del objeto JavaScript (ej. input.value). Si el usuario escribe en el campo, input.value cambia a lo escrito, pero input.getAttribute("value") sigue reflejando el valor inicial estático del HTML.
  • Métodos de Gestión de Atributos:
    • elemento.getAttribute("nombre"): Devuelve el valor textual del atributo o null.
    • elemento.setAttribute("nombre", "valor"): Asigna o modifica el atributo.
    • elemento.hasAttribute("nombre"): Booleano de comprobación.
    • elemento.removeAttribute("nombre"): Elimina el atributo.
    • Atributos Booleanos (disabled, checked, hidden): Su presencia en el HTML implica valor verdadero, independientemente de su contenido textual.
  • Atributos Personalizados de Datos (HTML5 data-* y dataset):

    Estándar formal para asociar metadatos personalizados a elementos del DOM sin inventar atributos no estándar:

    • En HTML: Se escriben con prefijo data- y palabras en minúsculas separadas por guiones (ej. data-usuario-id="105", data-precio-descuento="19.99").
    • En JavaScript: Se accede mediante la propiedad elemento.dataset convertida automáticamente a notación camelCase (ej. elemento.dataset.usuarioId, elemento.dataset.precioDescuento).
    • Soporta lectura, asignación y eliminación (delete elemento.dataset.miClave).
🔍 Ampliación y Estándares 2026

Sincronización Bidireccional y Selectores CSS por dataset:

  • Los Atributos data-* son Selectores CSS Válidos: Se puede aplicar estilo en CSS según metadatos: article[data-estado="agotado"] { opacity: 0.5; }.
  • Serialización Automática: Los valores en dataset se almacenan siempre como cadenas de texto (Strings). Si se almacena un número o booleano, se debe convertir explícitamente al recuperarlo (Number(el.dataset.precio)).
💻 Demostración Práctica e Implementación de Código 
// Manipulación de atributos estándar y metadatos con dataset
const tarjetaUsuario = document.getElementById("tarjeta-cliente");

// 1. Lectura y modificación de atributos HTML nativos
tarjetaUsuario.setAttribute("role", "region");
tarjetaUsuario.setAttribute("aria-label", "Ficha de cliente");

// 2. Uso de dataset para metadatos de negocio
console.log("ID del cliente (data-cliente-id):", tarjetaUsuario.dataset.clienteId);
console.log("Rol del cliente (data-rol):", tarjetaUsuario.dataset.rol);

// Modificación dinámica de dataset (actualiza automáticamente el HTML a data-estado-cuenta)
tarjetaUsuario.dataset.estadoCuenta = "activa-verificada";

// Filtrado de elementos por metadatos
const elementosVerificados = document.querySelectorAll("[data-estado-cuenta='activa-verificada']");
console.log("Elementos verificados en el documento:", elementosVerificados.length);

🎯 Reto 4: Catálogo Interactivo con Metadatos data-* y Filtrado Reactivo por Atributos

📝 Enunciado y Especificación del Reto
Construye un módulo para filtrar un catálogo de cursos. Cada tarjeta de curso posee atributos `data-categoria` (ej. "frontend", "backend", "seguridad") y `data-nivel` ("iniciacion", "avanzado"). Crea una función `filtrarCatalogo(categoria, nivelMinimo)` que recorra todos los artículos del catálogo con `querySelectorAll()`, lea los metadatos con `elemento.dataset`, oculte con `elemento.hidden = true` aquellos que no coincidan y muestre con `elemento.hidden = false` los que satisfagan los criterios.
💡 Pistas Clave y Procedimiento Guiado
Lee articulo.dataset.categoria y articulo.dataset.nivel. Compara los valores y actualiza la propiedad booleana articulo.hidden.
🔍 Desplegar Solución Embebida y Explicación Técnica Clic para Ver/Ocultar
Explicación Técnica: El uso de dataset combinado con la propiedad nativa hidden permite crear sistemas de filtrado de contenido instantáneos y declarativos sin tocar clases complejas.
💻 Código de la Solución Comentada:
function filtrarCatalogoCursos(categoriaFiltro, nivelFiltro) {
    const articulos = document.querySelectorAll("article.tarjeta-curso");
    let visibles = 0;

    articulos.forEach(art => {
        // Extracción de metadatos desde dataset
        const categoria = art.dataset.categoria;
        const nivel = art.dataset.nivel;

        const coincideCategoria = !categoriaFiltro || categoriaFiltro === "todas" || categoria === categoriaFiltro;
        const coincideNivel = !nivelFiltro || nivelFiltro === "todos" || nivel === nivelFiltro;

        if (coincideCategoria && coincideNivel) {
            art.hidden = false;
            visibles++;
        } else {
            art.hidden = true;
        }
    });

    console.log(\`Filtrado completado: \${visibles}/\${articulos.length} cursos visibles.\`);
    return visibles;
}

5. Programación de Eventos Asociados al DOM y Observación de Mutaciones (MutationObserver)

💡 Fundamentos Conceptuales

La sincronización entre el estado de carga del documento y la reacción ante cambios estructurales en el DOM se coordina mediante eventos de ciclo de vida y observadores reactivos:

  • Eventos de Ciclo de Vida del Documento:
    • DOMContentLoaded: Se emite en document cuando el HTML ha sido parseado por completo y el árbol DOM está listo en memoria. Es el momento idóneo para inicializar la lógica JavaScript sin esperar a imágenes ni hojas de estilo pesadas.
    • window.onload: Se emite en window cuando la página completa, incluyendo imágenes, fuentes externas, iframes y hojas de estilo CSS han finalizado su descarga.
    • readystatechange: Se dispara en document al cambiar document.readyState ("loading", "interactive", "complete").
  • La API MutationObserver (Vigilancia Reactiva del DOM):

    API nativa de alto rendimiento diseñada para reemplazar los antiguos y obsoletos Mutation Events. Permite reaccionar a cambios en el árbol DOM de forma asíncrona sin sobrecargar el hilo principal:

    • Instanciación: const observer = new MutationObserver(callback);
    • El Callback de Mutaciones: Recibe una lista de objetos MutationRecord con detalles sobre: tipo de cambio (childList, attributes, characterData), nodos añadidos (addedNodes), nodos eliminados (removedNodes) y nombre del atributo alterado.
    • Configuración y Activación con observe(): 
      observer.observe(nodoObjetivo, {
    childList: true,      // Observar adición/borrado de hijos directos
    subtree: true,        // Observar en todos los descendientes anidados
    attributes: true,     // Observar mutación de atributos
    attributeOldValue: true // Registrar valor previo del atributo
});
    • Desconexión con observer.disconnect(): Detiene la monitorización liberando recursos.
🔍 Ampliación y Estándares 2026

Casos de Uso Críticos para MutationObserver:

  • Integración con Librerías Externas y Web Components: Permite detectar cuándo un framework o plugin de terceros inyecta contenido en el DOM para aplicarle automáticamente estilos, inicializar tooltips o registrar interactividad sin recurrir a ineficientes bucles de sondeo setInterval().
  • Agrupación de Notificaciones: MutationObserver no dispara el callback de forma síncrona por cada nodo insertado; agrupa todos los cambios de un ciclo en un único lote procesado como microtarea, garantizando un rendimiento óptimo.
💻 Demostración Práctica e Implementación de Código 
// Monitorización de Cambios Estructurales en el DOM con MutationObserver
const contenedorMonitorizado = document.getElementById("zona-dinamica");

const vigilanteDOM = new MutationObserver((mutaciones, observador) => {
    mutaciones.forEach(mutacion => {
        if (mutacion.type === "childList") {
            console.log("Nodos añadidos:", mutacion.addedNodes.length);
            console.log("Nodos eliminados:", mutacion.removedNodes.length);
        } else if (mutacion.type === "attributes") {
            console.log(`Atributo alterado: '${mutacion.attributeName}'. Valor previo: '${mutacion.oldValue}'`);
        }
    });
});

// Iniciar vigilancia profunda en el contenedor
vigilanteDOM.observe(contenedorMonitorizado, {
    childList: true,
    subtree: true,
    attributes: true,
    attributeOldValue: true
});

🎯 Reto 5: Monitor de Mutaciones del DOM en Tiempo Real con MutationObserver

📝 Enunciado y Especificación del Reto
Implementa un sistema de auditoría del DOM que vigile un contenedor `#panel-notificaciones`. Mediante `MutationObserver`, detecta cuando se añada un nuevo nodo hijo de tipo elemento y comprueba si posee la clase `"notificacion-urgente"`. En caso afirmativo, emite un aviso sonoro o alerta en consola, imprime el contenido del texto insertado y registra la marca de tiempo exacta del cambio.
💡 Pistas Clave y Procedimiento Guiado
En el callback de MutationObserver, itera sobre mutacion.addedNodes. Comprueba nodo.nodeType === Node.ELEMENT_NODE y nodo.classList.contains("notificacion-urgente").
🔍 Desplegar Solución Embebida y Explicación Técnica Clic para Ver/Ocultar
Explicación Técnica: MutationObserver proporciona un mecanismo desacoplado para interceptar y validar cambios en la estructura del documento en tiempo real sin interferir en el código que produce la inserción.
💻 Código de la Solución Comentada:
function auditarNotificaciones(contenedor) {
    const observer = new MutationObserver((mutaciones) => {
        for (const mutacion of mutaciones) {
            if (mutacion.type === "childList") {
                mutacion.addedNodes.forEach(nodo => {
                    // Filtrar sólo nodos de elemento
                    if (nodo.nodeType === Node.ELEMENT_NODE) {
                        const esUrgente = nodo.classList.contains("notificacion-urgente");
                        const mensaje = nodo.textContent.trim();
                        const hora = new Date().toLocaleTimeString();

                        if (esUrgente) {
                            console.warn(\`🚨 [\${hora}] ALERTA URGENTE DETECTADA EN DOM: "\${mensaje}"\`);
                        } else {
                            console.log(\`ℹ️ [\${hora}] Notificación estándar añadida: "\${mensaje}"\`);
                        }
                    }
                });
            }
        }
    });

    observer.observe(contenedor, { childList: true, subtree: false });
    console.log("Vigilante MutationObserver activo en:", contenedor.id);

    return observer;
}

6. Diferencias entre Navegadores y Separación de Contenido, Estilo y Comportamiento

💡 Fundamentos Conceptuales

La arquitectura profesional de software en cliente exige neutralizar divergencias entre navegadores y aplicar rigurosamente la separación de las tres capas de la web:

  • Diferencias de Implementación entre Navegadores:
    • Evolución de Motores: En el pasado existían fuertes discrepancias entre Internet Explorer (modelo de eventos attachEvent, event.srcElement) y los estándares W3C. Hoy en día, la convergencia hacia motores basados en Chromium (Blink), Firefox (Gecko) y Safari (WebKit) ha estandarizado casi todo el DOM Living Standard.
    • Herramientas de Compatibilidad: Consulta obligatoria en Can I Use (caniuse.com) y MDN Web Docs para auditar el soporte de APIs recientes.
    • Polyfills: Scripts de relleno (como los proporcionados por Polyfill.io o core-js) que emulan APIs nativas modernas en navegadores que aún no las han implementado.
  • El Principio Arquitectónico de las Tres Capas Desacopladas:
    • 1. Capa de Contenido y Estructura (HTML5 Semántico): Define el significado, la jerarquía y los datos del documento mediante etiquetas semánticas accesibles (<header>, <nav>, <main>, <article>, <section>, <footer>). Libre de estilos visuales y de código JavaScript.
    • 2. Capa de Presentación y Diseño (CSS3): Define la estética, distribución espacial (Grid, Flexbox), tipografías, colores y temas mediante hojas de estilo externas y variables CSS.
    • 3. Capa de Comportamiento e Interacción (JavaScript): Lógica dinámica, validaciones y peticiones asíncronas alojadas exclusivamente en archivos .js externos vinculados sin atributos en línea (Unobtrusive JavaScript).
  • Reglas de Oro del Código Limpio:
    • Prohibido el uso de estilos en línea mediante style="..." en el marcado HTML.
    • Prohibido el uso de manejadores de eventos en línea en atributos HTML (como onclick="...").
🔍 Ampliación y Estándares 2026

Accesibilidad Universal (WAI-ARIA) y Mejora Progresiva:

  • Mejora Progresiva (Progressive Enhancement): La página web debe ser plenamente legible, navegable y estructurada incluso si el navegador tiene JavaScript desactivado o una conexión de red inestable que impida cargar los scripts.
  • Atributos ARIA (Accessible Rich Internet Applications): Uso de aria-expanded, aria-hidden, aria-live y roles semánticos para comunicar cambios dinámicos del DOM a lectores de pantalla para usuarios con discapacidad visual.
💻 Demostración Práctica e Implementación de Código

            console.log("Comportamiento desacoplado ejecutado limpiamente.");
