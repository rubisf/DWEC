1. Objetos Nativos del Lenguaje: String, Number, Math y Date

💡 Fundamentos Conceptuales

JavaScript proporciona un conjunto de objetos nativos globales con métodos estáticos y de instancia para operar con cadenas, números, matemáticas y marcas temporales:

  • Objeto String (Inmutable): Métodos de búsqueda (includes, indexOf, startsWith, endsWith), manipulación de subcadenas (slice, substring), reemplazo con literales o expresiones regulares (replace, replaceAll), normalización (trim, toLowerCase, toUpperCase), división en arrays (split) y plantillas literales (Template Literals con interpolación ${...}).
  • Objeto Number: Métodos estáticos de validación numérica: Number.isInteger(), Number.isFinite() y Number.isNaN(). Formateo de precisión y decimales con toFixed(decimales). Constantes fundamentales: Number.MAX_SAFE_INTEGER (253 - 1) y Number.EPSILON.
  • Objeto Math (Funciones Matemáticas Estáticas): Redondeos: Math.round() (al entero más próximo), Math.floor() (hacia abajo), Math.ceil() (hacia arriba) y Math.trunc() (elimina decimales). Aritmética avanzada: Math.abs(), Math.sqrt(), Math.pow() (o **), Math.min(), Math.max() y generación pseudoaleatoria con Math.random().
  • Objeto Date (Gestión Temporal): Representa momentos temporales en milisegundos desde el Epoch (1 de enero de 1970 UTC). Métodos get/set para año, mes (0-11), día del mes, horas y milisegundos. Obtención de timestamp actual de alta velocidad con Date.now(). Internacionalización avanzada de fechas y monedas con la API nativa Intl.DateTimeFormat y Intl.NumberFormat.
🔍 Ampliación y Estándares 2026

Internacionalización Moderna con la API Intl:

  • Formateo Localizado: Evitar la concatenación manual de cadenas para fechas o divisas. Usar new Intl.DateTimeFormat('es-ES', { dateStyle: 'full', timeStyle: 'short' }).format(fecha) para garantizar localización automática respetando el huso horario y las normas culturales del usuario.
  • Inmutabilidad de Cadenas y Garbage Collection: Como las cadenas son inmutables, operaciones continuas de concatenación en bucles largos generan múltiples copias en memoria. Es más eficiente acumular fragmentos en un array y aplicar .join('').

🎯 Reto 1: Generador de Tokens Temporales y Calculadora de Diferencia de Fechas

Debe devolver un objeto indicando los días transcurridos completos, los meses aproximados y una cadena formateada en español mediante `Intl.DateTimeFormat`. 💡 Pistas Clave y Procedimiento Guiado

🔍 Desplegar Solución Embebida y Explicación Técnica Clic para Ver/Ocultar
Explicación Técnica: La gestión de diferencias temporales mediante marcas de tiempo en milisegundos asegura cálculos exactos sin depender de ambigüedades en nombres de meses o zonas horarias.
💻 Código de la Solución Comentada:
function calcularAntiguedad(fechaISO) {
    const fechaEntrada = new Date(fechaISO);
    const ahora = Date.now();
    const diferenciaMs = ahora - fechaEntrada.getTime();

    if (Number.isNaN(diferenciaMs) || diferenciaMs < 0) {
        throw new Error("La fecha proporcionada es inválida o posterior a la actual.");
    }

    const unDiaMs = 1000 * 60 * 60 * 24;
    const diasTranscurridos = Math.floor(diferenciaMs / unDiaMs);
    const mesesAproximados = Math.floor(diasTranscurridos / 30.44);

    // Formateo con API Intl nativa
    const fechaFormateada = new Intl.DateTimeFormat('es-ES', {
        dateStyle: 'full',
        timeStyle: 'medium'
    }).format(fechaEntrada);

    // Generador de Token con Math y String (base 36)
    const token = "AUDIT-" + Math.random().toString(36).substring(2, 8).toUpperCase() + "-" + Date.now().toString(36).toUpperCase();

    return {
        tokenConsulta: token,
        fechaOriginal: fechaFormateada,
        diasTranscurridos,
        mesesAproximados
    };
}

2. Jerarquía del Browser Object Model (BOM): window, navigator, history y location

💡 Fundamentos Conceptuales

El Browser Object Model (BOM) expone las APIs del navegador organizadas en una jerarquía encabezada por el objeto supremo window:

  • Objeto window (Entorno Global): Representa la ventana o pestaña activa del navegador. Cualquier variable o función declarada en el ámbito global (con var) se convierte en propiedad de window. Proporciona dimensiones de pantalla útil (innerWidth, innerHeight) y posición de scroll (scrollX, scrollY).
  • Objeto navigator (Información del Cliente): Permite inspeccionar el estado del navegador y del hardware: navigator.userAgent (identificación), navigator.language (idioma preferido), navigator.onLine (estado de conexión de red booleano) y acceso a portapapeles con navigator.clipboard.
  • Objeto location (Dirección y Navegación URL): Expone los componentes de la URL activa (href, origin, protocol, host, pathname, search, hash). Métodos de navegación: location.assign(url) (navega guardando en historial), location.replace(url) (reemplaza la página actual sin guardar historial) y location.reload() (recarga).
  • Objeto history (Historial de Navegación de Sesión): Métodos tradicionales: history.back(), history.forward() y history.go(delta). Métodos de la HTML5 History API para Single Page Applications (SPA): history.pushState(estado, titulo, url) y history.replaceState(), coordinados con el evento popstate para cambiar la URL sin recargar la página.
🔍 Ampliación y Estándares 2026

Enrutamiento en Cliente con History API (pushState):

  • Base de los Enrutadores SPA (React Router, Vue Router, Angular): Al hacer clic en un enlace de navegación, se intercepta con e.preventDefault() y se invoca history.pushState({ vista: 'contacto' }, '', '/contacto'). La URL cambia instantáneamente en la barra de navegación del navegador sin provocar una petición de recarga al servidor web.
  • Detección de Estado de Red Reactivo: Escuchando los eventos window.addEventListener('online', ...) y window.addEventListener('offline', ...), las aplicaciones web pueden alertar al usuario en tiempo real cuando pierde la conexión a Internet.
💻 Demostración Práctica e Implementación de Código

function inicializarEnrutador() {

        console.log("Renderizando vista en DOM:", vista);
        // En una página real: document.getElementById('app').innerHTML = contenido;

        window.history.pushState({ seccion }, "", "#" + seccion);

3. Gestión de la Apariencia de la Ventana y Creación de Nuevas Ventanas

💡 Fundamentos Conceptuales

El objeto window proporciona métodos para interactuar con ventanas secundarias, pestañas y la geometría física del área de visualización:

  • Creación de Nuevas Ventanas con window.open():

    Sintaxis: const ventanaHija = window.open(url, target, specs);

    • url: Dirección web del recurso a cargar (o cadena vacía para ventana en blanco).
    • target: Nombre de la ventana, o palabras reservadas (_blank para nueva pestaña/ventana, _self para actual).
    • specs: Cadena de características separadas por comas que condicionan la apariencia: width=600, height=400, left=100, top=100, resizable=yes, scrollbars=yes.
  • Cierre y Verificación: El método ventana.close() cierra la ventana referenciada. La propiedad booleana ventana.closed permite verificar si el usuario o un script ya han cerrado la ventana secundaria.
  • Gestión de Tamaño y Posición (Restringido por seguridad):
    • Redimensionamiento: window.resizeTo(ancho, alto) y window.resizeBy(deltaX, deltaY).
    • Movimiento: window.moveTo(x, y) y window.moveBy(deltaX, deltaY).
    • Foco: window.focus() (trae al frente) y window.blur().
  • Políticas Anti-Popup de Navegadores Modernos: Los navegadores bloquean por defecto cualquier invocación a window.open() que no se desencadene como resultado directo de una acción explícita del usuario (como un evento click).
🔍 Ampliación y Estándares 2026

Seguridad y Aislamiento en Creación de Ventanas:

  • Vulnerabilidad Tabnabbing y noopener / noreferrer: Al abrir enlaces a sitios de terceros con target="_blank", la página de destino tiene acceso a window.opener y podría redirigir maliciosamente la página de origen a un sitio de phishing. Para mitigarlo, los navegadores modernos aplican automáticamente rel="noopener".
  • Restricciones de Manipulación: Los navegadores prohíben mover o redimensionar pestañas que no hayan sido abiertas programáticamente mediante window.open() con dimensiones personalizadas explícitas.
💻 Demostración Práctica e Implementación de Código 
// Creación y control seguro de una ventana emergente auxiliar

        <html>

        </body>
        </html>
    `);
}

🎯 Reto 3: Controlador de Ventanas Auxiliares con Posicionamiento Dinámico y Protección Anti-Bloqueo

🔍 Desplegar Solución Embebida y Explicación Técnica Clic para Ver/Ocultar
Explicación Técnica: El cálculo matemático de coordenadas relativas a screen permite ofrecer una experiencia de usuario ergonómica, respetando al mismo tiempo los filtros de seguridad contra ventanas emergentes no deseadas.
💻 Código de la Solución Comentada:
class GestorVentanaEmergente {
    constructor(ancho = 600, alto = 450) {
        this.ancho = ancho;
        this.alto = alto;
        this.referencia = null;
    }

    abrirCentrada(url = "") {
        // Cálculo de posición centrada en el monitor del usuario
        const left = Math.max(0, Math.floor((window.screen.width - this.ancho) / 2));
        const top = Math.max(0, Math.floor((window.screen.height - this.alto) / 2));
        const specs = \`width=\${this.ancho},height=\${this.alto},left=\${left},top=\${top},resizable=yes,scrollbars=yes\`;

        this.referencia = window.open(url, "VentanaCentrada", specs);

        if (!this.referencia) {
            console.error("❌ Ventana bloqueada. Por favor, habilite los popups en la barra de direcciones.");
            return false;
        }

        console.log("✅ Ventana abierta con éxito en posición:", { left, top });
        return true;
    }

    cerrar() {
        if (this.referencia && !this.referencia.closed) {
            this.referencia.close();
            console.log("Ventana auxiliar cerrada programáticamente.");
            this.referencia = null;
        } else {
            console.warn("La ventana ya estaba cerrada o nunca fue abierta.");
        }
    }
}

4. Comunicación Entre Ventanas (Métodos y Propiedades de window)

💡 Fundamentos Conceptuales

Cuando una aplicación web abre ventanas secundarias o integra marcos anidados (iframes), surgen mecanismos de comunicación bidireccional coordinados:

  • Referencias de Parentesco entre Ventanas:
    • Ventana Principal hacia Ventana Hija: La llamada const popup = window.open(...) devuelve una referencia al objeto window de la ventana secundaria, permitiendo invocar funciones públicas o acceder a su DOM si comparten el mismo origen.
    • Ventana Hija hacia Ventana Principal: La ventana secundaria puede acceder a su creadora mediante la propiedad window.opener.
    • Jerarquía de Iframes: Dentro de un iframe, window.parent referencia al marco inmediatamente superior, y window.top referencia a la ventana raíz de la jerarquía.
  • Restricción del Mismo Origen (Same-Origin Policy en Ventanas): Si la ventana principal y la ventana secundaria pertenecen a dominios, protocolos o puertos distintos, el navegador bloquea el acceso directo a sus variables o DOM por seguridad (arrojando SecurityError).
  • Mensajería Segura con window.postMessage(): Es el estándar oficial W3C para comunicación segura entre ventanas de distintos orígenes (Cross-Origin):
    • Envío: destinoVentana.postMessage(datos, targetOrigin); donde targetOrigin especifica qué dominio tiene permiso para recibirlo (ej. "https://mi-dominio.com") para evitar interceptación.
    • Recepción: Se escucha el evento window.addEventListener('message', (event) => { ... }), comprobando siempre de forma estricta if (event.origin !== "https://origen-esperado.com") return;.
🔍 Ampliación y Estándares 2026

Seguridad Crítica en el Uso de postMessage:

  • Nunca usar el comodín "*" en entornos de producción: Usar postMessage(datos, "*") expone la información enviada a cualquier iframe o ventana maliciosa que pueda residir en la página. Se debe indicar siempre el origen explícito.
  • Validación Obligatoria de event.origin: Un receptor que procese mensajes sin validar el origen remitente es vulnerable a ataques de inyección de comandos o suplantación de identidad.
💻 Demostración Práctica e Implementación de Código 
// Comunicación Bidireccional Segura con postMessage

// 1. En la Ventana Principal (Emisora)
function enviarDatosAPopup(ventanaPopup, pedido) {
    const origenPermitido = "https://tienda.com";
    // Envío seguro tipado
    ventanaPopup.postMessage({ tipo: "NUEVO_PEDIDO", payload: pedido }, origenPermitido);
}

// 2. En la Ventana Popup o Iframe (Receptora)
window.addEventListener('message', (evento) => {
    // Comprobación estricta de origen
    if (evento.origin !== "https://tienda.com") {
        console.warn("Mensaje descartado: Origen no autorizado:", evento.origin);
        return;
    }

    console.log("Mensaje seguro recibido:", evento.data);

    // Respuesta a la ventana que envió el mensaje
    if (evento.source) {
        evento.source.postMessage({ estado: "CONFIRMADO", id: evento.data.payload.id }, evento.origin);
    }
});

// === PROTOCOLO DE MENSAJERÍA SEGURA CLIENTE ===

// CÓDIGO DEL RECEPTOR (Popup o Iframe)
function configurarReceptorSeguro() {
    window.addEventListener('message', (evento) => {
        // 1. Verificación obligatoria de origen de procedencia
        if (evento.origin !== window.location.origin) {
            console.error("Acceso denegado: Procedencia no confiable ->", evento.origin);
            return;
        }

        const mensaje = evento.data;
        console.log("📨 Mensaje recibido de origen legítimo:", mensaje);

        // 2. Procesar acción requerida
        if (mensaje?.accion === "AUTENTICAR") {
            console.log("Procesando token de sesión:", mensaje.token);

            // 3. Responder al remitente a través de event.source
            if (evento.source) {
                evento.source.postMessage({
                    estado: "SESION_ESTABLECIDA",
                    tiempo: Date.now()
                }, evento.origin);
            }
        }
    });
}

// CÓDIGO DEL EMISOR (Ventana Principal)
function emitirAutenticacion(ventanaDestino) {
    if (!ventanaDestino || ventanaDestino.closed) {
        console.warn("Imposible enviar mensaje: Ventana destino cerrada.");
        return;
    }

    const payload = {
        accion: "AUTENTICAR",
        token: "JWT_SECURE_TOKEN_XYZ_123"
    };

    // Envío especificando origen exacto (sin comodín '*')
    ventanaDestino.postMessage(payload, window.location.origin);
    console.log("📤 Mensaje de autenticación despachado.");

5. Interacción con el Usuario (alert, prompt, confirm y Formularios)

💡 Fundamentos Conceptuales

La interacción con el usuario en el cliente abarca desde cuadros de diálogo modales nativos hasta la captura estructurada de controles de formulario:

  • Diálogos Modales Nativos del Navegador (BOM):
    • window.alert(mensaje): Muestra un cuadro de diálogo informativo modal con botón de aceptar. Detiene la ejecución del hilo principal de JavaScript hasta que el usuario lo cierra.
    • window.confirm(pregunta): Diálogo de confirmación con botones Aceptar y Cancelar. Devuelve un booleano síncrono (true si pulsa Aceptar, false si cancela o cierra).
    • window.prompt(texto, valorPorDefecto): Solicita una entrada textual. Devuelve la cadena ingresada por el usuario o null si presiona Cancelar.
  • Inconvenientes y Bloqueo de UI: Los diálogos clásicos (alert, confirm, prompt) son bloqueantes y síncronos. Congelan el renderizado, detienen animaciones CSS y degradan la experiencia de usuario. En aplicaciones modernas se sustituyen por modales declarativos HTML5 (<dialog>) o componentes personalizados.
  • El Elemento HTML5 <dialog>: Alternativa moderna no bloqueante estandarizada:
    • Método dialog.showModal(): Abre el diálogo modal generando automáticamente un backdrop atenuado y bloqueando la interacción con el fondo sin congelar el hilo de JS.
    • Método dialog.close(valorRetorno): Cierra el diálogo y propaga el evento 'close', recuperando la respuesta en dialog.returnValue.
  • Interacción Básica con Controles de Formulario: Acceso a formularios mediante la colección document.forms o document.querySelector. Lectura y asignación de valores de campos de texto (input.value), casillas de verificación (checkbox.checked) y desplegables (select.value).
🔍 Ampliación y Estándares 2026

Accesibilidad y Foco en Modales Modernos:

  • Focus Trap (Atrapamiento del Foco): El elemento <dialog> nativo gestiona automáticamente el atrapamiento del foco del teclado (accesibilidad WCAG) e intercepta la tecla Escape para cerrar el diálogo limpiamente sin código adicional.
  • Validación Preliminar en Tiempo de Captura: Antes de enviar formularios, los escuchadores de evento input y change permiten validar los datos introducidos en tiempo real antes de recurrir a diálogos de confirmación.
💻 Demostración Práctica e Implementación de Código

        console.log("Registro eliminado mediante confirm clásico.");

        dialog.addEventListener('close', () => {
            console.log("Diálogo cerrado. Respuesta del usuario:", dialog.returnValue);
        }, { once: true });
    }
}

6. Almacenamiento Local y de Sesión (Storage, Cookies) y Manipulación DOM

💡 Fundamentos Conceptuales

La persistencia en cliente y la manipulación dinámica del contenido son pilares fundamentales para crear aplicaciones web reactivas y personalizadas:

  • Cookies del Navegador (document.cookie):

    Pares clave-valor enviados automáticamente al servidor en cada cabecera HTTP. Limitadas a 4 KB. Directivas de seguridad: expires / max-age (caducidad), path (ámbito), domain, Secure (sólo HTTPS), SameSite=Strict/Lax (protección anti-CSRF) y HttpOnly (inmune a lectura por JavaScript).

  • Web Storage API (Almacenamiento Local vs Sesión):
    • localStorage: Persistencia permanente en el navegador aislada por origen (protocolo + dominio + puerto). Límite de ~5 MB. Los datos sobreviven al cierre del navegador.
    • sessionStorage: Persistencia vinculada a la pestaña de navegación actual. Se destruye automáticamente al cerrar la pestaña o ventana.
    • Métodos estándar: setItem(clave, valor), getItem(clave), removeItem(clave), clear(), length y key(indice).
    • Serialización obligatoria de objetos con JSON.stringify() y recuperación con JSON.parse().
    • Evento window.addEventListener('storage', ...): Se dispara en todas las demás pestañas abiertas del mismo origen cuando una pestaña altera el localStorage.
  • Manipulación Dinámica del DOM y Depuración: Generación segura de elementos HTML en memoria mediante document.createElement(), asignación de atributos y clases con classList, inserción con appendChild() o append(), y uso de console.dir() para inspeccionar las propiedades del objeto DOM en consola.
🔍 Ampliación y Estándares 2026

Seguridad y Rendimiento en Almacenamiento Cliente:

  • Jamás almacenar secretos en Web Storage: La Web Storage API (localStorage/sessionStorage) es totalmente accesible por cualquier script JavaScript que se ejecute en la página. Almacenar tokens JWT o contraseñas en localStorage expone la aplicación a robo de sesión en caso de vulnerabilidades XSS. Las credenciales sensibles deben almacenarse en cookies con bandera HttpOnly; Secure; SameSite=Strict.
  • Manejo del Límite de Cuota (QuotaExceededError): Si el almacenamiento local se satura, setItem() arroja una excepción QuotaExceededError que debe capturarse con bloques try/catch.
💻 Demostración Práctica e Implementación de Código 
// Gestor de Web Storage con Serialización JSON y sincronización
const GestorPreferencias = {
    guardar(clave, valor) {
        try {
            const serializado = JSON.stringify(valor);
            localStorage.setItem(clave, serializado);
            console.log(`Dato guardado en localStorage [${clave}]`);
        } catch (error) {
            console.error("Error al persistir en Storage:", error.name);
        }
    },
    leer(clave, valorPorDefecto = null) {
        const item = localStorage.getItem(clave);
        if (item === null) return valorPorDefecto;
        try {
            return JSON.parse(item);
        } catch {
            return item; // Si no era JSON, devuelve la cadena plana
        }
    }
};

🎯 Reto 6: Carrito de Compras Persistente con Sincronización en localStorage y DOM Seguro

📝 Enunciado y Especificación del Reto
Escribe una clase `CarritoPersistente` que guarde una lista de productos en `localStorage`. Debe incluir métodos para añadir producto (gestionando cantidades si ya existe), eliminar producto y vaciar la cesta. Cada mutación debe persistir en Storage y renderizar una lista en el DOM mediante `document.createElement()`. Registra además un escuchador para el evento `window.onstorage` que actualice la interfaz si el carrito cambia desde otra pestaña.
💡 Pistas Clave y Procedimiento Guiado
Usa JSON.stringify y JSON.parse para la lista de productos. En el evento storage, comprueba si e.key === "carrito_compras" y llama al método de renderizado.
🔍 Desplegar Solución Embebida y Explicación Técnica Clic para Ver/Ocultar
Explicación Técnica: La sincronización entre pestañas mediante el evento storage garantiza coherencia de estado en aplicaciones de comercio electrónico donde el usuario trabaja en múltiples ventanas simultáneamente.
💻 Código de la Solución Comentada:
class CarritoPersistente {
    constructor(claveStorage = "carrito_compras", selectorContenedor = "#lista-carrito") {
        this.clave = claveStorage;
        this.selectorContenedor = selectorContenedor;
        this.items = this.cargar();
        this.sincronizarPestanas();
        this.renderizar();
    }

    cargar() {
        try {
            const raw = localStorage.getItem(this.clave);
            return raw ? JSON.parse(raw) : [];
        } catch (e) {
            console.warn("Fallo al leer Storage, iniciando cesta vacía:", e);
            return [];
        }
    }

    guardar() {
        try {
            localStorage.setItem(this.clave, JSON.stringify(this.items));
            this.renderizar();
        } catch (e) {
            console.error("Error de cuota en Storage (QuotaExceededError):", e);
        }
    }

    agregar(id, nombre, precio) {
        const existente = this.items.find(i => i.id === id);
        if (existente) {
            existente.cantidad += 1;
        } else {
            this.items.push({ id, nombre, precio, cantidad: 1 });
        }
        this.guardar();
    }

    eliminar(id) {
        this.items = this.items.filter(i => i.id !== id);
        this.guardar();
    }

    vaciar() {
        this.items = [];
        this.guardar();
        console.log("Cesta de compras vaciada completamente.");
    }

    sincronizarPestanas() {
        window.addEventListener('storage', (e) => {
            if (e.key === this.clave) {
                console.log("🔄 Sincronización: El carrito fue modificado en otra pestaña o ventana.");
                this.items = e.newValue ? JSON.parse(e.newValue) : [];
                this.renderizar();
            }
        });
    }

    renderizar() {
        // 1. Diagnóstico estructurado en consola
        const total = this.items.reduce((acc, item) => acc + (item.precio * item.cantidad), 0);
        console.group("🛒 Estado Actual del Carrito (Sincronizado)");
        console.table(this.items);
        console.log(`Importe Total Acumulado: ${total.toFixed(2)}€`);
        console.groupEnd();

        // 2. Renderizado dinámico y seguro en el DOM con document.createElement
        if (typeof document !== "undefined") {
            let contenedor = document.querySelector(this.selectorContenedor);
            if (!contenedor) {
                // Si no existe, crear un contenedor de demostración en el body
                contenedor = document.createElement("div");
                contenedor.id = this.selectorContenedor.replace("#", "");
                contenedor.style.cssText = "padding: 16px; background: #f8fafc; border-radius: 8px; font-family: sans-serif;";
                document.body.appendChild(contenedor);
            }

            contenedor.replaceChildren(); // Limpieza eficiente de nodos previos

            if (this.items.length === 0) {
                const vacioP = document.createElement("p");
                vacioP.textContent = "Tu cesta de compras está vacía.";
                vacioP.style.color = "#64748b";
                contenedor.appendChild(vacioP);
                return;
            }

            const ul = document.createElement("ul");
            ul.style.cssText = "list-style: none; padding: 0; margin: 0 0 12px 0;";

            const fragmento = document.createDocumentFragment();
            this.items.forEach(item => {
                const li = document.createElement("li");
                li.style.cssText = "display: flex; justify-content: space-between; align-items: center; padding: 8px; border-bottom: 1px solid #e2e8f0;";

                const infoSpan = document.createElement("span");
                infoSpan.textContent = `${item.nombre} x${item.cantidad} - ${(item.precio * item.cantidad).toFixed(2)}€`;

                const btnBorrar = document.createElement("button");
                btnBorrar.textContent = "✖";
                btnBorrar.title = "Eliminar artículo";
                btnBorrar.style.cssText = "background: #ef4444; color: white; border: none; border-radius: 4px; padding: 2px 6px; cursor: pointer;";
                btnBorrar.onclick = () => this.eliminar(item.id);

                li.append(infoSpan, btnBorrar);
                fragmento.appendChild(li);
            });

            ul.appendChild(fragmento);

            const totalDiv = document.createElement("div");
            totalDiv.style.cssText = "font-weight: bold; color: #0f172a; margin-top: 8px;";
            totalDiv.textContent = `Total a Pagar: ${total.toFixed(2)}€`;

            contenedor.append(ul, totalDiv);
        }
    }
}
