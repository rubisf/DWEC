1. Introducción al Modelo de Eventos y Manejadores (addEventListener)

💡 Fundamentos Conceptuales

El desarrollo frontend se rige por el paradigma de Programación Dirigida por Eventos (Event-Driven Programming), donde el código reacciona a interacciones del usuario o cambios del sistema:

  • Evolución de los Manejadores de Eventos:
    • Atributos HTML en Línea (onclick="..."): Obsoletos y desaconsejados por acoplar estructura y comportamiento, además de exponer a vulnerabilidades XSS.
    • Propiedades DOM Tradicionales (elemento.onclick = fn): Permiten un único manejador por evento; cualquier asignación posterior sobreescribe la anterior.
    • Estándar W3C Moderno (addEventListener): Permite adjuntar múltiples escuchadores independientes al mismo evento y elemento, soportando parámetros de configuración avanzados y separación total de capas.
  • Sintaxis de addEventListener(tipo, listener, opciones):
    • tipo: Nombre del evento en minúsculas (ej. "click", "input").
    • listener: Función que se ejecuta al dispararse el evento (función nombrada, anónima o función flecha).
    • opciones: Objeto de configuración:
      • once: true: El escuchador se ejecuta una sola vez y se desvincula automáticamente.
      • passive: true: Garantiza al navegador que el manejador nunca llamará a preventDefault(), permitiendo un scroll ultrasuave en dispositivos táctiles.
      • capture: true: Ejecuta el manejador en la fase de captura en lugar de en la fase de burbujeo.
  • Desvinculación con removeEventListener(): Exige proporcionar exactamente la misma referencia de función nombrada que se usó al registrar el evento. Las funciones anónimas o flecha no pueden desvincularse.
  • El Objeto Event: Se inyecta automáticamente como primer parámetro en el callback:
    • e.target: Elemento exacto del DOM donde se originó el evento.
    • e.currentTarget: Elemento al que está vinculado el escuchador activo (equivalente a this en funciones clásicas).
    • e.type: Nombre textual del evento.
    • e.timeStamp: Marca de tiempo en milisegundos de cuándo ocurrió el evento.
🔍 Ampliación y Estándares 2026

Gestión de Memoria y Fugas en Event Listeners:

  • Prevención de Memory Leaks con AbortController: El estándar moderno permite cancelar grupos enteros de eventos pasando una señal: elemento.addEventListener('click', fn, { signal: controller.signal }). Al invocar controller.abort(), todos los eventos vinculados a esa señal se destruyen de golpe limpiamente.
  • Comportamiento de this vs e.currentTarget: En funciones flecha, this no apunta al elemento DOM (hereda el ámbito superior). Para acceder al elemento que escucha el evento de forma 100% segura e independiente del tipo de función, se debe emplear siempre e.currentTarget.

🔍 Desplegar Solución Embebida y Explicación Técnica Clic para Ver/Ocultar

💻 Código de la Solución Comentada:
function configurarBotonConLimite(botonElemento, maxIntentos = 3) {
    let clicsRealizados = 0;
    const controller = new AbortController();

    function manejarClic(evento) {
        clicsRealizados++;
        console.log(\`Clic \${clicsRealizados}/\${maxIntentos} registrado en \${evento.currentTarget.id}\`);

        if (clicsRealizados >= maxIntentos) {
            console.warn("Límite de interacciones alcanzado. Desvinculando escuchador...");
            controller.abort(); // Destruye el listener automáticamente
            botonElemento.disabled = true;
            botonElemento.textContent = "Límite Alcanzado 🔒";
        }
    }

    botonElemento.addEventListener("click", manejarClic, { signal: controller.signal });
    console.log("Escuchador con señal de cancelación registrado con éxito.");
}

2. Fases de Propagación de Eventos: Captura, Destino, Burbujeo y Delegación

💡 Fundamentos Conceptuales

Cuando ocurre un evento en un elemento del DOM, viaja a través de la jerarquía de nodos en un ciclo formal de propagación en tres fases:

  • 1. Fase de Captura (Capturing Phase): El evento desciende por el árbol DOM desde el objeto window, pasando por document, <html>, <body> y ancestros hasta llegar al elemento objetivo. Por defecto, los escuchadores no se disparan en esta fase a menos que se configure explícitamente { capture: true }.
  • 2. Fase de Destino (Target Phase): El evento alcanza el elemento exacto donde se originó la interacción (e.target).
  • 3. Fase de Burbujeo (Bubbling Phase): El evento asciende de vuelta desde el elemento objetivo hacia arriba a través de todos sus padres hasta window. La inmensa mayoría de escuchadores operan en esta fase por defecto.
  • Control de la Propagación:
    • e.stopPropagation(): Detiene la propagación del evento, impidiendo que siga ascendiendo o descendiendo por el árbol DOM hacia los demás elementos ancestros.
    • e.stopImmediatePropagation(): Además de detener la propagación por el árbol, impide la ejecución de cualquier otro escuchador registrado en ese mismo elemento.
    • e.preventDefault(): Cancela la acción predeterminada que el navegador realiza por defecto (ej. navegar al enlace en un <a>, enviar formulario en submit o escribir texto en keydown). No detiene la propagación.
  • Técnica de Delegación de Eventos (Event Delegation): En lugar de vincular un escuchador a cientos de elementos hijos individuales (lo que consume excesiva memoria), se vincula un único escuchador en el contenedor padre. Gracias al burbujeo, el padre intercepta los clics de cualquier hijo presente o futuro mediante e.target.closest(selector).
🔍 Ampliación y Estándares 2026

Eficiencia y Escalabilidad con Delegación de Eventos:

  • Elementos Creados Dinámicamente: La delegación es la solución por excelencia para listas dinámicas o tablas donde se añaden o eliminan filas continuamente: no es necesario adjuntar nuevos listeners a cada fila creada porque el contenedor padre ya los gestiona todos.
  • Eventos que no Burbujean: Eventos como focus, blur, mouseenter y mouseleave no burbujean. Para delegarlos se debe usar la fase de captura ({ capture: true }) o sus variantes que sí burbujean: focusin, focusout, mouseover y mouseout.

Utiliza un único escuchador de eventos en el elemento `<tbody>` mediante delegación. Identifica el botón pulsado con `e.target.closest()`, extrae el identificador del pedido desde el atributo `data-id` de la fila, y anula la acción predeterminada de navegación mediante `e.preventDefault()`.

🔍 Desplegar Solución Embebida y Explicación Técnica Clic para Ver/Ocultar
Explicación Técnica: La delegación de eventos optimiza drásticamente el consumo de memoria del navegador y elimina la necesidad de re-vincular eventos al insertar nuevas filas dinámicas.
💻 Código de la Solución Comentada:
function inicializarTablaPedidos(tbodyElemento) {
    // Delegación centralizada en el contenedor <tbody>
    tbodyElemento.addEventListener("click", (e) => {
        // Buscar el botón interactivo pulsado más cercano
        const boton = e.target.closest("button");
        if (!boton) return; // Se pulsó en texto plano de la tabla

        // Obtener la fila contenedora y su metadato
        const fila = boton.closest("tr");
        const pedidoId = fila?.dataset.id ?? "Desconocido";

        // Determinar acción según las clases o atributos del botón
        if (boton.classList.contains("btn-eliminar")) {
            e.preventDefault();
            console.warn(\`Eliminando pedido #\${pedidoId} de la tabla.\`);
            fila.remove();
        } else if (boton.classList.contains("btn-enviar")) {
            e.preventDefault();
            console.log(\`Marcando pedido #\${pedidoId} como enviado.\`);
            fila.style.background = "#dcfce7";
            boton.disabled = true;
        } else if (boton.classList.contains("btn-detalles")) {
            e.preventDefault();
            console.log(\`Abriendo panel de detalles para pedido #\${pedidoId}\`);
        }
    });
}

3. Catálogo de Tipos de Eventos: Ratón, Teclado, Formulario, Ventana y Personalizados

💡 Fundamentos Conceptuales

El navegador emite una amplia variedad de eventos clasificados según la naturaleza del dispositivo de entrada o la fuente generadora:

  • Eventos de Ratón (MouseEvent):
    • Pulsaciones: click, dblclick, mousedown, mouseup, contextmenu (menú contextual del botón derecho).
    • Movimiento: mousemove (alta frecuencia), mouseenter / mouseleave (no burbujean, se activan al entrar/salir del contenedor), frente a mouseover / mouseout (burbujean y se reactivan al pasar sobre elementos hijos).
    • Coordenadas: clientX/Y (relativas al viewport visible), pageX/Y (relativas a la página completa con scroll), screenX/Y (relativas al monitor del usuario).
  • Eventos de Teclado (KeyboardEvent):
    • keydown (al presionar la tecla, se repite si se mantiene pulsada) y keyup (al soltarla).
    • Propiedades modernas: e.key (carácter textual producido, ej. "Enter", "a", "Escape") y e.code (código físico del botón del teclado, ej. "KeyA", "Digit1"). Teclas modificadoras booleanas: e.ctrlKey, e.shiftKey, e.altKey, e.metaKey (Cmd en Mac).
  • Eventos de Ventana y Documento:
    • DOMContentLoaded: Se dispara en document cuando el árbol HTML está completamente parseado sin esperar a imágenes ni hojas de estilo.
    • load: Se dispara en window cuando la página completa y todos sus recursos externos asociados han terminado de cargarse.
    • resize, scroll (conviene modularlos con debouncing/throttling) y beforeunload (advertencia antes de abandonar la página).
  • Eventos Personalizados (CustomEvent): Permiten desacoplar componentes y crear arquitecturas orientadas a eventos. Se instancian con new CustomEvent(nombre, { detail: {...}, bubbles: true }) y se emiten con elemento.dispatchEvent(evento).
🔍 Ampliación y Estándares 2026

Optimización de Eventos de Alta Frecuencia con Debounce y Throttle:

  • Debounce: Pospone la ejecución del manejador hasta que transcurra un periodo de inactividad (ideal para barras de búsqueda predictiva en el evento input).
  • Throttle: Limita la frecuencia de ejecución a un intervalo fijo regular (ej. ejecutar como máximo una vez cada 100 ms durante el evento scroll o resize para evitar caídas de fotogramas).

🔍 Desplegar Solución Embebida y Explicación Técnica Clic para Ver/Ocultar
Explicación Técnica: El uso de CustomEvent permite que componentes independientes de la interfaz se comuniquen sin acoplamiento directo, respondiendo a eventos de teclado de forma modular.
💻 Código de la Solución Comentada:
function inicializarAtajosGlobales() {
    window.addEventListener("keydown", (e) => {
        // 1. Atajo: Cerrar modales con Escape
        if (e.key === "Escape") {
            console.log("Atajo presionado: Escape -> Cerrando elementos flotantes.");
            const eventoCierre = new CustomEvent("ui:cerrar-modales", { bubbles: true });
            document.dispatchEvent(eventoCierre);
            return;
        }

        // 2. Atajo: Envío rápido con Ctrl + Enter
        if ((e.ctrlKey || e.metaKey) && e.key === "Enter") {
            e.preventDefault();
            console.log("Atajo presionado: Ctrl + Enter -> Emitiendo evento de envío rápido.");

            const eventoEnvio = new CustomEvent("formulario:enviar-rapido", {
                detail: { origen: "atajo_teclado", timestamp: Date.now() },
                bubbles: true
            });
            document.dispatchEvent(eventoEnvio);
        }
    });

    // Escuchador de prueba del evento desacoplado
    document.addEventListener("formulario:enviar-rapido", (e) => {
        console.log("Evento personalizado capturado con éxito:", e.detail);
    });
}

4. Interacción con Formularios y Controles desde Código

💡 Fundamentos Conceptuales

Los formularios HTML constituyen el principal medio de entrada de datos en la web. JavaScript permite interceptar, manipular y controlar el ciclo de vida de sus campos:

  • Acceso a Formularios y Elementos:
    • Colección histórica: document.forms["miFormulario"].
    • Selector moderno: const form = document.querySelector("#registro-form");
    • Colección interna de controles: form.elements["email"] o form.elements[0]. Agrupa todos los inputs, selects, textareas y buttons del formulario.
  • Eventos de Formulario Clave:
    • input: Se dispara de forma inmediata en tiempo real cada vez que el valor del campo cambia (al escribir cada letra). Indispensable para validación instantánea y feedback visual.
    • change: Se dispara cuando el valor cambia y el campo pierde el foco (en inputs de texto) o de inmediato al seleccionar una opción (en <select>, checkboxes y radios).
    • focus y blur: Se activan al recibir o perder el foco de interacción (no burbujean; usar focusin/focusout si se requiere delegación).
    • submit: Se activa en el formulario al pulsar un botón type="submit" o presionar Enter. La llamada a e.preventDefault() detiene el envío HTTP tradicional para procesarlo de forma asíncrona (AJAX/Fetch).
    • reset: Se activa al restablecer el formulario con un botón type="reset".
  • Lectura y Manipulación de Tipos de Controles:
    • Campos de texto y textareas: Propiedad input.value (siempre devuelve un string).
    • Casillas de verificación (Checkbox): Propiedad booleana checkbox.checked.
    • Botones de opción (Radio): Mismo atributo name; se localiza el seleccionado mediante form.querySelector('input[name="genero"]:checked')?.value.
    • Desplegables (Select): select.value (valor de la opción seleccionada) y select.selectedIndex (índice numérico).
🔍 Ampliación y Estándares 2026

El Objeto FormData para Formularios Complejos:

  • Extracción Instantánea de Datos: Al invocar const datos = new FormData(formulario);, se empaquetan automáticamente todos los campos con atributo name, incluyendo ficheros subidos (<input type="file">).
  • Conversión a Objeto Plano: La instrucción moderna const json = Object.fromEntries(datos.entries()); transforma el formulario entero en un objeto JavaScript listo para serializar a JSON y enviar vía API Fetch.

function configurarFormularioRegistro(formulario, selectTipo, campoCifContenedor, inputCif) {

        e.preventDefault(); // Impide recarga de página

        const formData = new FormData(formulario);
        const payload = Object.fromEntries(formData.entries());

        console.log("Formulario validado y procesado localmente:");
        console.table(payload);
    });
}

5. Validación de Campos Mediante Expresiones Regulares y Constraint Validation API

💡 Fundamentos Conceptuales

La validación de datos en cliente proporciona retroalimentación instantánea al usuario y previene el envío de información defectuosa mediante dos mecanismos complementarios:

  • Expresiones Regulares en JavaScript (Objeto RegExp):
    • Definición: Sintaxis literal (const regex = /^[\w.-]+@[\w.-]+\.[a-z]{2,}$/i;) o mediante constructor new RegExp("patron", "flags").
    • Metacaracteres clave: ^ (inicio), $ (fin), \d (dígito), \w (alfanumérico y guion bajo), \s (espacio en blanco), + (uno o más), * (cero o más), ? (opcional), {min, max} (cuantificador exacto), [...] (clase de caracteres).
    • Banderas (Flags): i (insensible a mayúsculas), g (búsqueda global), u (soporte Unicode completo).
    • Método principal de validación: regex.test(cadena) (devuelve booleano estricto).
  • Patrones Clásicos de Validación Web:
    • DNI Español: 8 números seguidos de letra mayúscula (/^[0-9]{8}[A-Z]$/) validada con el algoritmo de control "TRWAGMYFPDXBNJZSQVHLCKE"[dni % 23].
    • Contraseña Fuerte: Mínimo 8 caracteres, al menos una mayúscula, una minúscula, un dígito y un carácter especial (/^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[@$!%*?&])[A-Za-z\d@$!%*?&]{8,}$/).
  • Constraint Validation API (Validación Nativa HTML5):

    Conjunto de propiedades y métodos expuestos en los elementos de formulario:

    • Atributos estándar: required, pattern="regex", minlength, maxlength, min, max, type="email".
    • Método input.checkValidity(): Comprueba si el campo cumple sus restricciones (devuelve booleano).
    • Método input.reportValidity(): Comprueba y, si es inválido, muestra la burbuja de error nativa del navegador.
    • Método input.setCustomValidity("Mensaje de error"): Asigna un mensaje de error personalizado. Si se pasa una cadena vacía (""), el campo vuelve a considerarse válido.
    • Objeto input.validity: Expone el motivo exacto de la invalidez (valueMissing, patternMismatch, typeMismatch, tooShort, valid).
🔍 Ampliación y Estándares 2026

La Regla Inviolable de la Validación en Cliente:

  • La Validación Cliente es UX, no Seguridad: La validación en JavaScript existe para mejorar la experiencia del usuario (inmediatez sin esperar al servidor). Nunca sustituye a la validación en el Backend, ya que un atacante puede deshabilitar JavaScript o enviar peticiones HTTP directamente mediante herramientas como Postman o cURL.
  • Atributo novalidate en <form>: Desactiva los globos de error nativos del navegador, permitiendo al desarrollador diseñar sistemas propios de mensajería y estilos de error visuales.

// Validación con Expresiones Regulares y Constraint Validation API
function validarDNIEspanol(inputElemento) {
    const valor = inputElemento.value.trim().toUpperCase();
    const regexDNI = /^[0-9]{8}[TRWAGMYFPDXBNJZSQVHLCKE]$/;

    // 1. Validación de formato formal con RegExp
    if (!regexDNI.test(valor)) {
        inputElemento.setCustomValidity("El DNI debe tener 8 dígitos y una letra mayúscula.");
        inputElemento.reportValidity();
        return false;
    }

    // 2. Validación algorítmica de la letra de control
    const numero = parseInt(valor.substring(0, 8), 10);
    const letraIngresada = valor.charAt(8);
    const letrasControl = "TRWAGMYFPDXBNJZSQVHLCKE";
    const letraCalculada = letrasControl[numero % 23];

    if (letraIngresada !== letraCalculada) {
        inputElemento.setCustomValidity(`Letra incorrecta. Para el número ${numero} corresponde la '${letraCalculada}'.`);
        inputElemento.reportValidity();
        return false;
    }

    // Campo 100% válido: limpiar error personalizado
    inputElemento.setCustomValidity("");
    console.log("DNI validado con éxito:", valor);
    return true;
}

function validarDNI(inputDNI) {

// 2. Auditor Reactivo de Complejidad de Contraseña
function auditarSeguridadContrasena(inputPassword) {
    inputPassword.addEventListener("input", () => {
        const pass = inputPassword.value;
        const faltantes = [];

        if (pass.length < 8) faltantes.push("mínimo 8 caracteres");
        if (!/[A-Z]/.test(pass)) faltantes.push("al menos una mayúscula");
        if (!/[a-z]/.test(pass)) faltantes.push("al menos una minúscula");
        if (!/[0-9]/.test(pass)) faltantes.push("al menos un dígito numérico");
        if (!/[@$!%*?&._-]/.test(pass)) faltantes.push("un carácter especial (@$!%*?&._-)");

        if (faltantes.length > 0) {
            inputPassword.setCustomValidity("Requisitos pendientes: " + faltantes.join(", "));
            inputPassword.style.borderColor = "#ef4444";
        } else {
            inputPassword.setCustomValidity(""); // Conforme
            inputPassword.style.borderColor = "#10b981";
            console.log("✅ Contraseña robusta verificada.");
        }
    });
}

6. Modificación Dinámica de Apariencia, Comportamiento y Pruebas del Código

💡 Fundamentos Conceptuales

La interacción con el usuario se complementa con la modificación dinámica de estilos y clases y el testeo automatizado de eventos:

  • Gestión Dinámica de Clases CSS con classList:

    Forma estándar y óptima para alterar la apariencia de los elementos sin manipular cadenas directas:

    • elemento.classList.add("clase1", "clase2"): Añade clases.
    • elemento.classList.remove("clase"): Elimina clases.
    • elemento.classList.toggle("clase", condicionBooleana): Conmuta la presencia de la clase (la añade si no está, la elimina si ya está presente).
    • elemento.classList.contains("clase"): Comprueba la existencia devolviendo un booleano.
    • elemento.classList.replace("vieja", "nueva"): Sustituye una clase por otra atómicamente.
  • Estilos en Línea vs Estilos Calculados:
    • elemento.style.propiedadCSS: Permite leer y escribir estilos en línea (en formato camelCase, ej. elemento.style.backgroundColor = "red"). Solo lee estilos definidos en línea en el atributo style.
    • window.getComputedStyle(elemento): Devuelve un objeto de solo lectura con los valores calculados finales reales de todas las propiedades CSS del elemento tras aplicar la cascada y la herencia del navegador.
  • Pruebas y Simulación Programática de Eventos:

    Para testing unitario o automatización de interfaces, JavaScript permite despachar eventos sintéticos de forma programática:

    • Disparo simplificado: elemento.click(), elemento.focus().
    • Disparo estándar: elemento.dispatchEvent(new Event("change", { bubbles: true })).
    • Herramienta de depuración en consola: monitorEvents(elemento) en DevTools para ver en directo cualquier evento emitido.
🔍 Ampliación y Estándares 2026

Separación de Responsabilidades en Estilos:

  • Preferir Clases sobre style.property: El código JavaScript nunca debe definir valores específicos de diseño (colores hex, márgenes o fuentes) mediante elemento.style. La buena práctica consiste en definir las clases de diseño en CSS y hacer que JavaScript se limite a añadir o quitar dichas clases (classList.add('error')) o modificar Variables CSS (elemento.style.setProperty('--color-tema', '#2563eb')).
  • Coordinación con Transiciones CSS: Al añadir una clase con animación, el evento transitionend permite ejecutar lógica JavaScript justo en el instante en que la animación visual ha finalizado.

🎯 Reto 6: Conmutador de Temas Visuales (Dark/Light Mode) con Persistencia y Eventos Sintéticos

📝 Enunciado y Especificación del Reto
Diseña un módulo que gestione el tema visual de una página web. Debe: 1) Detectar la preferencia del sistema operativo mediante `window.matchMedia("(prefers-color-scheme: dark)")`, 2) Permitir conmutar manualmente entre modo claro y oscuro con `classList.toggle("dark")`, 3) Persistir la elección en `localStorage`, y 4) Disparar un evento sintético `"tema:cambiado"` para notificar a los componentes de la interfaz.
💡 Pistas Clave y Procedimiento Guiado
Usa window.matchMedia.matches para la preferencia inicial del SO. Emite document.dispatchEvent(new CustomEvent("tema:cambiado", { detail: { tema } })).
🔍 Desplegar Solución Embebida y Explicación Técnica Clic para Ver/Ocultar
Explicación Técnica: La sincronización entre matchMedia, variables CSS y eventos personalizados produce interfaces adaptables que respetan la configuración de accesibilidad del usuario.
💻 Código de la Solución Comentada:
class GestorTemas {
    constructor() {
        this.temaActual = this.determinarTemaInicial();
        this.aplicarTema(this.temaActual);
        this.escucharPreferenciaSO();
    }

    determinarTemaInicial() {
        const guardado = localStorage.getItem("app_tema");
        if (guardado) return guardado;

        // Detección automática de preferencia del sistema operativo
        return window.matchMedia("(prefers-color-scheme: dark)").matches ? "oscuro" : "claro";
    }

    aplicarTema(tema) {
        this.temaActual = tema;
        const esOscuro = tema === "oscuro";
        document.body.classList.toggle("dark-theme", esOscuro);
        localStorage.setItem("app_tema", tema);

        // Disparo de evento sintético para notificar a la aplicación
        const evento = new CustomEvent("tema:cambiado", {
            detail: { tema, esOscuro },
            bubbles: true
        });
        document.dispatchEvent(evento);
        console.log(\`Tema aplicado: \${tema.toUpperCase()}\`);
    }

    conmutar() {
        const nuevoTema = this.temaActual === "oscuro" ? "claro" : "oscuro";
        this.aplicarTema(nuevoTema);
    }

    escucharPreferenciaSO() {
        window.matchMedia("(prefers-color-scheme: dark)").addEventListener("change", (e) => {
            if (!localStorage.getItem("app_tema")) {
                this.aplicarTema(e.matches ? "oscuro" : "claro");
            }
        });
    }
}

const temas = new GestorTemas();
