1. Modelo de Eventos W3C y addEventListener

💡 Fundamentos Conceptuales

El modelo de eventos estandarizado por el W3C permite gestionar las interacciones del usuario de forma desacoplada:

  • Método addEventListener(event, listener, options): Vincula un manejador de eventos a un elemento DOM sin sobrescribir otros listeners existentes.
  • Desvinculación con removeEventListener(): Elimina un evento previamente adjuntado. Requiere pasar exactamente la misma referencia de función.
  • Objeto Event: Contiene información sobre el evento desencadenado (e.target elemento origen, e.type tipo de evento, e.timeStamp marca de tiempo).
🔍 Ampliación y Estándares 2026

Opciones de registro avanzadas e interrupción del comportamiento por defecto:

  • event.preventDefault(): Cancela la acción predeterminada que el navegador ejecutaría para ese evento (ej. evitar el envío de un formulario o la navegación de un enlace).
  • Opción { once: true }: Garantiza que el manejador se ejecute una sola vez y se desvincule automáticamente del DOM.
  • Opción { passive: true }: Indica al navegador que el listener nunca llamará a preventDefault(), optimizando drásticamente el rendimiento de desplazamientos (scroll).
💻 Demostración Práctica e Implementación de Código 🚀 Abrir Ejemplo Real en Vivo (ejemplo1_event_listeners.js) 🔗 
// UT5 - Ejemplo 1: Event Listeners
if (typeof document !== 'undefined') {
    const btn = document.createElement("button");
    btn.addEventListener("click", (e) => console.log("Clic registrado en:", e.target), { once: true });
}

2. Fases de Propagación: Captura, Burbujeo y Delegación

💡 Fundamentos Conceptuales

Cuando ocurre un evento en un elemento anidado, este se propaga a través del árbol DOM en tres fases consecutivas:

  • 1. Fase de Captura (Capturing Phase): El evento desciende desde el objeto window y la raíz del DOM hasta llegar al elemento objetivo.
  • 2. Fase del Objetivo (Target Phase): El evento alcanza directamente al nodo desencadenante (e.target).
  • 3. Fase de Burbujeo (Bubbling Phase): El evento asciende consecutivamente desde el objetivo de vuelta hasta la raíz del documento HTML.
🔍 Ampliación y Estándares 2026

Técnicas avanzadas de optimización mediante delegación de eventos:

  • Delegación de Eventos (Event Delegation): Patrón que consiste en registrar un único manejador de eventos en un contenedor padre en lugar de adjuntar cientos de listeners a elementos hijos. Aprovecha la fase de burbujeo y gestiona elementos dinámicos mediante e.target.closest(selector).
  • event.stopPropagation(): Detiene inmediatamente la propagación del evento hacia los elementos superiores en la fase de burbujeo.
  • event.stopImmediatePropagation(): Cancela la propagación y evita que otros listeners registrados en el mismo elemento se ejecuten.
💻 Demostración Práctica e Implementación de Código 🚀 Abrir Ejemplo Real en Vivo (ejemplo2_propagacion_delegacion.js) 🔗 
// UT5 - Ejemplo 2: Delegación de Eventos
if (typeof document !== 'undefined') {
    document.addEventListener("click", (e) => {
        const item = e.target.closest(".item-lista");
        if (item) console.log("Elemento seleccionado por delegación:", item.dataset.id);
    });
}

3. Eventos de Ratón, Teclado e Interacción

💡 Fundamentos Conceptuales

JavaScript expone eventos específicos para gestionar interacciones ricas de usuario:

  • Eventos de Ratón y Puntero: click, dblclick, pointerdown, pointermove, pointerup. La Pointer Events API unifica ratón, pantallas táctiles y lápices ópticos.
  • Eventos de Teclado: keydown y keyup. La propiedad e.key devuelve el valor del carácter presionado y e.code el código físico de la tecla.
  • Eventos de Foco y Formulario: focus, blur, change (al perder el foco habiendo cambiado el valor) e input (disparado inmediatamente en cada pulsación).
🔍 Ampliación y Estándares 2026

Técnicas de control de tasa de ejecución (Throttling y Debouncing):

  • Debouncing (Antirrebote): Pospone la ejecución de una función hasta que haya transcurrido un tiempo determinado de inactividad tras la última llamada (ideal para campos de búsqueda de texto).
  • Throttling (Limitación de Tasa): Limita la frecuencia máxima con la que una función puede ejecutarse a intervalos regulares fijados (ideal para eventos de scroll o resize).
  • Accesibilidad (A11y): Asegurar que todas las interacciones de ratón tengan su equivalente funcional navegable mediante teclado.
💻 Demostración Práctica e Implementación de Código 🚀 Abrir Ejemplo Real en Vivo (ejemplo3_eventos_teclado_raton.js) 🔗 
// UT5 - Ejemplo 3: Keydown Events
if (typeof document !== 'undefined') {
    document.addEventListener("keydown", (e) => {
        console.log(`Tecla: ${e.key} | Código: ${e.code}`);
    });
}

4. Validación de Formularios y Constraint Validation API

💡 Fundamentos Conceptuales

La validación de formularios en el cliente es la primera línea de defensa para mejorar la experiencia de usuario:

  • Atributos de Validación HTML5: required, minlength, maxlength, pattern (expresiones regulares) y tipos específicos (type="email", type="number").
  • Evento submit: Captura el intento de envío del formulario en el contenedor <form> para validar datos antes de llamar a e.preventDefault() si existen errores.
🔍 Ampliación y Estándares 2026

Validación programática avanzada con la Constraint Validation API:

  • element.checkValidity(): Evalúa si el campo cumple todas las restricciones devolviendo un booleano.
  • Objeto element.validity: Expone propiedades booleanas detalladas de error (valueMissing, typeMismatch, patternMismatch, tooShort, rangeUnderflow).
  • element.setCustomValidity(mensaje): Asigna un mensaje de error personalizado. Pasar una cadena vacía () marca el campo como válido.
💻 Demostración Práctica e Implementación de Código 🚀 Abrir Ejemplo Real en Vivo (ejemplo4_constraint_validation.js) 🔗 
// UT5 - Ejemplo 4: Constraint Validation
if (typeof document !== 'undefined') {
    const input = document.createElement("input");
    input.type = "email";
    input.value = "correo-invalido";
    console.log("¿Input email válido?:", input.checkValidity());
}
