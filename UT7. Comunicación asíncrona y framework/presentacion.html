1. Asincronía en JavaScript: Event Loop, Promesas y Fetch API

💡 Fundamentos Conceptuales

JavaScript gestiona operaciones asíncronas de red mediante el bucle de eventos y la estructura de Promesas:

  • Promesas (Promises): Objetos que representan el resultado eventual (éxito o fallo) de una operación asíncrona. Tienen 3 estados: Pending (pendiente), Fulfilled (resuelta con éxito) o Rejected (rechazada con error).
  • Sintaxis async / await: Azúcar sintáctico sobre Promesas que permite escribir código asíncrono con apariencia secuencial sincrónica utilizando bloques try...catch para captura de errores.
  • Fetch API: Interfaz nativa basada en Promesas para realizar peticiones HTTP (fetch(url, options)).
🔍 Ampliación y Estándares 2026

Gestión avanzada de colas asíncronas y cancelación de peticiones de red:

  • Microtareas vs Macrotareas: Las Promesas (.then/await) y queueMicrotask se ejecutan en la Microtask Queue, la cual se vacía por completo antes de procesar la siguiente macrotarea (setTimeout, eventos I/O) del Event Loop.
  • Mapeo de Errores en Fetch: fetch() NO rechaza la promesa ante códigos HTTP 404 o 500. Debe comprobarse manualmente la propiedad response.ok.
  • AbortController API: Permite cancelar peticiones HTTP en curso mediante un AbortSignal ante eventos de tiempo de espera (timeout) o navegación activa.
💻 Demostración Práctica e Implementación de Código 🚀 Abrir Ejemplo Real en Vivo (ejemplo1_async_await_fetch.js) 🔗 
// UT7 - Ejemplo 1: Async / Await y Fetch API
async function obtenerDatos(url) {
    try {
        console.log(`Petición asíncrona enviada a: ${url}`);
        return { ok: true, status: 200, data: [{ id: 1, usuario: "Rubén" }] };
    } catch (err) {
        console.error("Error en la solicitud:", err.message);
    }
}
obtenerDatos("https://api.ejemplo.com/v1/usuarios").then(res => console.log("Respuesta recibida:", res));

2. Arquitectura SPA (Single Page Applications)

💡 Fundamentos Conceptuales

Una SPA (Single Page Application) es una aplicación web que carga un único documento HTML inicial y actualiza dinámicamente el contenido sin recargar la página completa:

  • Enrutamiento en Cliente (Client-Side Routing): Intercepción de eventos de navegación para cambiar la vista cliente sin realizar solicitudes de página completa al servidor.
  • HTML5 History API: Métodos history.pushState() y history.replaceState() combinados con el evento window.addEventListener('popstate') para manipular la URL visible y mantener el funcionamiento de los botones Atrás/Adelante.
🔍 Ampliación y Estándares 2026

Arquitectura de componentes y renderizado dinámico en cliente:

  • Componentes Web Nativos (Web Components): Conjunto de APIs de la plataforma web formadas por Custom Elements (etiquetas personalizadas), Shadow DOM (árbol DOM encapsulado e independiente que aísla los estilos CSS) y <template> HTML.
  • Gestión de Estado Centralizada: Mantener una fuente única de la verdad (Single Source of Truth) para sincronizar las vistas UI ante cambios de datos en la SPA.
💻 Demostración Práctica e Implementación de Código 🚀 Abrir Ejemplo Real en Vivo (ejemplo2_spa_history_api.js) 🔗

3. Introducción al Framework Angular

💡 Fundamentos Conceptuales

Angular es un framework de desarrollo frontend mantenido por Google diseñado para construir SPAs escalables en TypeScript:

  • Arquitectura Basada en Componentes: La interfaz se divide en componentes modulares compuestos por una plantilla HTML (Template), estilos CSS y una clase TypeScript (@Component).
  • Inyección de Dependencias (Dependency Injection): Patrón de diseño donde el framework suministra automáticamente las instancias de los servicios requeridos a los componentes.
  • Enlace de Datos Bidireccional (Two-Way Data Binding): Sincronización automática de datos entre el modelo de TypeScript y la vista HTML mediante [(ngModel)] o Signals modernos.
🔍 Ampliación y Estándares 2026

Programación reactiva con RxJS y nuevos paradigmas de reactividad en Angular:

  • RxJS y Observables: Biblioteca de programación reactiva que maneja flujos de datos asíncronos mediante colecciones observables (Observable, Subject) y operadores como pipe(), map() y switchMap().
  • Angular Signals: Modelo reactivo moderno que realiza un seguimiento fino y granular de las dependencias de datos actualizando solo las partes afectadas del DOM.
  • Módulos y Standalone Components: Los componentes independientes (standalone: true) simplifican la arquitectura eliminando la necesidad de los antiguos NgModule.

4. Persistencia NoSQL con MongoDB y Modelado Documental

💡 Fundamentos Conceptuales

MongoDB es una base de datos NoSQL orientada a documentos que almacena información en formato flexible de tipo BSON (Binary JSON):

  • Conceptos Clave vs Relacional: Las Tablas se convierten en Colecciones, las Filas se convierten en Documentos JSON/BSON y las Columnas en Campos de clave-valor.
  • Identificador Único (_id / ObjectId): Cada documento generado incluye un campo _id obligatorio de 12 bytes que actúa como clave primaria.
  • Operaciones CRUD Básicas: insertOne() / insertMany(), find(), updateOne() / updateMany(), deleteOne() / deleteMany().
🔍 Ampliación y Estándares 2026

Modelado de datos documental e integración mediante ODM (Mongoose):

  • Estrategias de Modelado: Documentos incrustados (Embedding) para relaciones de alta cardinalidad/lectura rápida frente a referencias (Referencing) para relaciones complejas.
  • ODM Mongoose (Object Data Modeling): Biblioteca para Node.js que añade esquemas estrictos (Schemas), validaciones de campos y middleware sobre MongoDB.
  • Framework de Agregación (Aggregation Pipeline): Procesamiento y transformación de datos en etapas secuenciales ($match, $group, $project, $lookup) similar a las consultas SQL avanzadas.
💻 Demostración Práctica e Implementación de Código 🚀 Abrir Ejemplo Real en Vivo (ejemplo4_mongodb_aggregation.js) 🔗
