Reto 4: Simulador de Orden de Carga: Sync vs Async vs Defer vs Module

📝 Enunciado:

Escribe una página HTML con scripts que demuestren de forma práctica cómo influye el modo de inclusión en el acceso a elementos del DOM. Comprueba qué sucede cuando un script clásico en `<head>` intenta acceder a un elemento del `<body>` frente a un script con `defer` o `type="module"`.

💡 Pistas: Comprueba document.getElementById("titulo") desde un script síncrono en <head> (devolverá null) y compáralo con un script type="module" que lo encontrará sin error.

Los scripts síncronos en head detienen el parser antes de que el elemento exista en el DOM. Por contra, los módulos ES y scripts con defer esperan a que el árbol DOM esté completamente disponible en memoria.

<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8"/>
  <title>Demostración de Carga y Acceso al DOM</title>
  
  <!-- Intento 1: Script síncrono en head -->
  <script>
    console.log("1. [Sync en Head] Intento leer #caja:", document.getElementById('caja')); // null
  </script>

  <!-- Intento 2: Script con defer -->
  <script defer>
    // Se ejecuta al finalizar el parseo del DOM
    console.log("3. [Defer] Acceso a #caja:", document.getElementById('caja') ? "Éxito ✅" : "Fallo ❌");
  </script>

  <!-- Intento 3: Módulo ES6 -->
  <script type="module">
    const elemento = document.getElementById('caja');
    console.log("4. [Type=Module] Acceso a #caja:", elemento ? "Éxito ✅" : "Fallo ❌");
    console.log("   Ámbito aislado: window.elemento es", window.elemento); // undefined
  </script>
</head>
<body>
  <div id="caja">Elemento contenedor del DOM</div>
  <script>
    console.log("2. [Pie de Body] Acceso inmediato a #caja:", document.getElementById('caja') ? "Éxito ✅" : "Fallo ❌");
  </script>
</body>
</html>
