Fundamentos de JavaScript

⚡ Características Fundamentales de JavaScript

🎯 1. Interpretado (no compilado previo)

Se traduce y ejecuta al vuelo por el motor (V8, SpiderMonkey) mediante compilación JIT (Just-In-Time) sin requerir una compilación previa a ejecutable binario.

⚡ 2. Basado en Eventos

Reacciona a las acciones del usuario (clicks, teclados, envíos de formulario) mediante escuchadores de eventos y la cola de tareas del Event Loop.

🪶 3. Es Ligero

Sintaxis concisa de ejecución nativa directa en el cliente dentro del navegador sin requerir entornos pesados ni instalación de runtimes locales.

🏷️ 4. Tipado Dinámico y Débil

Las variables no se vinculan a un tipo de dato fijo (let x = 10; x = "hola"). El tipo de dato se evalúa en tiempo de ejecución.

🔠 5. Sensible a Mayúsculas/Minúsculas

Lenguaje estrictamente Case-Sensitive: miVariable, Mivariable y MIVARIABLE representan tres identificadores independientes.

🌐 6. Independiente de Plataforma

Multiplataforma por especificación W3C y ECMAScript. Se ejecuta de forma idéntica en Windows, macOS, Linux, iOS y Android dentro del navegador.

⏱️ 7. Procesamiento Asíncrono y No Bloqueante

Modelo monohilo (Single Thread) que delega tareas intensivas de red/disco en segundo plano mediante Promesas, Async/Await y Callbacks sin bloquear el renderizado ni la UI del usuario.

1. Mecanismos de Ejecución de Código en el Navegador Web

💡 Fundamentos Conceptuales

JavaScript es el único lenguaje de programación interpretado que se ejecuta nativamente en todos los navegadores web. Su ejecución se rige por un entorno de ejecución (Runtime Environment) monohilo no bloqueante compuesto por:

  • Motor de JavaScript (JS Engine): Implementaciones como V8 (Chrome, Edge, Node.js), SpiderMonkey (Firefox) o JavaScriptCore (Safari). Se compone del compilador JIT (Just-In-Time) y el recolector de basura (Garbage Collector).
  • Fase de Parsing y AST: El código fuente se analiza léxica y sintácticamente generando un Abstract Syntax Tree (AST) que representa la gramática del programa en memoria.
  • Compilación JIT (Just-In-Time): El intérprete (ej. Ignition en V8) genera bytecode rápido inicial, mientras que el compilador optimizador (ej. TurboFan) perfila el código caliente (hot code) y lo compila directamente a código máquina nativo de la CPU.
  • Call Stack (Pila de Llamadas): Estructura LIFO (Last In, First Out) donde se apilan los marcos de contexto de ejecución de las funciones que se están ejecutando secuencialmente.
  • Event Loop y Colas de Tareas: Coordina la ejecución asíncrona enviando tareas de la Microtask Queue (Promesas, mutation observers) y de la Macrotask Queue (setTimeout, I/O) a la pila de llamadas una vez que esta se encuentra completamente vacía.
🔍 Ampliación y Estándares 2026

Arquitectura de Ejecución en Navegadores Modernos:

  • Separación Motor de Render vs Motor JS: El motor de renderizado (Blink, Gecko, WebKit) procesa HTML/CSS para construir el DOM y CSSOM, mientras el motor JS procesa la lógica. Ambos comparten el hilo principal (Main Thread), por lo que ejecuciones pesadas de JS congelan el repintado de la pantalla.
  • Modelo de Concurrencia Basado en Eventos: JavaScript delega operaciones de red, temporizadores o eventos en las Web APIs del navegador, evitando bloquear el hilo de ejecución del usuario.
  • Gestión de Memoria y Heap: Los objetos complejos se alojan en el montículo de memoria (Memory Heap), y el recolector de basura libera automáticamente referencias huérfanas mediante algoritmos de Mark-and-Sweep.

🎯 Reto 1: Inspección del Motor, Tiempos de Ejecución y Prioridades del Event Loop

📝 Enunciado y Especificación del Reto
Diseña un script que: 1) Extraiga y clasifique mediante expresiones regulares el nombre y versión exacta del motor de JavaScript y navegador a partir de `navigator.userAgent`, 2) Evalúe la identidad del objeto global unificado (`window === globalThis`), y 3) Demuestre cuantitativamente con `performance.now()` la prioridad del Event Loop programando una macrotarea (`setTimeout 0ms`) antes de una microtarea (`Promise.resolve()` y `queueMicrotask()`), registrando una tabla de traza y validando el orden secuencial de resolución.
💡 Pistas Clave y Procedimiento Guiado
Usa expresiones regulares como /Chrome\/([0-9.]+)/, /Firefox\/([0-9.]+)/ o /Version\/([0-9.]+).*Safari/ sobre navigator.userAgent. Almacena en un array de traza cada evento con performance.now() y muestra console.table().
🔍 Desplegar Solución Embebida y Explicación Técnica Clic para Ver/Ocultar
Explicación Técnica: La especificación HTML/W3C define que el Event Loop procesa todo el Call Stack síncrono primero, luego vacía completamente la cola de microtareas (Promesas y queueMicrotask) y finalmente, en el siguiente ciclo, atiende la cola de macrotareas (como temporizadores de setTimeout).
💻 Código de la Solución Comentada:
function auditarMotorYEventLoop() {
    console.group("🔍 1. Detección y Extracción del Motor JS mediante navigator.userAgent");
    const ua = navigator.userAgent;
    let motorDetectado = "Desconocido";
    let versionMotor = "Desconocida";
    let navegador = "Navegador no identificado";

    // Expresiones regulares para extraer motor y versión exacta
    if (/Edg\/([0-9.]+)/i.test(ua)) {
        motorDetectado = "V8 (Blink)";
        versionMotor = ua.match(/Edg\/([0-9.]+)/i)[1];
        navegador = "Microsoft Edge";
    } else if (/Chrome\/([0-9.]+)/i.test(ua)) {
        motorDetectado = "V8 (Blink)";
        versionMotor = ua.match(/Chrome\/([0-9.]+)/i)[1];
        navegador = "Google Chrome / Chromium";
    } else if (/Firefox\/([0-9.]+)/i.test(ua)) {
        motorDetectado = "SpiderMonkey (Gecko)";
        versionMotor = ua.match(/Firefox\/([0-9.]+)/i)[1];
        navegador = "Mozilla Firefox";
    } else if (/Version\/([0-9.]+).*Safari/i.test(ua)) {
        motorDetectado = "JavaScriptCore (Nitro/WebKit)";
        versionMotor = ua.match(/Version\/([0-9.]+)/i)[1];
        navegador = "Apple Safari";
    }

    console.log("Navegador:", navegador);
    console.log("Motor de JavaScript:", motorDetectado);
    console.log("Versión detectada:", versionMotor);
    console.log("User-Agent en bruto:", ua);
    console.groupEnd();

    console.group("🌐 2. Comparativa de Identidad del Objeto Global");
    const auditoriaGlobal = {
        "window === globalThis": window === globalThis,
        "self === globalThis": typeof self !== "undefined" && self === globalThis,
        "typeof window": typeof window,
        "typeof globalThis": typeof globalThis,
        "Entorno estandarizado": "globalThis (ES2020)"
    };
    console.table(auditoriaGlobal);
    console.groupEnd();

    console.group("⚡ 3. Demostración Cuantitativa de Prioridades del Event Loop");
    const t0 = performance.now();
    const traza = [];

    function registrarPaso(fase, tipo, prioridadTeorica) {
        traza.push({
            "Orden de Ejecución": traza.length + 1,
            "Fase / Cola": fase,
            "Tipo de Tarea": tipo,
            "Prioridad": prioridadTeorica,
            "Timestamp Relativo (ms)": Number((performance.now() - t0).toFixed(4))
        });
    }

    // 1. Sentencia Síncrona Inicial en Call Stack
    registrarPaso("Call Stack", "Síncrono (Inicio)", "1 - Inmediata");

    // 2. Macrotarea: Se programa PRIMERO en el código deliberadamente
    setTimeout(() => {
        registrarPaso("Macrotask Queue", "Macrotarea (setTimeout 0ms)", "3 - Baja");

        // Al ejecutarse la macrotarea, el ciclo ha concluido y mostramos la tabla
        console.table(traza);
        const ordenCorrecto = traza[2]["Tipo de Tarea"].includes("Microtarea") && 
                              traza[traza.length - 1]["Tipo de Tarea"].includes("Macrotarea");
        console.log("¿Se demostró la prioridad de microtareas frente a macrotareas?:", ordenCorrecto ? "SÍ ✅" : "NO ❌");
        console.groupEnd();
    }, 0);

    // 3. Microtarea (Promise.resolve): Se programa DESPUÉS de setTimeout
    Promise.resolve().then(() => {
        registrarPaso("Microtask Queue", "Microtarea (Promise.resolve)", "2 - Alta");
    });

    // 4. Microtarea Nativa (queueMicrotask)
    if (typeof queueMicrotask === "function") {
        queueMicrotask(() => {
            registrarPaso("Microtask Queue", "Microtarea (queueMicrotask)", "2 - Alta");
        });
    }

    // 5. Sentencia Síncrona Final en Call Stack
    registrarPaso("Call Stack", "Síncrono (Fin)", "1 - Inmediata");
}

2. Capacidades y Limitaciones de Ejecución en Entorno Cliente

💡 Fundamentos Conceptuales

La ejecución de código en el cliente opera bajo un modelo de caja de arena (Sandbox) que equilibra potencia interactiva y estrictas restricciones de seguridad para proteger al usuario:

  • Capacidades de Ejecución:
    • Manipulación en tiempo real del árbol DOM y modificación dinámica de estilos CSS.
    • Interacción con APIs web del dispositivo: Geolocalización, Web Workers (hilos secundarios), Canvas/WebGL, Audio/Vídeo y WebSockets para comunicación bidireccional.
    • Persistencia local de datos aislada por origen: LocalStorage, SessionStorage e IndexedDB.
    • Comunicaciones asíncronas de fondo mediante la Fetch API sin recarga de página.
  • Limitaciones y Restricciones de Seguridad:
    • Aislamiento de Sistema (Sandbox): JavaScript cliente no puede acceder directamente al sistema de archivos local (disco duro), ni ejecutar procesos binarios en el sistema operativo del usuario.
    • Same-Origin Policy (SOP): Restringe el acceso a recursos entre diferentes orígenes (combinación de protocolo, dominio y puerto).
    • Protección contra ataques XSS y CSRF: Se prohíbe la lectura de cookies con bandera HttpOnly desde JavaScript.
🔍 Ampliación y Estándares 2026

Seguridad Avanzada en Clientes Web Modernos:

  • Content Security Policy (CSP): Cabecera HTTP que restringe de qué dominios se pueden cargar scripts, estilos y fuentes, bloqueando la inyección de código malicioso no autorizado.
  • Feature Detection vs Browser Detection: La técnica profesional para comprobar capacidades nunca debe evaluar el navigator.userAgent (fácilmente manipulable), sino verificar la existencia de la propiedad en el objeto correspondiente (ej: if ('geolocation' in navigator)).
  • Permisos del Navegador (Permissions API): El acceso a APIs sensibles (cámara, micrófono, geolocalización) requiere consentimiento explícito del usuario gestionado mediante la Permissions API.

function auditarNavegador() {

3. Lenguajes de Programación en Entorno Cliente y Tecnologías Asociadas

💡 Fundamentos Conceptuales

Aunque JavaScript es la lengua franca del navegador estandarizada bajo la especificación ECMAScript (ECMA-262), el desarrollo moderno en cliente convive con lenguajes tipados, tecnologías de transpilación y bytecode nativo:

  • Evolución ECMAScript: Desde la refundación con ES6 (ES2015), el estándar evoluciona anualmente incorporando clases, módulos nativos, async/await, optional chaining y operadores lógicos modernos.
  • TypeScript: Superconjunto tipado estático desarrollado por Microsoft. Aporta tipado estricto, interfaces y genéricos que se compilan (transpilan) a JavaScript plano compatible con cualquier navegador, erradicando errores en tiempo de desarrollo.
  • WebAssembly (Wasm): Formato binario ejecutable de bajo nivel estandarizado por el W3C. Permite compilar lenguajes como C, C++, Rust o Go a un bytecode que se ejecuta en el navegador a una velocidad casi idéntica a la nativa, comunicándose directamente con la memoria de JavaScript.
  • Transpiladores y Polyfills: Herramientas como Babel convierten código JavaScript moderno (ES2024+) a versiones compatibles con navegadores heredados (ES5), mientras que los polyfills (como Core-js) inyectan funciones o APIs inexistentes.
  • Empaquetadores (Bundlers): Motores modernos como Vite (esbuild/Rollup) o Webpack empaquetan, minifican y optimizan los árboles de dependencias para despliegue en producción.
🔍 Ampliación y Estándares 2026

El Rol Transformador de WebAssembly y Transpilación:

  • Complementariedad Wasm + JS: WebAssembly no sustituye a JavaScript; se complementan. JS gestiona el DOM, los eventos de usuario y la lógica de interfaz, mientras Wasm asume tareas de cómputo intensivo (edición de vídeo, física de videojuegos 3D, compresión o criptografía).
  • Compatibilidad Retroactiva (Backward Compatibility): Un principio inviolable de la web es "Don't break the web": el código JavaScript escrito en 1997 sigue funcionando en los navegadores actuales.

📝 Enunciado y Especificación del Reto

💡 Pistas Clave y Procedimiento Guiado

🔍 Desplegar Solución Embebida y Explicación Técnica Clic para Ver/Ocultar
Explicación Técnica: La verificación e instanciación de WebAssembly en cliente permite decidir en tiempo de ejecución si se delega el cálculo matemático intensivo en un módulo Wasm o en un algoritmo JavaScript.
💻 Código de la Solución Comentada:
async function probarWasmYBenchmark() {
    console.log("=== Comprobación e Instanciación de WebAssembly ===");
    
    // Módulo Wasm mínimo válido con cabecera mágica \0asm y versión 1
    const wasmBytes = new Uint8Array([0x00, 0x61, 0x73, 0x6d, 0x01, 0x00, 0x00, 0x00]);
    let wasmActivo = false;

    if (typeof WebAssembly === "object" && typeof WebAssembly.instantiate === "function") {
        try {
            const resultado = await WebAssembly.instantiate(wasmBytes);
            if (resultado && resultado.instance) {
                wasmActivo = true;
                console.log("✅ Wasm Activo: Módulo binario WebAssembly instanciado con éxito en memoria.");
                console.log("Instancia WebAssembly creada:", resultado.instance);
            }
        } catch (e) {
            console.warn("Fallo al instanciar binario Wasm:", e.message);
        }
    }

    if (!wasmActivo) {
        console.warn("⚠️ WebAssembly no disponible en este cliente. Activando motor JavaScript estándar.");
    }

    // Benchmark computacional comparativo en JavaScript
    console.time("Cálculo Fibonacci en JS (n=32)");
    function fibonacci(n) {
        return n <= 1 ? n : fibonacci(n - 1) + fibonacci(n - 2);
    }
    const valorFib = fibonacci(32);
    console.timeEnd("Cálculo Fibonacci en JS (n=32)");
    console.log("Resultado Fibonacci(32) en JS:", valorFib);
}

probarWasmYBenchmark();

4. Integración del Código JavaScript con las Etiquetas HTML

💡 Fundamentos Conceptuales

La integración de JavaScript en documentos HTML5 determina la velocidad de renderizado (FCP/LCP) y la prevención de colisiones de variables globales:

  • 1. Script Clásico en <head> (Bloqueante): Detiene el parseo del HTML mientras se descarga y ejecuta el script. Puede provocar errores si intenta acceder a elementos del DOM aún no creados.
  • 2. Script al pie de <body>: Asegura que todo el DOM esté parseado antes de ejecutar el código. Históricamente la técnica más extendida, aunque retrasa el inicio de la descarga.
  • 3. Atributo defer en <head>: Descarga el archivo en paralelo sin bloquear el parseo HTML y ejecuta los scripts en el orden exacto en que fueron declarados una vez completado el DOM.
  • 4. Atributo async en <head>: Descarga en paralelo y ejecuta inmediatamente al completarse la descarga, interrumpiendo el HTML y sin garantizar el orden relativo entre scripts. Adecuado únicamente para analítica independiente.
  • 5. Módulos ES6 (<script type="module">): El estándar moderno. Tienen comportamiento defer implícito, se ejecutan en Modo Estricto ('use strict') automáticamente y poseen ámbito de módulo aislado (no contaminan window).
🔍 Ampliación y Estándares 2026

Buenas Prácticas de Arquitectura Frontend:

  • Separación Estricta de Capas: Queda totalmente desaconsejado el uso de scripts en línea dentro de atributos HTML (como onclick="..." o onload="..."). El comportamiento debe residir en ficheros JavaScript externos vinculados mediante escuchadores de eventos.
  • Precarga de Scripts Críticos: El uso de <link rel="preload" as="script" href="..."> o <link rel="modulepreload" ...> permite priorizar en la red la obtención de scripts cruciales para la primera interacción del usuario.

📝 Enunciado y Especificación del Reto
Escribe una página HTML con scripts que demuestren de forma práctica cómo influye el modo de inclusión en el acceso a elementos del DOM. Comprueba qué sucede cuando un script clásico en `<head>` intenta acceder a un elemento del `<body>` frente a un script con `defer` o `type="module"`.
💡 Pistas Clave y Procedimiento Guiado

🔍 Desplegar Solución Embebida y Explicación Técnica Clic para Ver/Ocultar
Explicación Técnica: Los scripts síncronos en head detienen el parser antes de que el elemento exista en el DOM. Por contra, los módulos ES y scripts con defer esperan a que el árbol DOM esté completamente disponible en memoria.
💻 Código de la Solución Comentada:

<html lang="es">
<head>
  <meta charset="UTF-8"/>
  <title>Demostración de Carga y Acceso al DOM</title>

  <script>
    console.log("1. [Sync en Head] Intento leer #caja:", document.getElementById('caja')); // null
  </script>

  <!-- Intento 2: Script con defer -->
  <script defer>
    // Se ejecuta al finalizar el parseo del DOM
    console.log("3. [Defer] Acceso a #caja:", document.getElementById('caja') ? "Éxito ✅" : "Fallo ❌");
  </script>

  <!-- Intento 3: Módulo ES6 -->
  <script type="module">
    const elemento = document.getElementById('caja');
    console.log("4. [Type=Module] Acceso a #caja:", elemento ? "Éxito ✅" : "Fallo ❌");
    console.log("   Ámbito aislado: window.elemento es", window.elemento); // undefined
  </script>
</head>
<body>
  <div id="caja">Elemento contenedor del DOM</div>
  <script>
    console.log("2. [Pie de Body] Acceso inmediato a #caja:", document.getElementById('caja') ? "Éxito ✅" : "Fallo ❌");
  </script>
</body>
</html>

5. Herramientas de Programación, Depuración, Librerías y Frameworks

💡 Fundamentos Conceptuales

El ecosistema profesional de programación en cliente se fundamenta en herramientas avanzadas de diagnóstico integradas en los navegadores y un rico ecosistema de librerías:

  • DevTools del Navegador (F12):
    • Console (Consola): Ejecución de comandos en vivo y métodos de diagnóstico (console.table, console.group, console.time).
    • Sources / Debugger: Inspección del código fuente, establecimiento de puntos de interrupción (breakpoints condicionales), inspección de variables locales/clausuras y navegación paso a paso (Step Over, Step Into, Step Out).
    • Network (Red): Monitorización de peticiones HTTP, estado del caché, tiempos de latencia y cascada de descargas (Waterfall).
    • Performance y Lighthouse: Auditorías de accesibilidad, SEO y métricas de rendimiento Web Vitals (LCP, FID/INP, CLS).
  • Herramientas de Entorno y Calidad de Código:
    • IDEs y Editores: Visual Studio Code con extensiones de depuración integrada.
    • Linters y Formateadores: ESLint para análisis estático de errores y Prettier para consistencia de estilo.
  • Librerías vs Frameworks Cliente:
    • Librerías de Utilidad (ej. jQuery): Históricamente esenciales para abstraer discrepancias entre navegadores; hoy reemplazadas por las APIs nativas modernas del DOM.
    • Frameworks y Librerías Reactivas (React, Vue, Angular, Svelte): Arquitectura basada en componentes reutilizables, reactividad de estado y manipulación virtual o declarativa del DOM para Single Page Applications (SPA).
🔍 Ampliación y Estándares 2026

Estrategias Avanzadas de Depuración y Rendimiento:

  • La sentencia debugger;: Al insertarla en el código fuente, si las DevTools están abiertas, el motor del navegador detiene automáticamente la ejecución en esa línea exacta, permitiendo inspeccionar el estado de la pila sin necesidad de configurar el breakpoint a mano.
  • Source Maps (.map): Ficheros que mapean el código empaquetado y minificado de producción con los ficheros fuente originales de TypeScript o ES Modules, facilitando la depuración como si estuviéramos en desarrollo.

function procesarPedidos(pedidos) {
