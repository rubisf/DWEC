Fundamentos de JavaScript

⚡ Características Fundamentales de JavaScript

🎯 1. Interpretado (no compilado previo)

Se traduce y ejecuta al vuelo por el motor (V8, SpiderMonkey) mediante compilación JIT (Just-In-Time) sin requerir una compilación previa a ejecutable binario.

⚡ 2. Basado en Eventos

Reacciona a las acciones del usuario (clicks, teclados, envíos de formulario) mediante escuchadores de eventos y la cola de tareas del Event Loop.

🪶 3. Es Ligero

Sintaxis concisa de ejecución nativa directa en el cliente dentro del navegador sin requerir entornos pesados ni instalación de runtimes locales.

🏷️ 4. Tipado Dinámico y Débil

Las variables no se vinculan a un tipo de dato fijo (let x = 10; x = "hola"). El tipo de dato se evalúa en tiempo de ejecución.

🔠 5. Sensible a Mayúsculas/Minúsculas

Lenguaje estrictamente Case-Sensitive: miVariable, Mivariable y MIVARIABLE representan tres identificadores independientes.

🌐 6. Independiente de Plataforma

Multiplataforma por especificación W3C y ECMAScript. Se ejecuta de forma idéntica en Windows, macOS, Linux, iOS y Android dentro del navegador.

⏱️ 7. Procesamiento Asíncrono y No Bloqueante

Modelo monohilo (Single Thread) que delega tareas intensivas de red/disco en segundo plano mediante Promesas, Async/Await y Callbacks sin bloquear el renderizado ni la UI del usuario.

1. Arquitectura Web y Rol de JavaScript

💡 Fundamentos Conceptuales

JavaScript es el único lenguaje de programación del lado del cliente estandarizado por el W3C y ECMA que se ejecuta nativamente en los navegadores web. Opera dentro de una arquitectura web de 3 capas:

  • 1. Capa de Presentación (Frontend): Formada por HTML5 (estructura), CSS3 (estilos) y JavaScript (lógica dinámica e interacción del cliente).
  • 2. Capa de Lógica de Negocio (Backend): Servidores de aplicaciones (Node.js, Java, Python) que procesan la lógica central y validaciones.
  • 3. Capa de Persistencia (Base de Datos): Almacenes relacionales (PostgreSQL) o NoSQL (MongoDB).

Al descargar un script, el motor del navegador (V8, SpiderMonkey) construye el AST (Abstract Syntax Tree) y aplica compilación JIT (Just-In-Time) a código máquina nativo.

🔍 Ampliación y Estándares 2026

El entorno de ejecución cliente utiliza una arquitectura basada en eventos no bloqueante estructurada en los siguientes componentes:

  • Call Stack (Pila de Llamadas): Pila LIFO donde se apilan y ejecutan las funciones secuencialmente en un único hilo de ejecución.
  • Event Loop (Bucle de Eventos): Monitor continuo que mueve tareas pendientes desde las colas asíncronas cuando la pila se vacía.
  • Jerarquía BOM (Browser Object Model): Encabezada por el objeto global window, expone las APIs del navegador (navigator para sistema, location para URLs, history para navegación).
  • Jerarquía DOM (Document Object Model): Representada por document, convierte la estructura HTML en un árbol de objetos navegable en memoria.

2. Inclusión de Scripts en HTML: Defer vs Async vs Module

💡 Fundamentos Conceptuales

Existen 4 modos de incluir JavaScript en HTML, condicionando el acceso al DOM y el aislamiento de variables:

  • 1. <script> en <head> (Sync): Bloquea el HTML. ❌ Acceso al DOM: FALLA (null). ❌ Sobreescritura: ALTA (contamina window).
  • 2. <script> al pie de </body>: ✅ Acceso al DOM: OK. ❌ Sobreescritura: ALTA (si script1.js y script2.js usan la misma variable global var usuario, script2 sobreescribe a script1).
  • 3. <script defer> en <head>: Descarga en paralelo y ejecuta tras el DOM. ✅ Acceso al DOM: OK. ❌ Sobreescritura: ALTA (sigue en window).
  • 4. <script type="module"> (ES Modules): ✅ Acceso al DOM: OK (defer implícito). ✅ Aislamiento: ABSOLUTO (Module Scope). Imposible sobreescribir variables desde fuera.
🔍 Ampliación y Estándares 2026

Con la llegada de ES Modules (ES6), la etiqueta <script type="module"> transforma el modelo de inclusión añadiendo 5 garantías nativas:

  • 1. Comportamiento defer automático: Los módulos se descargan en paralelo y ejecutan tras la construcción del DOM HTML.
  • 2. Ámbito Aislado de Módulo (Module Scope): Las variables declaradas en un módulo permanecen privadas. No ensucian window (window.usuario === undefined) ni se pueden sobreescribir desde otros ficheros scripts independientes.
  • 3. Modo Estricto ('use strict') automático: Convierte errores silenciosos en excepciones explícitas y prohíbe variables no declaradas.
  • 4. Sintaxis nativa import / export: Permite modularizar código entre ficheros sin herramientas de empaquetado externas.
  • 5. Requisito CORS: Exige cargar el archivo bajo protocolo HTTP/HTTPS garantizando el origen cruzado seguro.

3. Control de Versiones Distribuido con Git

💡 Fundamentos Conceptuales

Git es un DVCS (Sistema de Control de Versiones Distribuido) diseñado por Linus Torvalds que registra la evolución inmutable del código. El flujo de trabajo organiza las modificaciones a través de tres áreas fundamentales:

  • 1. Working Directory (Directorio de Trabajo): Espacio de trabajo local donde se crean y modifican archivos activamente.
  • 2. Staging Area (Zona de Preparación / Index): Área intermedia donde se seleccionan y organizan las modificaciones con git add antes de confirmarlas.
  • 3. Repositorio Local (.git): Base de datos que almacena las instantáneas permanentes e inmutables mediante git commit.
🔍 Ampliación y Estándares 2026

Internamente, Git almacena la historia como un DAG (Grafo Acíclico Dirigido) de commits inmutables:

  • Hashes Criptográficos (SHA-1/SHA-256): Cada commit recibe una suma de verificación única de 40 caracteres hexadecimales que garantiza la integridad del código.
  • Objetos Internos: Commits que apuntan a árboles (trees) y bloques de contenido de archivos (blobs). Las ramas son punteros móviles ligeros a commits, haciendo que git branch o git merge tengan coste O(1).
  • Flujo Profesional Distribuido: Trabajo con ramas de características (feature branches), sincronización remota con git push y revisiones continuas mediante Pull Requests (PR) en GitHub.

// UT1 - Ejemplo 3: Flujo de Trabajo con Git

4. Generación Básica de Contenido DOM con JavaScript

💡 Fundamentos Conceptuales

Existen 3 métodos principales para la inserción de HTML desde JavaScript:

  • innerHTML: Reemplaza el marcado interno completo (re-parseo total).
  • createElement() / append(): Construcción programática segura de nodos en memoria.
  • insertAdjacentHTML(): Inserción directa de plantillas HTML en 4 posiciones relativas sin destruir los nodos circundantes ni sus eventos.
🔍 Ampliación y Estándares 2026

Técnicas de Inserción HTML y Seguridad DOM:

  • 1. innerHTML: Evalúa cadenas HTML. Rápido pero ⚠️ vulnerable a XSS si los datos provienen del usuario y ❌ destruye listeners de eventos previos al re-parsear el contenedor.
  • 2. document.createElement() + append(): ✅ 100% Inmune a XSS al usar textContent. Genera nodos en memoria y los inserta conservando todos los escuchadores de eventos.
  • 3. element.insertAdjacentHTML(posicion, html): Inyecta plantillas HTML sin destruir los nodos existentes. Admite 4 posiciones exactas:
    • 'beforebegin': Antes del elemento.
    • 'afterbegin': Primer hijo interno.
    • 'beforeend': Último hijo interno.
    • 'afterend': Después del elemento.
