Fundamentos de JavaScript

⚡ Características Fundamentales de JavaScript

🎯 1. Interpretado (no compilado previo)

Se traduce y ejecuta al vuelo por el motor (V8, SpiderMonkey) mediante compilación JIT (Just-In-Time) sin requerir una compilación previa a ejecutable binario.

⚡ 2. Basado en Eventos

Reacciona a las acciones del usuario (clicks, teclados, envíos de formulario) mediante escuchadores de eventos y la cola de tareas del Event Loop.

🪶 3. Es Ligero

Sintaxis concisa de ejecución nativa directa en el cliente dentro del navegador sin requerir entornos pesados ni instalación de runtimes locales.

🏷️ 4. Tipado Dinámico y Débil

Las variables no se vinculan a un tipo de dato fijo (let x = 10; x = "hola"). El tipo de dato se evalúa en tiempo de ejecución.

🔠 5. Sensible a Mayúsculas/Minúsculas

Lenguaje estrictamente Case-Sensitive: miVariable, Mivariable y MIVARIABLE representan tres identificadores independientes.

🌐 6. Independiente de Plataforma

Multiplataforma por especificación W3C y ECMAScript. Se ejecuta de forma idéntica en Windows, macOS, Linux, iOS y Android dentro del navegador.

⏱️ 7. Procesamiento Asíncrono y No Bloqueante

Modelo monohilo (Single Thread) que delega tareas intensivas de red/disco en segundo plano mediante Promesas, Async/Await y Callbacks sin bloquear el renderizado ni la UI del usuario.

Arquitectura de Aplicaciones Web

🏗️ Arquitectura Web de 3 Capas: Frontend, Backend y Persistencia

🖥️ 1. Frontend (Presentación) Entorno Cliente

La interfaz visual e interactiva que se ejecuta directamente en el navegador web del usuario (Chrome, Firefox, Safari, Edge).

  • HTML5: Estructura semántica del contenido.
  • CSS3: Estilos visuales y diseño responsive.
  • JavaScript: Lógica dinámica e interacción en vivo.
  • Librerías / Frameworks: React, Vue, Angular.
🎯 Ámbito del módulo (DWEC): Programación e interactividad en esta capa cliente.
⚙️ 2. Backend (Lógica de Negocio) Entorno Servidor

Se ejecuta en servidores centralizados o en la nube. Procesa las reglas de negocio, transacciones, autenticación y seguridad.

  • Entornos de Servidor: Node.js, Java, Python, PHP, C# (.NET).
  • APIs y Microservicios: Endpoints RESTful y GraphQL.
  • Seguridad Crítica: Control de acceso, tokens JWT y hashing.
🔗 Conexión: El frontend se comunica con el backend mediante peticiones HTTP / Fetch API.
🗄️ 3. Capa de Persistencia Bases de Datos

Almacena y gestiona de forma permanente, consistente e íntegra los datos de la aplicación para que no se pierdan al cerrar sesión.

  • BBDD Relacionales (SQL): PostgreSQL, MySQL, MariaDB, Oracle.
  • BBDD NoSQL / Documentales: MongoDB, Firestore, DynamoDB.
  • Caché en Memoria: Redis, Memcached.
🛡️ Seguridad: El navegador cliente nunca conecta directamente a la BBDD por aislamiento.
🔄 Flujo de Comunicación: Usuario ➔ [Frontend (Navegador)] ➔ Petición HTTP / JSON ➔ [Backend (Servidor)] ➔ Consultas SQL/NoSQL ➔ [Base de Datos] Arquitectura Cliente-Servidor Web

1. Mecanismos de Ejecución de Código en el Navegador Web

💡 Fundamentos Conceptuales

JavaScript es el lenguaje estándar de programación que se ejecuta nativamente en los navegadores dentro de una arquitectura web de 3 capas:

  • 1. Capa de Presentación (Frontend - Cliente): Construida con HTML5 (estructura), CSS3 (estilo) y JavaScript (lógica interactiva). Es el foco central del módulo DWEC.
  • 2. Capa de Lógica de Negocio (Backend - Servidor): Servidores de aplicaciones (Node.js, Java, Python, PHP) que procesan las reglas de negocio y exponen servicios API.
  • 3. Capa de Persistencia (Base de Datos): Almacenes relacionales (PostgreSQL, MySQL) o NoSQL (MongoDB) que conservan la información permanente de la aplicación.
  • El Motor de JavaScript (JS Engine): Entorno integrado en el cliente (V8 en Chrome/Edge, SpiderMonkey en Firefox, JavaScriptCore en Safari) que interpreta y ejecuta el código en memoria.
  • El Objeto Global (window / globalThis): Representa el entorno global unificado de ejecución en el navegador.
🔍 Ampliación y Estándares 2026

El Rol del Navegador como Plataforma de Aplicaciones:

  • Entorno Monohilo (Single-Threaded): JavaScript ejecuta una sola instrucción a la vez en su hilo principal. Si un script realiza un bucle infinito o una operación pesada sin control, congela temporalmente la respuesta de la ventana del navegador.
  • Compatibilidad Estándar ECMAScript: JavaScript se rige por el estándar internacional ECMA-262, garantizando que el código básico escrito funcione de manera consistente en cualquier navegador moderno.

2. Capacidades y Limitaciones de Ejecución en Entorno Cliente

💡 Fundamentos Conceptuales

La ejecución de código en el navegador web equilibra grandes posibilidades de interacción con estrictas barreras de seguridad para proteger los datos del usuario:

  • Capacidades de Ejecución (Lo que SÍ puede hacer):
    • Manipular el contenido visible de la página web (textos, imágenes, formularios y estilos CSS).
    • Reaccionar a las acciones del usuario (clics de ratón, pulsaciones de teclas, desplazamientos).
    • Consultar el estado del entorno: si el dispositivo está conectado a Internet (navigator.onLine), el idioma configurado (navigator.language) o el tamaño de la pantalla (screen.width, screen.height).
    • Almacenar información local específica del sitio web mediante localStorage y sessionStorage.
  • Limitaciones y Restricciones de Seguridad (Lo que NO puede hacer):
    • Modelo Sandbox (Caja de Arena): JavaScript en el navegador se ejecuta completamente aislado del sistema operativo. No puede leer ni modificar archivos del disco duro del usuario sin su consentimiento explícito (mediante un control <input type="file">).
    • Imposibilidad de Ejecutar Programas: Un script web no puede iniciar aplicaciones externas, procesos ni comandos en el ordenador del cliente.
    • Política del Mismo Origen (Same-Origin Policy): Impide que un script procedente de un dominio acceda a datos confidenciales (como cookies o sesiones) de otro dominio diferente.
🔍 Ampliación y Estándares 2026

Por qué es Fundamental el Modelo Sandbox:

  • Navegación Segura: Gracias al sandbox, cualquier usuario puede entrar en un enlace desconocido sin temor a que la página borre sus carpetas personales, instale software malicioso o acceda a ficheros de su sistema.
  • Consentimiento de Permisos: Para acceder a sensores delicados (cámara, micrófono o ubicación geográfica), el navegador solicita obligatoriamente una ventana de confirmación al usuario.

3. Lenguajes de Programación en Entorno Cliente y Tecnologías Asociadas

💡 Fundamentos Conceptuales

El desarrollo web moderno en el entorno cliente se articula en torno a tres tecnologías estándar y una serie de lenguajes y herramientas complementarias:

  • El Trinomio Fundamental de la Web:
    • HTML (HyperText Markup Language): Proporciona la estructura semántica y el contenido de la página web (títulos, párrafos, formularios).
    • CSS (Cascading Style Sheets): Define la presentación estética, diseño visual, colores, tipografías y adaptación a diferentes pantallas (Responsive Web Design).
    • JavaScript: Aporta el comportamiento dinámico, la lógica de programación y la interactividad con el usuario.
  • Tecnologías Asociadas y Superconjuntos:
    • TypeScript: Lenguaje de código abierto desarrollado por Microsoft que añade tipado estático opcional y autocompletado avanzado sobre JavaScript. Dado que los navegadores solo entienden JavaScript, el código TypeScript se "transpila" (convierte) a JavaScript plano antes de ejecutarse.
    • WebAssembly (Wasm): Estándar complementario de bajo nivel que permite ejecutar código compilado (desde C, C++ o Rust) a velocidades cercanas al código máquina nativo. Se utiliza para tareas de cálculo intensivo (edición de gráficos, juegos 3D, emuladores), conviviendo en armonía con JavaScript.
    • Herramientas de Construcción: Utilidades como Vite o transpiladores como Babel que empaquetan y optimizan los ficheros para su despliegue en los navegadores.
🔍 Ampliación y Estándares 2026

La Regla de Oro de la Web: "Separación de Capas":

  • Estructura (HTML), Diseño (CSS) y Comportamiento (JS): Mantener cada lenguaje en su propio archivo facilita el mantenimiento, el trabajo en equipo y el rendimiento de la aplicación.
  • JavaScript Universal: A día de hoy, JavaScript es el único lenguaje de scripting interpretado soportado de forma nativa por el 100% de los navegadores web del mundo sin requerir plugins ni instalaciones adicionales.
💻 Demostración Práctica e Implementación de Código

4. Integración del Código JavaScript con las Etiquetas HTML

💡 Fundamentos Conceptuales

Para que el navegador ejecute código JavaScript, este debe vincularse a un documento HTML mediante la etiqueta <script> a través de diferentes modalidades:

  • 1. Script Externo (Modalidad Recomendada):

    El código reside en un fichero independiente con extensión .js vinculado con el atributo src: <script src="app.js"></script>. Facilita la reutilización y el almacenamiento en caché del navegador.

  • 2. Script Embebido / Interno:

    Las sentencias se escriben directamente dentro de las etiquetas <script> ... </script> en el HTML. Adecuado únicamente para pequeños scripts de inicialización.

  • 3. Script en Línea (Desaconsejado):

    Escrito dentro de atributos de eventos HTML (como onclick="alert('Hola')"). Viola el principio de separación de capas y está en desuso en el desarrollo profesional.

  • Ubicación y Atributos de Control de Carga (head vs body, defer y async):
    • Al pie del <body>: Garantiza que todo el árbol HTML esté cargado antes de que el script intente buscar elementos.
    • Atributo defer (Recomendado en <head>): Descarga el archivo en segundo plano sin interrumpir la lectura del HTML y lo ejecuta de forma ordenada justo cuando el documento ha finalizado su carga.
    • Atributo async: Descarga en paralelo y ejecuta inmediatamente al terminar, interrumpiendo el HTML. Indicado para scripts independientes como herramientas de analítica.
🔍 Ampliación y Estándares 2026

Optimización de la Carga de Páginas (Performance):

  • Evitar Scripts Bloqueantes: Un script tradicional en el <head> detiene la lectura del documento hasta que el archivo se descarga y ejecuta, dejando la pantalla en blanco durante ese tiempo. El uso de defer elimina por completo ese bloqueo.
  • Módulos ES6 (type="module"): Al añadir type="module" a la etiqueta script, el navegador activa automáticamente el comportamiento de carga diferida (equivalente a defer) y aísla el ámbito de sus variables.
💻 Demostración Práctica e Implementación de Código 🚀 Abrir Ejemplo Real en Vivo (ejemplo4_insercion_dom.html) 🔗

<html lang="es">
<head>
  <meta charset="UTF-8">
  <title>Integración de Scripts</title>
  
  <!-- Inclusión recomendada en head con atributo defer -->
  <script defer src="main.js"></script>
</head>
<body>
  <h1>Hola, DWEC</h1>

  <!-- Script interno al final del body -->
  <script>
    console.log("El documento HTML ya está accesible.");
  </script>
</body>
</html>

5. Control de Versiones Distribuido con Git para Desarrollo Web

💡 Fundamentos Conceptuales

El control de versiones es una herramienta imprescindible en cualquier proyecto web. Git es el sistema de control de versiones distribuido estándar en la industria del software:

  • ¿Por qué usar Control de Versiones?:
    • Guarda un historial completo de cambios realizados en los archivos del proyecto.
    • Permite volver a cualquier versión anterior si se produce un fallo o error imprevisto.
    • Facilita el trabajo coordinado entre múltiples desarrolladores sin sobrescribir el trabajo de los demás.
  • Las Tres Áreas de Trabajo de Git:
    • 1. Working Directory (Directorio de Trabajo): La carpeta de tu ordenador donde creas y editas tus archivos HTML, CSS y JavaScript.
    • 2. Staging Area (Zona de Preparación): Espacio intermedio donde seleccionas qué archivos modificados van a formar parte del siguiente guardado mediante git add.
    • 3. Repositorio Local (Carpeta .git): Base de datos donde se registran de forma permanente las instantáneas (snapshots) del proyecto mediante git commit.
  • Comandos Fundamentales de la Terminal:
    • git init: Inicializa un nuevo repositorio Git en la carpeta actual.
    • git config user.name "Nombre" y git config user.email "correo@ies.es": Configuran la autoría de los cambios.
    • git status: Informa sobre qué archivos han sido creados, modificados o preparados.
    • git add .: Añade todos los archivos modificados a la Zona de Preparación.
    • git commit -m "mensaje": Confirma los cambios creando una nueva versión con un mensaje descriptivo.
    • git checkout -b develop: Crea y cambia a una nueva rama de desarrollo para trabajar de forma aislada.
🔍 Ampliación y Estándares 2026

Buenas Prácticas en el Uso de Git:

  • Mensajes de Commit Semánticos: Describir con claridad qué añade o corrige cada commit (ej: feat: añadir formulario de contacto o fix: corregir ruta de script).
  • El Fichero .gitignore: Archivo de texto que indica a Git qué carpetas o ficheros locales temporales no deben subirse al repositorio (como node_modules/ o ficheros de configuración privada).
💻 Demostración Práctica e Implementación de Código

6. Herramientas de Programación, Depuración y Prueba sobre Clientes Web

💡 Fundamentos Conceptuales

El desarrollo profesional en JavaScript se apoya en un conjunto de herramientas integradas en los navegadores y editores de código para diagnosticar y corregir errores:

  • Herramientas de Desarrollador del Navegador (DevTools - Tecla F12):
    • Pestaña Elements (Elementos): Permite inspeccionar la estructura HTML en vivo, modificar etiquetas y alterar reglas CSS en tiempo real para previsualizar cambios de diseño.
    • Pestaña Console (Consola): Muestra errores de ejecución, advertencias y mensajes de depuración generados mediante métodos como:
      • console.log(): Mensajes informativos habituales.
      • console.warn(): Avisos y advertencias de advertencia (color amarillo).
      • console.error(): Errores graves destacados (color rojo).
      • console.table(): Muestra listas de objetos o datos en una tabla legible.
    • Pestaña Sources (Fuentes / Depurador): Permite navegar por los ficheros de código fuente cargados y establecer puntos de interrupción (Breakpoints).
    • La Sentencia debugger;: Instrucción especial de JavaScript que detiene automáticamente la ejecución en esa línea exacta si las herramientas de desarrollador están abiertas, permitiendo inspeccionar las variables paso a paso.
  • Editores de Código Modernos:

    Entornos como Visual Studio Code ofrecen resaltado de sintaxis, detección temprana de fallos, autocompletado y extensiones como Live Server para recarga automática en el navegador.

🔍 Ampliación y Estándares 2026

Estrategias Básicas para Encontrar y Corregir Errores:

  • Leer la Consola Primero: Siempre que una página no responda como se espera, abrir la pestaña Console de DevTools es el primer paso. El navegador indicará el fichero y el número de línea exacto donde se produjo el error.
  • Evitar las Alertas Invasivas: El uso de alert() para depurar interrumpe el uso de la página y es molesto. Se recomienda utilizar siempre la consola (console.log, console.table) y los puntos de interrupción.

console.warn("Aviso: Comprueba la resolución en dispositivos móviles.");

};

// 1. Mensajes en consola con diferentes niveles de severidad
console.log("ℹ️ [INFO]: La aplicación se ha iniciado correctamente.");

// 2. Visualización tabular de datos del navegador
const estadoNavegador = {
    plataforma: navigator.userAgent.includes("Windows") ? "Windows" : "Otro Sistema",
