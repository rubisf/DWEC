📦 Comparativa de Modos de Inclusión de JavaScript y Beneficios de type="module"

Análisis práctico: ¿Cómo influye la ubicación y el atributo de script en el acceso a elementos DOM y la contaminación/sobreescritura de variables globales?

Modo de Inclusión Acceso al DOM Ámbito de Variables Riesgo de Sobreescritura Modo Estricto
1. <script> en <head> (Sync) ❌ FALLA (null) Global (window) ⚠️ ALTO (Sobreescribible) Opcional
2. <script> al pie de </body> ✅ OK (DOM listo) Global (window) ⚠️ ALTO (Colisión de scripts) Opcional
3. <script defer> en <head> ✅ OK (Deferido) Global (window) ⚠️ MEDIO (Mismo espacio) Opcional
4. <script type="module"> 🚀 ✅ OK (Defer implícito) 🔒 Aislado (Module Scope) ✅ NULO (Imposible sobreescribir) ✅ Automático ('use strict')
❌ Scripts Tradicionales (Sin Módulo) Colisión Global 
// script1.js
var usuario = "Ana García"; // En window.usuario

// script2.js (Cargado después)
var usuario = "Pedro López"; // ¡SOBREESCRIBE A ANA!

console.log(window.usuario); // "Pedro López" 😱
Resultado: Las variables se sobreescriben accidentalmente entre archivos distintos sin ningún aviso.
✅ ES Modules (type="module") Module Scope 
// modulo1.js
const usuario = "Ana García"; // Privada al módulo

// modulo2.js
const usuario = "Pedro López"; // Privada al módulo

console.log(window.usuario); // undefined 🎉
Resultado: Cada módulo tiene su propio espacio aislado. Imposible sobreescribir desde fuera.
